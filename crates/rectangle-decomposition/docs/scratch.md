# Scratch、接口与容量上界

[返回 README](../README.md) · 算法背景：[从像素到最少矩形](algorithm.md)

## 接口如何选择

| 场景 | 入口 | 内存行为 |
| --- | --- | --- |
| 已有叶子切片，直接分解 | `scratch.decompose_borrowed(&leaves)` | 校验输入，借用输出，内部不分配 |
| 重复使用一个拥有型输入对象 | `SparseQuadImage64::from_leaves` + `decompose_quads_borrowed` | image 构造分配；借用分解不分配 |
| 希望独立保存返回结果 | `decompose`、`decompose_quads` | 将内部结果复制为 `Vec<Rectangle>`，可以分配 |
| 逐个提供正方形 | `SparseLayerBuilder64::push_square` + `finish` | builder 拥有区间列表，返回拥有型结果，可以分配 |

`SparseQuadImage64` 保存校验后的叶子，不缓存分解结果；两种借用入口共用轴区间与匹配算法。builder 的单个正方形在加入时校验形状，重叠在 `finish` 时检查；`finish` 不清空输入，开始下一层前调用 builder 的 `clear()`。

`SparseOptimalScratch64::new()` 直接创建可用缓存，`Default` 等价。旧的 `preallocate_64()` 是兼容空操作，`try_new_preallocated()` 等价于 `Ok(new())`；新代码直接使用 `new()`。

## 为什么可以放到栈上

scratch 内部全部为固定容量、已初始化的数组，没有 `Vec`、`Box` 或指向自有堆缓冲的指针。`FixedVec<T, N>` 使用 `[T; N] + len`，只接受 `Copy` 元素；清空仅重置有效长度，算法按需重置配对和标记。

因此构造、两个借用分解入口和析构都不调用堆分配器。输出切片位于 scratch 对象内部，下一次可变使用会覆盖它，必须事先消费完毕。这一契约不包含调用方构造输入、保存结果或写入 mesh 时的分配。

## 固定容量从哪里来

以下上界针对合法、无重叠的 64×64 彩色像素区域，允许孔洞和多个连通分量。用 `n` 表示推广后的图像边长。

| 缓冲 | 64×64 容量 | 依据 |
| --- | ---: | --- |
| 每方向轴区间 | 4096 | 每像素至多贡献一个单位区间 |
| 每行区间、run、活跃矩形 | 64 | 每段宽度至少为 1 |
| 每方向 chord、配对、队列、DFS 栈 | 1953 | 每条内部格线消耗互异的成对端点 |
| 有 chord 的颜色组 | 1024 | 每组至少需要 4 个同色像素 |
| 冲突边、CSR 边、可重复的最短层根 | 3969 | 每条冲突边对应唯一内部格点 |
| 输出矩形 | 4096 | 每个矩形至少包含一个非背景像素 |

**Chord 上界。** 每个内部格点最多是一个标签的凹角；沿同一轴只支持一个向内方向。每条内部格线有 `n−1` 个候选端点，一条 chord 消耗两个互异端点，所以每方向至多 `(n−1) floor((n−1)/2)` 条。64×64 下为 1953。把横纵坐标均为偶数的像素设为背景、其余设为同色，可以同时达到两个方向的上界。

**颜色组上界。** 长度为 `L≥1` 的 chord 两侧有 `2L` 个同色像素，两端外侧还各需要一个同色像素，至少占 4 个像素。不同标签不能共享像素，故组数至多 `n²/4`。这是安全上界，不声称所有容量可在同一张图上同时取满。

**冲突图上界。** 同向 chord 没有公共格点，每个内部格点至多承载一条水平和一条竖直 chord，因此 `E≤(n−1)²`。一条 chord 最多遇到 `n−1` 个对向候选，故最大度 `Δ≤n−1`。

**搜索缓冲上界。** 队列和显式 DFS 路径长度不超过一侧顶点数。最短层根可以重复，但每次记录都来自一条被扫描的冲突边，长度至多为 `E`。CSR 的偏移数组还需为末尾哨兵多留一个槽。

这些性质使整个 scratch 的空间为 `O(n²)`。颜色组串行复用同一匹配缓存，不为每种颜色保留独立的搜索数组。

## 线程栈怎样核算

当前 x86_64 布局下，`size_of::<SparseOptimalScratch64>()` 为 **374,736 字节，约 366 KiB**。这是对象大小，不是任意调用链的栈峰值或稳定 ABI；编译器布局、平台和字段变化都可能影响它。

每个 worker 在任务循环外构造一份 scratch，以 `&mut` 传递并复用。大对象经过按值辅助函数、`Result` 或 `?` 展开，尤其在 debug 构建中，可能出现额外临时副本。直接 `new()` 能让使用方式更容易核算。

[资源集成测试](../tests/stack_scratch.rs) 覆盖 4 个并发 worker，各自使用 2 MiB 栈，包含输入、初始化及反复分解。测试配置不代表调用方整条调用链也只需 2 MiB；引擎还应计入自己的栈帧。线程栈设置见 [Rust 线程文档](https://doc.rust-lang.org/std/thread/#stack-size)。

资源测试使用纯安全 Rust，保留容量、借用输出地址、复用和 worker 栈验证；不安装自定义分配器，不再检测分配次数。上面的零分配说明是实现资源契约，不代表当前测试已自动验证分配次数。

## 修改存储布局时要守住的契约

- 合法输入不能依赖溢出后扩容；每个容量都应有几何或搜索上界。
- 未激活数组槽不应参与算法。格点编号的读取由本轮列标记和位图共同保护。
- 内联数组的所有元素始终已初始化；零初值有利于整块清零构造，但不把某条汇编指令视为接口保证。
- 除了计量对象大小，还应核查零分配契约，并运行借用输出地址、标记复用和 worker 栈测试；当前测试不计量分配次数。
