# 介质状态简化审查

## 已落实的契约

路径仅携带当前介质；实体透射按翻译后的边界方向替换它，反射、TIR 和普通薄壁透射保持它。
相机初始介质由捕获层给出。`SINGLE` 的实体外侧明确为 vacuum，`BOUNDARY` 提供两端 SOLID
介质；不能把“未解析”编码成 vacuum，也不能留给下游按历史推测。新增场景的缺面、相交、
重合或相机介质问题应在翻译层修复或拒绝。

已删除两项栈、计数、push/pop、第三层溢出处理、Lambert 首次背面推测，以及阴影起点双介质
绕数与差分基底。阴影改用双侧边界距离矩及最远边界的目标介质，保留 any-hit 顺序无关性。
空气微缝仍按原模型着色，物理介质切换由单独的明确步骤完成。

透明 NEE 的条件反射、条件透射和完整闭包现在共用已解析状态，删除了以占位介质 ID
重新构造双侧边界的求值接口。各项 OpenPBR 数学、随机数映射和采样分布保持原契约。

| 数据 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 完整实时路径 | 112 B/像素 | 96 B/像素 |
| 轻量路径 | 144 B/像素 | 128 B/像素 |
| detached guide | 40 B | 36 B |
| 离线路径 | 128 B/像素 | 128 B/像素，删除历史后保留对齐 padding |

完整实时和轻量路径分别在 3840×2160 内部分辨率减少 126.5625 MiB 路径 backing。
guide 与其他阶段复用的区域仍由更大的存活数据决定，不能把 4 B guide 缩减再计作独立显存收益。
这是布局计算，未据此推断 FPS。连续消光仍为 f32，MediumId 和 IOR source 仍精确保存。

## 仍可简化的设计

### 已修复：阴影发射接口隐式沿用入射介质

`transport/direct/primary.slang` 与 `transport/offline/direct.slang` 现在先按源边界的几何法线、
入射和出射方向求阴影起始介质，再交给忽略源图元的 `primeTraceShadow`。反射和普通薄壁保持
入射介质，实体透射采用出射端点；法线贴图和微缝外观不改变物理介质侧别。

新增 GPU 回归覆盖没有后续边界命中的连接：有色介质退出到空气、光源位于目标介质内部、
相邻介质、反射、薄壁及零/有限/百万单位距离。测试执行生产起点选择与阴影消光函数，并以
独立 Beer–Lambert 期望验收；它不是硬件 ray tracing 场景测试。完整 build/shaderTest 通过。

### 1. 不透明与薄叶采样仍携带整个介质对象

`shaders/bsdf/compact/opaque/sample.slang`、`foliage/sample.slang` 的采样接口仍接收并返回介质；
其调用者 `shaders/service/bsdf/{opaque,foliage}/sample.slang` 只消费 BSDF 结果。当前介质的 IOR
已在构造闭包状态时使用，采样阶段不需要再次携带消光、身份和相函数参数。

可把这两类采样收窄为纯 BSDF 结果，由 transport 保留当前介质；实体透射单独携带目标介质。
这会减少接口和潜在寄存器存活范围。需要保持原有事件、随机数映射、PDF 和零事件语义，并
运行现有分布及数值门禁；实际运行时收益应由编译产物和 GPU 测量确认。

### 2. 传输状态与通用体积参数仍共用类型

`PrimeOpenPbrVolume` 同时包含 extinction、IOR、身份及 scattering albedo / anisotropy。
生产 Minecraft 材质构造器把 scatter 和 anisotropy 设为零；实时/离线存储恢复时也将这两项
置零。当前 transport 只积分吸收，不消费体积散射参数。

可以把生产路径介质与 compact 参考数学使用的体积参数拆成不同类型。应保留 compact
测试支持的散射参数转换，不能把当前生产零参数特化变成对参考数学的删减。该项主要收窄
源码依赖和调用状态；当前持久化记录已经不保存这两项，不能重复计算显存收益。

### 3. 已建闭包的接口还重复接收原始材质参数

`primeSampleMinecraftTransmissionCompleteFromState` 与
`primeEvaluateMinecraftTransmissionCompleteFromState` 仍接收未消费的 baseColor、opacity 和
materialControl；`primeSampleMinecraftTransmissionSplitFromState` 也有同类参数。
可统一让 FromState 接口只接收状态与方向/随机样本，使“翻译完成”的接口边界更清楚。

### 4. 纹理光学编码的兼容规则仍在逐 hit 解码

`shaders/model/material/translation.slang::primeDecodeOpticalMaterial` 仍处理导体 code、默认
dielectric F0、thin/thick SSS 和粗糙度范围。可继续把资源格式兼容策略前移到规范光学页面
生成，只给 BSDF 留已验证语义。但部分值来自纹理采样，动画、过滤与动态材质也会影响结果；
必须先建立规范 encoding 与纹理翻译门禁，不能仅因为 CPU 有 MaterialRecipe 就删掉全部分支。

## 核对后保留的设计

- BSDF 的有限性、PDF、几何半球和无效 proposal 拒绝：合法输入也可能遇到数值奇点或参考
  分布的拒绝事件；它们不是缺失材质语义的补救。
- guide 的链长上限、PSR 回退、双信号身份与生命周期：承担有界调度和重建契约，与介质历史无关。
- 离线 primary distance / albedo / material flags：`service/reconstruct/offline.slang` 仍用它们
  求大气透视和测光统计，并非未使用的实时 guide 遗留。
- f32 消光与阴影已有的 canonical encoding：只凭 MediumId 不能证明每个材质的连续参数
  都能由全局表唯一重建；进一步收窄需要独立误差门禁。

## 验证范围

CPU 行为测试覆盖单侧/双侧歧义接触拒绝、薄壁不能充当实体端点、含水实体对同侧流体的
局部排除，以及独立网格模型与输入乱序的一致性。GPU 测试覆盖介质身份与消光、Snell/TIR/eta、粗糙双侧条件采样与求值、
64 次连续边界切换、24 种阴影边界调用顺序、百万单位太阳射线和路径/guide 精确存储。

构建命令为 `gradlew.bat build shaderTest --console=plain`，包含生产 Slang/SPIR-V、ABI、
依赖闭包与发行检查。本次全部通过：598 项 CPU 测试、70 项 GPU 测试，最终构建成功。

运行日志中的 cluster `(-12, 0, 44)` 错误已在 `GNLXC_main_v1.0.1` 存档副本复现：
`(-139, 18, 727)` 的粉色玻璃块接触含水玻璃板，玻璃板端面与同 owner 的水面同时进入
接触解析，被多面检查误判为未知端点。翻译层现先裁掉玻璃板占据区域的流体，保留其余
玻璃—水边界；没有恢复介质栈或下游猜测。回归覆盖两个朝向、全部六种输入次序、边界面积
和端点身份，并覆盖含水透明/不透明实体的露出面。

修复后在副本的出错区域加载并连续累计至少 4096 samples，未再触发 Prime 退回原版。
运动玻璃、水下和重建画面仍需专项验收；本次运行验证不等同于图像质量或 GPU 帧时间测量。
