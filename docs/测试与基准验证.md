# 测试与基准验证

测试验证行为、数学、ABI 和资源契约；性能测量验证实际热路径成本。测试数量、单次耗时、
抓帧排名和实现进度不作为设计规范。运行命令与环境见[构建与验证](构建与验证.md)。

## 验证层次

| 层次 | 责任 | 边界 |
| --- | --- | --- |
| JUnit CPU 测试 | 配置、纯翻译、状态转换、生命周期、几何与采样性质 | 普通 test 不启动 Vulkan 或外部 shader 编译器 |
| Shader 产物检查 | manifest、编译闭包、descriptor、payload、布局与发布包 | 检查真实产物，不以搜索源码证明行为 |
| shaderTest | 执行生产数学、队列与几何 shader，比较结果 | 设备能力和验证失败必须明确报告 |
| native 契约测试 | Java/native ABI、图像格式、资源与 SDK 参数 | 使用项目规定的平台及依赖 |
| 游戏与 GPU 抓帧 | 重建稳定性、透明运动、帧时间、寄存器和显存 | 不用 CPU 测试或 SPIR-V 体积代替 |

属性测试通过 `PrimeProperties` 固定和报告 seed，可用 `-Dprime.test.seed` 重放。
失败应留下最小反例、输入和误差，不能通过降低断言精度消除未解释的失败。
共享支持只能进入测试/benchmark 源集，不扩大生产 API 或恢复第二套可编译 BSDF。

## 高风险门禁

- OpenPBR 修改覆盖有限性、非负性、PDF、事件与状态转换、采样/求值一致性、分布、能量、
  互易性及极端参数；外部参考要求见[紧凑模块](OpenPBR紧凑模块.md)。
- 几何验证 BLAS f32 顶点、硬件重心、精确源/目标身份、自交和动态上一帧位置。
  position fetch 的真实 RT 测试覆盖压缩前后位置与实例变换。
- 队列验证全活、全灭、混合、非整组宽度、容量和交换后清零。SER/subgroup 组合必须
  执行真正的追踪与续接；纯 compute ballot 不能证明重排后的发布安全。
- 路径预算验证 M、B、K=max(M,B) 的边界、RR 起点、终止和有限阶能量期望。
  单透明分支同时验证逆概率权重与未选分支 guide。
- 重建验证静止零 MV、jitter 符号、前后帧原点、TIR、方向天空、guide 回退、信号去调制
  和 SIGMA/REBLUR 分工；外部契约见[透明渲染与实时重建](透明渲染与实时重建.md)。
- GPU 发布和退休验证 accepted/abandoned 更新、失败清理、旧 buffer/image/AS 引用与
  slot 复用，不能把 CPU 方法返回当作 GPU 已完成。

只针对修改涉及的风险运行必要检查。数学、encoding、布局、调度和生命周期修改扩大到
相应门禁；可逆文案修改不增加镜像实现的测试。

## 基准方法

`translationBenchmark` 使用 JMH，对典型与极端捕获输入比较纯翻译开销。先用确定性产物
或哈希确认输入和结果一致，再比较吞吐、分配和 GC；benchmark 不进入默认生产执行链。
测试夹具可以共享，不能让 benchmark 初始化或外部资源进入普通单元测试。

`rectangleBenchmark` 单独测量 64×64 最优矩形分解：`finish` 复用已构建图层，`unitFaces`
包含清空和逐个单位面的输入成本。八组固定输入覆盖实心层、条纹、棋盘格、稀疏层、密集
随机孔洞、低差异孔洞、每方向 1953 条 chord 的极限图和大量标签；计时前校验覆盖与外部
参考导出的最优矩形数。默认启用 JMH 的 GC profiler，scratch 构造不在计时范围内。

```powershell
.\gradlew.bat test --tests '*Rectangle*' --tests '*MergedFace*'
.\gradlew.bat rectangleBenchmark
```

对比移植或常数优化时，应同时报告这两个入口；预热时间须足以越过 JVM 编译阶段，不能
把运行中发生的性能阶跃平均成算法收益。分解缓存的容量依赖整数网格上界，缩小缓存时
同时验证极限 chord、3969 条冲突边、63 度顶点、标记回绕、标签和输入顺序变化。

GPU 比较固定设备、场景、视角、内部与显示尺寸、bounce 设置、SER/subgroup 和重建模式。
报告 GPU 时间、常驻/峰值显存、allocated/live registers、active threads per warp、spill
与实际热点。频率、场景或调度不同的捕获只能定位疑点，不能直接报告算法加速比。
寄存器分析与后续准入见[路径追踪性能约束](路径追踪性能约束.md)。

实时验证以移动时可重建的信号和帧时间为主；离线比较相同预算后的方差与误差。降低路径
长度、dispatch 数、源码 load 数或编译产物体积只是线索，不能替代这两类验收。
