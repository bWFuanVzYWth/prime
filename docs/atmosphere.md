# 大气资产、更新与消费契约

大气沿用旧 Prime 调整过的四波长介质、逐次多散射、相函数和光谱到 Rec.2020 拟合。太阳、散射天空与空气透视使用同一源光谱和共同比例，移除独立天空强度与逐通道白化。物理输入来自 Sky Tracer `b66b16342afe38e788a5ece5371d3b3a67c5909a`；来源和许可证见 [第三方声明](../THIRD_PARTY_NOTICES.md)。这里描述生产路径；单次测量和对拍结果放 `artifacts/`。

## 源边界与默认值

两个 Java 适配器在 `LevelExtractor.extract` 的天空源准备点读取相机 `EnvironmentAttributeProbe` 的 `SUN_ANGLE`，使用宿主相同的 partial tick 插值与角度到弧度转换，存入 `skyRenderState.sunAngle` 后连同相机绝对位置发包。Prime 接管时跳过原版天空的其余提取，不依赖只在原版 `addSkyPass` 中惰性创建的 `SkyRenderer`，也不重复求值太阳属性；切回原版则恢复原调用。96字节 `PrimeFrame` 通过具名 `solar_hour_angle` 字段传递 f32 太阳时角，单位弧度。`prime_minecraft` 解释时角，使用 Rust 的 `SolarOrbit` 按观测纬度、太阳黄经和旧轴倾角 23.43928°产生方向；默认纬度 30°、黄经 0°；`prime_scene::Environment` 包含世界高度、基准海拔和单位太阳方向。Rust 负责失效与 GPU 调度。离线冻结同时冻结时角、纬度/季节、世界高度、海拔偏移和视角。观测纬度范围 -90°…90°，太阳黄经范围 0°…359°；0/90/180/270° 对应春分/夏至/秋分/冬至（北半球）。季节沿用旧版手动控制，与游戏天数独立。纬度和赤纬的常量只在设置变化时由 CPU 准备，每帧只计算实际时角。

默认值保持地面半径6360 km、大气顶6480 km、世界单位1 m、气溶胶密度倍率1、太阳角半径0.00471 rad。用户选择的太阳渲染基准为积分亮度Y=8，太阳EV默认0；这与源光谱的绝对太阳照度分别说明，不能把8直接称为lux。光照组的“基准海拔”范围为0–10000 m，默认500 m，配置键为`atmosphere.altitude_offset_meters`。物理高度为`(世界Y + 64) × 0.001 + 偏移米数 × 0.001` km；偏移为0时Y=-64对应地面，默认时对应500 m。世界高度到f32半径的转换点和大气内clamp与旧版相同。偏移只改变空气高度映射，不移动几何或水体；离线沿用冻结值。颜色输运使用450/510/580/650 nm四个采样点，最终为线性Rec.2020；保留源太阳白点到D65的色适应和四波长拟合近似。

固定源`M*ATM_SOLAR`约为`[196.52023,196.53863,196.57865]`，其Y约196.53617；按光谱依据与[683 lm/W光度定义](https://www.bipm.org/en/si-base-units/candela)计算，外大气直接法向太阳照度约134234 lux。生产使用单一标量`8 / workingY(M*ATM_SOLAR)`作用于太阳及所有散射阶，保留它们的相对颜色与辐射关系。当前基准RGB约`[7.999351,8.000100,8.001729]`，属于明确选择的艺术幅度。太阳圆盘辐亮度使用`RGB / (π*sin²角半径)`，使投影积分等于直接法向源；采样PDF继续使用普通立体角`2π*(1-cos角半径)`。

物理介质固定为上述调优配置；设置页的光照组提供纬度、太阳黄经和海拔偏移。气溶胶编辑器、天气、月亮和维度专属天空尚未接入。星图沿用旧 Prime 的天文投影与固定 NASA 资产，原版几何星星提取在接管后跳过。光学边界的折射、Beer 与未知 coverage 支持各自的显式范围，见[材质契约](materials.md)；这些能力不能外推为旧版所有场景外观等价。

## 资产

GPU 纹理使用 KTX2 内部 Zstd 22，命名物理数组使用标准 Safetensors 外包 Zstd 22；little-endian、原始 FP16/FP32 位模式无损。物理语义由 metadata 明确规定，不从扩展名推断相函数的归一化或角度约定。格式与再封装规则见[固定资产规范](assets.md)，逐资源哈希见[manifest](../crates/prime-vulkan/assets/packed-assets.json)。

- `assets/atmosphere/medium.safetensors.zst`：命名的 f32 高度、介质 profile、相函数、积分质量、求积节点及映射系数。相函数为 `sr^-1`，`mu=+1` 表示前向；坐标为 `u=cbrt((1-mu)/2)`，1024 个中心节点，在 u 域线性插值、端点 clamp。四类粒子、四个波长和原始浮点位模式保持不变。
- `optical_depth.ktx2` / `scattering_source.ktx2`：512×128 / 3200×240 RGBA16F 的 optical depth 与归一化 scattering source。
- `incident_mean.ktx2` / `ground_radiance.ktx2` / `rayleigh_source.ktx2`：160×40 / 160×1 / 800×21 RGBA32F 的 incident mean、ground radiance 与 Rayleigh moments。五表均为八轮、每状态1536个入射方向求解的原产物，只有一层mip；数值轴和通道保持原定义，不作为彩色图像转换。

固定资产编入 native 库，初始化校验、解压和上传，不重新运行多散射求解器。纹理直接解压到上传staging，物理介质解压后验证元数据与数组，再按固定 GPU 布局连接一次；shader 不解析容器，稳态不重复解压。离线工具按原计算依赖生成标准 Safetensors 中间产物，统一封装脚本生成发行资产；工具特性不编入默认发行路径。再生成命令见 [CONTRIBUTING](../CONTRIBUTING.md#大气资产与无窗口验证)。

## 星图资产与天空消费

`assets/starmap/starmap_2020_16k.ktx2` 保留 NASA Deep Star Maps 2020 的 16K ICRF/J2000 星图与15层球面立体角加权 mip。BC6H资产已在离线工具中按旧源线性sRGB解释转换为D65线性Rec.2020；初始化只做Zstd解压，不转码或重复色域转换。原始EXR未声明primaries/white point，来源/编码/hash与独立credit见[manifest](../crates/prime-vulkan/assets/starmap/starmap_2020_16k.json)和[NASA声明](../licenses/NASA-DEEP-STAR-MAPS-2020-NOTICE.md)。完整链170.67MiB GPU常驻，直接解入15个mip staging，基层单次分配128MiB，全部170.67MiB staging可保留至完成；上传owner遵守独立fence或宿主serial回收。

`AtmLighting`/`AtmEnvironment`显式接收星图sampler与纬度、季节和scale常量。`atmSky`返回散射天空×太阳倍率，加星图LOD0×方向透射×`0.025×stars`；星图仍使用独立的艺术幅度，无绝对光度metadata，不宣称已有nits标定。地球遮挡为零。纬度和太阳黄经沿用同一观测配置；恒星时相位由当前太阳方向和太阳赤经得到，赤经缝使用wrap。

raw、Offline和反射/折射后续miss在环境终点消费星图。RR仅第一相机射线直接miss省略星图，随后在重建后的原生输出分辨率用未jitter方向、最多8tap/mip滤波合成；真实首命中前景位、重建alpha和guide完成状态分别保持身份。该后合成不替代路径内的星光。合成顺序、coverage、滤波近似与显存/分发成本集中维护在[显示契约](display.md)。星图不会使现有SkyView/Aerial资源失效或改变太阳采样/PDF。

| Aerial-T | 128×64×128 RGBA16F，约 8 MiB | 高度、姿态、FOV、宽高比变化 |

| 遮挡剖面历史 | 256×(1536+5) uint，约 1.5 MiB | 非场景输入变化时重写；否则精确比较五级计数及有效 blocker depth |

生产空气透视消费显式使用 Aerial-S 的 256 极线切片契约，与 Rust 分配、更新 dispatch 和 `ATM_AERIAL_RADIANCE_SLICES` 一致，不在路径内动态查询纹理尺寸。通用极线采样 API 仍可查询调用方纹理的实际高度；指定切片数的入口要求该值等于纹理高度。改变生产 LUT 布局时同步修改分配、更新与消费。

依赖使用精确输入身份，没有时间阈值、低频更新或旧帧混合。遮挡失效与外观世代分开：动态实例仅 RGB tint 变化保留缓存，alpha、UV、纹理身份、几何、姿态及未认证资源变化仍失效，不以 TLAS 重建为依据；纯材质变化仍跳过 TLAS 重建。静态普通 producer Triangles/Quads/QuadFragments 以自持 Arc、范围和实际几何/UV/纹理/flags/alpha 精确对照证明 RGB-only；编译生成的 SurfaceMesh、复杂表面和未知源继续保守失效，不额外保留整份编译输出。旧 producer owner 可保留到对应格实际替换/移除。静止且输入不变时全部 LUT 复用；太阳持续运动仍会刷新 SkyView 与 Aerial-S，相机旋转仍会刷新两份空气透视。资源在同一宿主队列按显式依赖更新和消费。描述符/帧常量仅写已完成的槽，资源退休沿用宿主完成值，创建失败与提交不确定性遵守现有隔离规则。

遮挡沿用旧版五级 0.5/1/2/4/8 m 网格、3×3 保守膨胀、2 cm bias、近级 512 / 远级各 256 项的极线剖面和可见长度积分。GPU 先原子标记剖面需要的 3×3 邻域，再通过硬件最近命中查询补齐请求列，最后读取 blocker depth 构建剖面；三个 pass 之间有显式依赖。无需维护旧版 Java 双银行、分帧瓦片状态或额外 min/max mip。列存请求代次、世界网格身份和 blocker depth，2 km 分片固定追踪平面，射线全长 8 km。未覆盖、剖面溢出及不可解析区间保持遮挡。实际遮挡依赖变化仍整体清空遮挡缓存，尚未做空间局部失效。

遮挡依赖变化后仍在当前帧重查遮挡列，包括粒子与材质 coverage；已证明的纯 RGB 外观变化复用遮挡。相机、高度、太阳和投影完全相同时，每条极线的区间边界不变；GPU 逐位比较有效 blocker depth 和五级计数，只有不同的极线重算光谱积分并写 Aerial-S。比较不使用哈希、容差或时间阈值；溢出剖面的无效尾部不参与比较。相机或太阳变化仍全量计算，不把动画忽略或推迟到后续帧。

## 每条路径的消费

SkyView 的太阳仰角、地平线与三个 chart 系数按帧准备，查询只做方向映射、一次硬件双线性过滤和指数解码。太阳方向基预计算，有限圆盘按立体角均匀采样，Camera-T 硬件过滤并单独判断地球遮挡；可保留地平线上的部分圆盘。NEE 和 BSDF miss 使用一致的圆盘 PDF/MIS，最后允许的顶点只有 NEE 时权重为 1。

空气透视仍在 primary hit 合成 `L = T*L + S`，使用同一相机 jitter、实际射线距离、旧平方深度分层与近端权重，最大距离 2.048 km。T 用一次硬件三线性查询；S 对两个相邻极线各做一次径向/深度过滤，再沿极线插值。相邻极线的径向坐标不同，不能直接替换成一次普通三线性查询。可见极线范围提前计算，消费不再重复做四个角的 atan2 和排序。Sky miss 不重复叠加有限距离空气透视；S 随太阳强度设置缩放，T 不随曝光或太阳强度变化。

海拔设置复用已有物理半径输入；有效 f32 半径变化会刷新 SkyView、Camera-T、Aerial-S 与 Aerial-T，太阳遮挡格网继续使用场景的实际世界坐标。设置不增加 GPU 字段或 pass。

无窗口验证覆盖300 m来源与500 m默认值、范围/clamp、实际天空输出及LUT更新复用、原光谱夹具与按共同基准换算的SkyView参考、太阳投影积分及地平线、太阳/天空/S同比缩放而星图/T独立、空气透视对直接积分、硬件过滤、零距离、遮挡更新与Vulkan同步。固定预计算已经包含太阳光谱，旧metadata中的12.5只保留历史来源信息，运行时不以它标定；共同幅度调整不需要重烘资产。游戏视觉、连续昼夜/跑图p95与帧数由用户在原生1920×1080验收，局部查询检查不能外推整帧收益。
