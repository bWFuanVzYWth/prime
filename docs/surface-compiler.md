# 自定义表面编译原型

`prime_scene::surface` 是版本无关的 CPU 编译入口，`prime_vulkan::packing` 定义直接 GPU quad 产物，`prime_vulkan::surface` 发布灯资源。它与 Minecraft 源适配分开：Java 的绑定和回调、`prime_minecraft` 的版本解释继续遵循[源边界](capture-boundaries.md)。当前封闭 quad 桥接没有来源证明、介质或发光声明，不能从纹理颜色或方块亮度猜测这些事实。

## 唯一编译路径与范围

所有 renderer 的静态几何更新统一经过表面编译器，不再提供旧编译流程或选择开关。编译器可以证明无需改变的输入复用原始共享几何；这是同一编译流程的产物选择。继续使用硬件三角形求交，不增加跨帧编译配额。启动与测量命令见 [CONTRIBUTING](../CONTRIBUTING.md)。

当前原型包含：明确来源域的表面输入、受证明约束的规范化、规则面矩形分解、直接着色记录、常量发光的局部/全局光源树、GPU NEE 和发光命中 MIS。源桥接仍消费既有已剔面的 quad，**尚未完成提前保留光学接触面的 Minecraft 源改造**。游戏中的水/岩浆不会因为后端支持声明式发光就自动成为光源。

## 语义与几何编译

`SurfaceQuad` 保存封闭几何、来源/运动域、显式线性 RGB 发光与表面规则。`Preserve` 不猜测邻近面关系；`Duplicate(group)` 只在同域、同证明组中移除几何和着色严格一致的冗余副本。证明比较实际两组三角形及逐角 UV，不以排序后的四个位置推断非平面 quad 的对角线等价。单侧发光不使用无向冗余证明。

`Interface` 表示没有附加涂层或发光的介质界面。相同介质的界面消除，不同端点保留其绕序语义。当前 renderer 尚无介质输运，对非零介质端点明确拒绝，不把它们渲染成已支持的物理玻璃/水。任意薄壳、未知重合层和非对齐面保持原几何，不做 epsilon 吸附。

规则合并只接受严格轴对齐、整数网格的单位面，以及在两个原始三角形上相同的仿射 UV 映射。规则合并输入为统一颜色；任意源三角形和逐角颜色均保留，由更新期规范化为完整或退化quad。方向、平面、64×64 局部域、运动域、texture/coverage、颜色、UV 映射、发光及介质端点共同限定合并。每次分解使用本地 `u16` 标签，绝不截断全局材质 ID。未知同格重叠的所有参与面都排除出合并。

`rectangle_decomposition` 产生同标签、无重叠、无缺口的矩形。scratch 随 compiler 持有并跨调用复用，不逐面/逐平面创建。产物SurfaceMesh保存四角SurfaceFace，不保存两份展开三角形。非规则面保持原剖分，每个quad通过共享索引提供两个硬件三角形。纹理使用 `origin + du * frac(s) + dv * frac(t)` 重复原单位面的 UV，不能拉伸 atlas 区间。单格矩形保留原映射，不增加 `frac`。

静态单元的独立编译使用既有 Rust 同步工作池，每个分区持有并复用 compiler scratch，返回前全部 join。没有规则面候选的封闭输入只扫描原始共享页，不展开中间三角形；同平面中不存在同标签共享边时可证明没有合并机会，直接跳过分解。保留面只暂存源索引，完成分解却没有减少面数的封闭输入继续使用原页。已携带显式语义的 `SurfaceMesh` 不使用这个快捷判据。规则网格仍有分类、排序与临时源记录成本，不能据此宣称所有反例都是零编译成本。

重三角化改变硬件重心坐标的浮点舍入和按三角形范围计算的安全起点误差界；多次反弹时也可能改变落在随机覆盖量化边界附近的样本。纹理/覆盖边界需要单独做像素差分，不能要求不同三角化在相同种子下逐位相同。格式切换、资源替换则必须与同编译策略的全新场景逐位相同。不得将这些数值边界扩展为几何吸附或颜色近似许可。

## 常驻 GPU 数据

源/编译表示不等于 GPU 表示。当前原型由 CPU 在更新时直接生成完整记录；尚未引入 GPU 上传展开。它不通过模板、SurfaceKey 或共享角点字典逐次解释命中。

| 记录 | 字节数 | 消费方式 |
| --- | ---: | --- |
| 普通quad | 176 | 四个位置、完整f32逐角颜色与UV、纹理及coverage标志 |
| 扩展quad | 240 | 普通记录后追加64B重复映射、发光与身份 |
| 静态geometry表项 | 64 | 记录地址/格式、局部灯地址、世界灯摘要、单元平移 |
| LightNode | 32 | 两个相邻子节点或一个叶子索引、空间范围和功率 |
| emitter采样记录 | 240 | 每个发光quad一份完整直接记录，选灯后不再查通用几何 |

普通记录0–63B为四个float4位置，64–127B为四角f32颜色，128–159B为四角UV，160–167B为texture/coverage，168–175B保留为零。format为0/1，表示普通/扩展记录，步长为 `176 + 64*format`。扩展的前32B为两行UV映射，随后16B为线性发光与 `power/area`，最后16B为介质、emitter及repeat/双侧标志。命中记录中的位置w为零；独立灯记录的第一个位置w保存第一半面的面积概率。

硬件仍使用三角形求交：固定索引 `012 / 230`，primitive index右移一位直接取得quad，最低位选择三个角及原始重心插值。独立三角形ABC存为ABCC，第四角复制完整属性，退化半面不产生交点。源三角形只有相邻两张的公共位置/颜色/UV逐位相同、材质一致且角点顺序严格吻合时才重新成对；否则各自退化，不进行近似焊接。非平面quad不改成双线性曲面。

源ABI及CPU源范围仍按三角形计数。源边界切开的半个quad规范化为退化quad；此后的GPU分配、上传、共享索引及BLAS geometry保持完整primitive pair。位置与AS构建复用f32字段，顶点步长16B；各记录格式使用对应共享索引。每个范围采用最宽240B记录的保守上限 `floor(2^32/240)`，总场景可跨页。

静态更新按实际字段需求拆分格式范围，局部合并不再把未合并普通面整体升级；同一BLAS可含这些范围。对象原型/动态桶保持单个geometry，统一使用176B普通记录；对象元数据与宿主源ABI不变。CPU源索引只用于更新期打包，不传GPU；未变化原型继续复用BLAS。

静态单元的平移约束、NVIDIA RTX双侧误差界与运算次序保持，动态实例仍使用一般仿射矩阵。统一quad不强迫普通面携带全部复杂材质字段，也不引入SurfaceKey或共享角点解码链。CPU源仍可只存单份均匀色，GPU记录保留四角颜色，以固定的颜色字段代替每次命中的均匀色/逐角色分支；不再为颜色另增格式和页池。池页仍保留历史峰值及最小页容量，逻辑记录字节减少不能等同实际常驻或峰值显存；退化primitive仍计入构建输入上限与尺寸查询。

每个 renderer 模式为同一 shader 预建普通记录、无灯扩展记录、有灯扩展记录三个特化管线，共用描述符与接口。通过 Vulkan specialization constants 消除未使用的扩展读取、发光命中和 NEE 分支；发布后的场景状态只选择已存在的句柄，首个灯出现时不临时编译 shader。整个场景无需扩展记录时使用普通记录特化，静态平移重建仍然生效；这些特化不提供另一种编译策略。管线同 renderer 的完成证明一起销毁。此策略增加初始化工作，收益需要与固定历史构建比较，不能只与同一个已增加通用分支的对照比较。Slang 属性参见[官方说明](https://docs.shader-slang.org/en/latest/external/slang/docs/user-guide/a2-01-spirv-target-specific.html#specialization-constants)。

## 光源、采样与发布

从最终规范几何提取非零面积 emitter，几何编号、emitter 映射和局部树属于同一个 `SurfaceMesh` 与 revision。常量发光是显式材质事实，不是 proposal 权重；功率按面积、线性 RGB 亮度和单/双侧定义。极端面积/功率超出当前 f32 ABI 时明确失败。

局部树和全局树使用相邻子节点、单 emitter 叶子及平衡空间划分。当前 proposal 仅按功率选择，尚无位置相关重要性、SAOH 或纹理分布。全局树引用本次静态 geometry 表项；每个源SurfaceMesh的局部灯只发布一次，即使着色记录被拆成多个格式范围；局部树与采样记录按单元几何发布，未变单元复用其资源。全局表在场景发布/重定位时重建，不能把它描述为常数更新成本。

GPU 将选择后的剩余均匀样本从全局树传给局部树，再按两个原始半面的面积比例选择半面并重映射样本，沿该三角形做重心采样。零面积半面没有采样质量；两半均为零则不入树。非等面积quad保留真实比例，极端概率超出当前f32 ABI时明确失败。前向面积 PDF 与发光命中反向 PDF 共用记录中的 `power/area` 和同版本全局总功率；立体角转换使用实际距离和几何法线。主射线、采样点 coverage 和有限长度阴影使用同一覆盖定义。NEE 和 BSDF 命灯通过 power heuristic 合并；最后一个允许反弹的 NEE 不与已禁止的 BSDF 延续竞争。

灯采样使用 `512+4*bounce` 起的独立 Z-Sobol domain，保留现有相机、太阳和 BSDF 的 domain。动态发光尚未注册。纹理发光、动画的重要性支持域、正反不同材质、ordered overlay/substrate、介质边界解析和已知 inset 修复仍需补充源契约和编译规则，不能由当前常量发光测试推断已经支持。

CPU 产物使用不可变共享所有权；上传、AS 和灯 buffer 沿用 Context 的实际完成/取消证明。一个命令序列发布对应的几何、表项和灯数据。旧资源不能按经过帧数释放，失败走 renderer 的隔离路径。仅改发光目前仍触发对应静态簇重建，细分几何/材质/灯失效尚未实现。

## 验收原则

源解释、自定义规范化、最终 GPU 消费分别验证。性能优先级为稳态帧数 > 显存节省 > 加载效率；分别记录 CPU/GPU 帧时间、常驻/峰值显存、更新到可见 p95 与上传吞吐。原生1920×1080固定输入与射线预算，保留不能合并、透明覆盖及在途替换反例。离屏行为/性能不替代游戏验收。

优化需要同时做复杂度判断：整帧收益有限却显著增加状态、解码、同步或兼容分支时，明确选择保留、简化或移除。矩形数量最少不等于帧率最高；编译器必需的语义能力与可选的性能技巧分别记录证据。单次数据、候选布局和决策放在被忽略的 artifacts，后续事项由 [TODO](../TODO.md) 管理。
