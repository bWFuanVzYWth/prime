# 自定义表面编译原型

`prime_scene::surface` 是版本无关的 CPU 编译入口，`prime_vulkan::surface` 定义其直接 GPU 产物。它与 Minecraft 源适配分开：Java 的绑定和回调、`prime_minecraft` 的版本解释继续遵循[源边界](capture-boundaries.md)。当前封闭 quad 桥接没有来源证明、介质或发光声明，不能从纹理颜色或方块亮度猜测这些事实。

## 选择与范围

`PRIME_SURFACE_COMPILER=rectangles` 在 renderer 创建时选择实验路径，默认 `legacy`。同一个 renderer 不在在途帧之间切换编译策略。两条路径共用源输入、材质、采样预算和硬件三角形求交；不采用体素自定义求交，不增加跨帧编译配额。启动与测量命令见 [CONTRIBUTING](../CONTRIBUTING.md)。

当前原型包含：明确来源域的表面输入、受证明约束的规范化、规则面矩形分解、直接着色记录、常量发光的局部/全局光源树、GPU NEE 和发光命中 MIS。源桥接仍消费既有已剔面的 quad，**尚未完成提前保留光学接触面的 Minecraft 源改造**。游戏中的水/岩浆不会因为后端支持声明式发光就自动成为光源。

## 语义与几何编译

`SurfaceQuad` 保存封闭几何、来源/运动域、显式线性 RGB 发光与表面规则。`Preserve` 不猜测邻近面关系；`Duplicate(group)` 只在同域、同证明组中移除几何和着色严格一致的冗余副本。证明比较实际两组三角形及逐角 UV，不以排序后的四个位置推断非平面 quad 的对角线等价。单侧发光不使用无向冗余证明。

`Interface` 表示没有附加涂层或发光的介质界面。相同介质的界面消除，不同端点保留其绕序语义。当前 renderer 尚无介质输运，对非零介质端点明确拒绝，不把它们渲染成已支持的物理玻璃/水。任意薄壳、未知重合层和非对齐面保持原几何，不做 epsilon 吸附。

规则合并只接受严格轴对齐、整数网格的单位面，以及在两个原始三角形上相同的仿射 UV 映射。当前 quad 输入为统一颜色；任意三角形及其逐角颜色保持通用路径。方向、平面、64×64 局部域、运动域、texture/coverage、颜色、UV 映射、发光及介质端点共同限定合并。每次分解使用本地 `u16` 标签，绝不截断全局材质 ID。未知同格重叠的所有参与面都排除出合并。

`rectangle_decomposition` 产生同标签、无重叠、无缺口的矩形。scratch 随 compiler 持有并跨调用复用，不逐面/逐平面创建。非规则面保持原三角化；矩形也输出两个硬件三角形。纹理使用 `origin + du * frac(s) + dv * frac(t)` 重复原单位面的 UV，不能拉伸 atlas 区间。单格矩形保留原映射，不增加 `frac`。

静态单元的独立编译使用既有 Rust 同步工作池，每个分区持有并复用 compiler scratch，返回前全部 join。没有规则面候选的封闭输入只扫描原始共享页，不展开中间三角形；同平面中不存在同标签共享边时可证明没有合并机会，直接跳过分解。保留面只暂存源索引，完成分解却没有减少面数的封闭输入继续使用原页。已携带显式语义的 `SurfaceMesh` 不使用这个快捷判据。规则网格仍有分类、排序与临时源记录成本，不能据此宣称所有反例都是零编译成本。

重三角化改变硬件重心坐标的浮点舍入和按三角形范围计算的安全起点误差界；多次反弹时也可能改变落在随机覆盖量化边界附近的样本。纹理/覆盖边界需要单独做像素差分，不能要求不同三角化在相同种子下逐位相同。格式切换、资源替换则必须与同编译策略的全新场景逐位相同。不得将这些数值边界扩展为几何吸附或颜色近似许可。

## 常驻 GPU 数据

源/编译表示不等于 GPU 表示。当前原型由 CPU 在更新时直接生成完整记录；尚未引入 GPU 上传展开。它不通过模板、SurfaceKey 或共享角点字典逐次解释命中。

| 记录 | 字节数 | 消费方式 |
| --- | ---: | --- |
| 既有 Triangle | 128 | 通用原型/动态对象、legacy 静态几何及实验路径中未改变的封闭几何 |
| SurfaceRecord | 192 | 按 hardware primitive index 直接读位置、逐角颜色/UV、重复映射、发光和身份 |
| 静态 geometry 表项 | 64 | 记录地址/格式、局部灯地址、世界灯摘要、单元平移 |
| LightNode | 32 | 两个相邻子节点或一个叶子索引、空间范围和功率 |
| emitter 采样记录 | 192 | 独立复制完整 SurfaceRecord，选灯后不再查通用几何 |

SurfaceRecord 前128B保持原 Triangle 布局；128–159B为两行 UV 映射；160–175B为线性发光与已表示的 `power/area`；176–191B为介质端点、emitter 索引和显式重复/双侧标志。位置与 AS 构建复用同一 f32 字段，顶点步长16B、索引跨12个16B槽。每个直接寻址范围不超过4GiB，192B记录的本地上限是 `floor(2^32/192)`，总场景可跨页。

每个 BLAS geometry 范围的记录步长一致，表项 format 位0选择128/192B，位1声明使用静态平移重建。同一 BLAS 可包含两种记录范围，更新时可更换范围格式；它们分别使用已有分页分配器和共享索引。普通几何不为未使用的重复 UV、介质和发光字段支付50%扩展。该选择只发生在更新阶段，命中时仍是一次直接寻址。池页保留历史峰值与最小页容量，逻辑记录字节数不能当成实际常驻/峰值显存。

静态单元只有平移，实验路径利用此生产者约束特化表面重建，保留 NVIDIA RTX 的两侧误差界和运算次序；动态实例继续使用一般仿射矩阵。增加字段、拆热/冷流或改记录尺寸都需测量完整帧时间，不以字节数或指令数代替收益。

每个 renderer 模式预建旧路径、无灯表面、有灯表面三个管线，共用描述符与接口。通过 Vulkan specialization constants 消除未使用的扩展读取、发光命中和 NEE 分支；发布后的场景状态只选择已存在的句柄，首个灯出现时不临时编译 shader。实验路径中整个场景都不需要扩展记录时也选择旧 shader，避免为不存在的功能保留命中分支。管线同 renderer 的完成证明一起销毁。此策略增加初始化工作，收益必须与真实旧版 shader 比较，不能只与同一个已增加通用分支的对照路径比较。Slang 属性参见[官方说明](https://docs.shader-slang.org/en/latest/external/slang/docs/user-guide/a2-01-spirv-target-specific.html#specialization-constants)。

## 光源、采样与发布

从最终规范几何提取非零面积 emitter，几何编号、emitter 映射和局部树属于同一个 `SurfaceMesh` 与 revision。常量发光是显式材质事实，不是 proposal 权重；功率按面积、线性 RGB 亮度和单/双侧定义。极端面积/功率超出当前 f32 ABI 时明确失败。

局部树和全局树使用相邻子节点、单 emitter 叶子及平衡空间划分。当前 proposal 仅按功率选择，尚无位置相关重要性、SAOH 或纹理分布。全局树引用本次静态 geometry 表项；局部树与采样记录按单元几何发布，未变单元复用其资源。全局表在场景发布/重定位时重建，不能把它描述为常数更新成本。

GPU 将选择后的剩余均匀样本从全局树传给局部树，再均匀采样最终三角形。前向面积 PDF 与发光命中反向 PDF 共用记录中的 `power/area` 和同版本全局总功率；立体角转换使用实际距离和几何法线。主射线、采样点 coverage 和有限长度阴影使用同一覆盖定义。NEE 和 BSDF 命灯通过 power heuristic 合并；最后一个允许反弹的 NEE 不与已禁止的 BSDF 延续竞争。

灯采样使用 `512+4*bounce` 起的独立 Z-Sobol domain，保留现有相机、太阳和 BSDF 的 domain。动态发光尚未注册。纹理发光、动画的重要性支持域、正反不同材质、ordered overlay/substrate、介质边界解析和已知 inset 修复仍需补充源契约和编译规则，不能由当前常量发光测试推断已经支持。

CPU 产物使用不可变共享所有权；上传、AS 和灯 buffer 沿用 Context 的实际完成/取消证明。一个命令序列发布对应的几何、表项和灯数据。旧资源不能按经过帧数释放，失败走 renderer 的隔离路径。仅改发光目前仍触发对应静态簇重建，细分几何/材质/灯失效尚未实现。

## 验收原则

源解释、自定义规范化、最终 GPU 消费分别验证。稳态 CPU/GPU 帧时间优先；更新到可见 p95、上传吞吐和常驻/峰值显存其次。原生1920×1080固定输入与射线预算，保留不能合并、透明覆盖及在途替换反例。离屏行为/性能不替代游戏验收。

优化需要同时做复杂度判断：整帧收益有限却显著增加状态、解码、同步或兼容分支时，明确选择保留、简化或移除。矩形数量最少不等于帧率最高；编译器必需的语义能力与可选的性能技巧分别记录证据。单次数据、候选布局和决策放在被忽略的 artifacts，后续事项由 [TODO](../TODO.md) 管理。
