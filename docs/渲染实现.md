# 渲染实现

本文概述当前稳定实现。透明数学、离线传输、场景流送和测试契约分别由对应专题文档维护；
仍开放的问题只记录在 [FIXME](FIXME.md)，未来增强只记录在 [TODO](TODO.md)。GPU 命中、
射线端点和运动重建的强制规则见 [GPU 几何追踪精度契约](GPU几何追踪精度契约.md)。

## 渲染模式

### 实时

实时路径通常每像素每帧生成一个样本。`ReconstructionBackendRegistry` 固定提供三个内建
后端：DLSS Ray Reconstruction、NRD + FSR 和原生分辨率 Noisy。DLSS 能力、optimal-size
查询或 feature 创建失败时只回退 NRD-FSR；配置值不被静默改写。NRD/Noisy 创建失败保持
fail-fast。

五档质量由各后端 profile 解释：FSR profile 定义内部尺寸、mip、jitter 和 ray cone；
DLSS profile 定义 NGX quality、optimal query 与 RR jitter；Noisy 固定原生尺寸。语义
`RealtimeFramePlan` 不包含 Vulkan handle 或后端 native 类型。

产品默认选择“性能”重建质量，目的是避免满足最低功能要求的较低端设备在首次启动或恢复
默认值后因内部像素数和显存开销而严重卡顿，不表示 Prime 对所有设备推荐某个固定档位。
重建质量应由用户按 GPU、输出分辨率、场景与目标帧率调整；缺失或未知配置回退到安全
默认值，并写回合法稳定 ID。

### 离线渲染模式

`OfflineRenderer` 冻结相机、天文、场景、材质、纹理 revision、相机介质和动态纹理列表，
在窗口原生分辨率累积 RGBA32F 运行均值。它旁路实时降噪与超分，并使用独立随机透明闭包和
全路径直接光估计；详细契约见[离线光传输契约](离线光传输契约.md)。

进入会话时复制实时显示通道的 16-byte 自动曝光状态，之后只读使用。最终曝光和显示曲线
可以即时调整，不修改累积样本。纵横比变化保留冻结姿态、更新投影并重新累积；世界或资源
切换会退出会话，避免混合不同场景。

## 积分器与透明

实时和离线使用各自的 KHR ray tracing pipeline、SBT、set 1 ABI 和 wavefront 状态，pipeline
递归深度为 1。miss、closest-hit 和 any-hit 只返回遍历结果；实时由固定 Wavefront 前缀与
Megakernel Tail 组成，离线每个反弹使用 Trace、Light Select、Direct、Scatter 四段式
Wavefront。
支持 raygen subgroup ballot 的设备独立加载 subgroup queue permutation；同时实际提供
invocation reorder 的设备加载 SER permutation。

实时 pipeline 声明 20 个逻辑 raygen group，由 15 个操作模块组成。每帧调度为：

```text
camera-trace → visible-direct → surface-split → delta-walk
    → landing-light-select → landing-direct → landing-scatter
    → (minimumBounces - 1) ×
      (fixed-bridge-trace → fixed-light-select → fixed-direct → fixed-scatter)
    → tail-admission → tail → branch-resolve → noisy-output-resolve
```

delta-walk Megakernel 只在精确 Delta 表面上直接推进，把普通路径或首接口条件双分支推到首个
非 Delta 表面或链上限。landing 完成包含主表面的第一轮固定 Wavefront；每个后续固定轮次按
Trace、Light Select、Direct 和 Scatter 切成四个窄阶段。Light Select 独占两级灯光树遍历，
Direct 对选中的面光源与太阳各取一个样本，Scatter 只负责 OpenPBR 推进。固定前缀不执行 RR。
tail-admission 对存活路径执行延后的首个 RR 并压缩队列；tail 每条路径只读一次队列状态，在
寄存器中完成余下 Trace、双 NEE、OpenPBR Scatter 与 RR，最后只写回一次结果。

“额外镜面反弹次数”控制 Delta 链长度，范围 1–64、默认 16；“最小反弹次数”控制包含主表面的
固定 Wavefront 轮数，范围 1–8、默认 2；“最大反弹次数”范围 1–64、默认 16。实时的最大值统计
固定 Wavefront 与 Tail 的主表面起常规传输，不计前置 Delta 链；它低于最小值时不能缩短固定
前缀，高于最小值的部分由 Tail 完成。实际调度数为 `4 × (minimumBounces - 1) + 11`，不随
最大反弹数增长。离线直接把最大反弹次数用作相机路径的总上限，调度数为
`4 × maximumBounces + 1`。

delta-walk 使用独立的
opaque/dielectric 离散源码岛；一般阶段的
opaque/complex 分类仍在执行阶段内部，尚未形成材质队列。是否增加该运行时分区只由实机 GPU
门禁决定，不能反向恢复全功能源码聚合。生产 entry 的目标可见性、变种约束和运行时
验收见[生产 Shader 编译边界契约](生产Shader编译边界契约.md)。

实时与离线积分器对太阳和方块面光源使用 NEE。每个支持立体角测度的实时顶点固定各采样
一次太阳和面光源，不执行光源族重要性估计、随机选族或族概率持久化。发光面进入未软化的
两级 world light tree；太阳单独采样。
两者默认使用同一个单候选尖锐树，并在存在竞争技术时重建反向树 PDF 做 power-heuristic MIS。
着色器 ABI 为反弹计数保留 128 的内部安全容量，产品设置只接受上述 1–64 范围。
CPU 建树将每个 section/emitter 作为单条目叶；候选划分先按 SAOH 排序，只在最优值的 2%
质量带内，以聚合功率加权的平衡二叉树后续深度作第二排序键。该项只改变树拓扑，不改变 GPU
节点 ABI、运行时概率或可反向重建的 bit trail。
多条目的 world 叶按各 section 根节点重算接收者相关目标，多条目的 section 叶按实际发光三角形
边界重算目标；单条目叶保持概率 1 的快速路径。目标近似 projected solid angle，并以完整 f32 着色法线的
余弦朝向代理 BRDF 支持域，形式为有界角度功率除以距离平方，另保留 `1/256` 的支持域地板。它不是
OpenPBR BSDF 的近似求值；BSDF 仍作为独立 MIS 技术精确处理。正向选择与发光面命中的反向 PDF
共用同一个缩放、求和顺序和接收面法线，避免叶内重要性破坏无偏 MIS。

两级树共用的 `LightNode` 为 32-byte ABI：质心和功率保留完整 f32，不能
改回 f16、固定范围、裁剪或丢弃远处驻留簇；render-origin 重定位后，world tree 可能在旧簇
退出驻留前暂时跨越很大的相对坐标。功率、方向、子节点和相对 RGB10 centroid 位于同一记录，
两个 reserved word 固定写零。路径状态、表面交互、BSDF、PDF、光源样本和采样维度是积分器
契约，调度层不得重新解释光传输数学。

实时积分器在首接口固定同时生成条件反射和条件折射，后续透明顶点从完整闭包随机选择一个
事件。guide 直接沿每条辐射分支实际选择的完整 f32 continuation 累积 PSR；不再构造规范
continuation 或独立 replay。遇到首个 solid-angle 表面前暂停 RR，建立 anchor 后恢复正常 RR；
运动、溢出、链上限和非法状态回退真实可见接口。
实体玻璃与水都按实际介质内路径长度吸收；阴影连接保持直线，只累计该线段上的光学厚度。
染色玻璃按纹理 alpha 将 `<= 0.5` 选为光滑界面、`> 0.5` 选为粗糙界面，吸收统一按
alpha 0.4 标定；普通玻璃由无色光滑主体和不透明粗糙漫反射边框组成。粗糙度来自 LabPBR，
缺失时使用用户设置的“默认粗糙度”。“无缝玻璃”默认开启，使普通玻璃边框按主体处理、
染色玻璃不再选择粗糙 texel，体积吸收与颜色标定不变；关闭后恢复纹理装饰分区。
离线从首顶点起使用完整闭包，不采用实时首面双分支或 guide。完整定义见
[透明渲染与实时重建](透明渲染与实时重建.md)。

## 重建与显示

DLSS RR 接收 noisy color、主/反射 motion、linear depth、normal/roughness 和
diffuse/specular albedo，并提交独立的 specular hit distance。Prime 不提供语义不真实的
Color Before Transparency；平滑透明反射 motion 来自反射分支 PSR 的上一帧 virtual
target。有限目标的首接口 TIR 将整条有界 discrete/PSR 链提升为虚拟主视图；NRD 处理主
历史、透明反射历史和太阳直射，输出再交给 FidelityFX FSR。重建 roughness 与实际闭包一致：
光滑玻璃和水为 0，不继承未参与 BSDF 的默认材质粗糙度。

NRD motion 使用非抖动 2.5D 约定 `old = new + MV`；FSR 复用 XY 并单独接收
reversed-infinite depth。图像诊断选择沿 runtime 到 Vulkan processor 的旁路传递，不进入
可序列化 frame plan，也不参与任何重建历史身份。

所有后端生成全分辨率线性 Rec.2020 HDR 后进入统一显示边界。自动曝光在 GPU 上完成直方图、
目标与时间适应，默认强度为 60%，正常路径不回读 CPU；最终曝光和固定的 Reinhard-Gamut 显示变换
只改变显示结果，不写回实时历史或离线累积。HDR 参考白默认使用 Windows 对当前屏幕查询的
SDR 白电平，也可按 nit 手动标定；它只改变物理亮度与 HDR shoulder 的可用余量，不移动 SDR
曲线的中灰或场景曝光。诊断 HUD 的 16-byte 曝光读回记录在主帧命令缓冲中，只在队列完成
回调发布，不增加独立提交或 GPU 等待。可选 HDR 输出延伸同一 Reinhard-Gamut shoulder，并通过线性 scRGB 交换链提交；能力检测、
原版 UI 合成和数值不变量见 [HDR 输出](HDR输出.md)。

## 材质与光照

缺少 PBR 数据时使用原版纹理和 biome tint，默认感知粗糙度为 0.90、介电 F0 为 0.04、
IOR 为 1.5。LabPBR 1.3 当前使用切线空间法线、光滑度/粗糙度、介电 F0、金属、次表面权重
和发光强度。法线 mip 保留归一化平均方向，并把分布宽度编码为等效 GGX 粗糙度后与材质
粗糙度合并；几何法线仍独立负责可见性、介质和射线原点。normal alpha 高度仅驱动互斥的
纹理几何位移模式。次表面权重仅用于明确的薄壁材质；厚材质忽略该输入并使用常规漫反射。
AO 和孔隙率尚未参与着色。

积分器、材质、光源和累积统一使用 D65 线性 Rec.2020；Minecraft 纹理由 Vulkan sRGB view
先解码到线性域再过滤，tint 在材质边界解码，随后统一转换。光源包括光谱大气、太阳、Gaia 星空
和由原版发光等级及纹理估计的方块面。NASA 星图资产只证明为 scene-linear RGB；来源 EXR
没有 chromaticities 属性，primaries 与 white point 未知，因此当前数值行为不被描述为 ACES
或来源保证的线性 sRGB。
太阳与星图共享由 Minecraft 日角、观测纬度和固定季节构造的天文帧。

太阳 aerial perspective 的局部可见性来自 RT 世界空间方向光深度 clipmap。缓存按相机移动
增量更新，并在 terrain cluster 替换后重追踪受影响区域；离线会话在开始累积前完成当前方向。
它只近似单方向太阳体积阴影，不表示任意天空可见性、局部灯光体积阴影或参与介质多次散射。
epipole 投影从现有 inverse view-projection 的三组 4×4 余子式直接构造 clip x/y/w，不再在
每个 aerial/组合 invocation 中执行完整 Gauss-Jordan 逆矩阵，也没有扩张 push-constant ABI。

sky、aerial 与 multi-scattering 的常量消光段统一计算
`length * (1-exp(-x))/x`，其中 `x=extinction*length`。`x<=0.05` 使用到四次项的解析级数，
其余使用指数式；这同时覆盖零消光极限，禁止用 `max(extinction, epsilon)` 伪造分母。

## 场景与资源

地形链分为四个边界：

- `render.runtime.terrain`：`TerrainStreamer` 的 desired/current、资源 epoch、worker 调度和上传；
- `render.scene.vanilla`：捕获 Minecraft region/assets，并通过原版 Section compiler 生成不可变
  几何事实；
- `render.terrain`：捕获值到 CPU mesh、OMM、发光分布和 light tree 的纯翻译；
- `render.vulkan.terrain`：用显式 update transaction 管理 staging、未发布替换资源、
  resident cluster、BLAS/TLAS 与 compaction。

Minecraft/Fabric 只在 `render.scene.vanilla` 边界被观察，并转换为 `CapturedSectionGeometry`、
`SpriteId` 和 `CapturedSprite`。一个对齐的 4×4×4 Section cluster 作为原子 generation 替换；
CPU mesh 可分段构建，但不会发布不完整 generation。详见
[区块簇场景翻译架构](区块簇场景翻译架构.md)。

动态场景在 `LevelRenderer.submitFeatures` 边界按帧捕获受支持的提交节点，包括实体、方块实体、
粒子、物品、移动方块、火焰、拴绳和文字。每帧结果先构造为不可变 `DynamicSceneFrame`，再原子
替换 `TerrainScene` 中独立于静态 cluster map 的单一动态 resident；空帧同样会移除上一帧
动态几何。实体与方块实体由 dispatcher scope 提供稳定 motion key，以前后帧对应顶点生成
运动向量。motion key 只有在本次提交确实经过 identity 提取且在一帧内唯一时才参与配对；
缺失 identity 或重复提交同一 identity 时，不按顺序猜测对应关系，受影响几何保留当前帧精确
顶点并使用零物体运动，同时记录兼容性诊断。这个降级只保证当前几何正确，不表示对应 Mod
已兼容。无法通用重放的 Fabric custom submit node、缺少可用 albedo 的材质和不受支持的拓扑
会被省略；blended 或 textureless 材质使用显式近似。两类情况都会记录兼容性诊断，且不会
复用可能已经过期的场景。

物品展示框沿上述动态实体路径进入光追场景。若 Minecraft 为展示框解析出的临时 block-state
model 没有任何 part，vanilla 适配层会按普通/发光以及有无地图四种状态恢复已预注册的原版
模型；已有模型、隐形展示框和专用 renderer 不会被该回退覆盖。

Prime 与原版 terrain 互斥驻留。启用 Prime 时释放原版 dispatcher、uber buffer 和 staging
资源；关闭时先完整退休 Prime renderer，再按原版上限重新建立 vanilla terrain。扩展视距
只用于集成服务器，远程连接和原版路径仍限制为 32。

`TraceBackend` 拥有共享 descriptor、BSDF LUT、星图和提交资源；实时与离线 renderer 各自
拥有 pipeline、wavefront 和分辨率相关资源。`TraceBindings` 提供 descriptor 就绪契约，
`SunShadowPipeline` 不持有整个 backend，基础 `VulkanContext` 也不依赖上层诊断实现。

renderer 在方块 atlas 可用后、进入世界前完成 bootstrap：建立实时与离线管线、当前窗口尺寸的
重建资源、尺寸无关的显示/曝光/HDR 管线，生成 atmosphere 静态 LUT，并上传 BSDF LUT、星图和
完整材质页面。shader/resource reload 在 apply 边界完成相同的可替换准备。正常第一帧不得再
承担这些一次性工作；窗口实际尺寸或用户设置随后变化时才允许显式重建相应尺寸资源。

地形静态 BLAS compaction 保留。它直接乘于 resident 地形规模，并非 renderer 生命周期常数；
查询、复制、地址替换与延迟退休仍由 `TerrainScene` 单一拥有。动态 BLAS/TLAS 固定逐帧重建，
不增加 dirty/refit 状态机。

## 状态发布

帧和资源都采用 prepare/accept：计划与候选资源先完整构造，`encoder.execute()` 正常返回
表示已被 Minecraft host submission 接受，此时才推进 Prime history、图像初始化和 resident
映射。execute 前失败执行 abandon；execute 后宿主失败则 runtime 进入 `FAILED` 并退休
renderer。旧 GPU 资源按 timeline 延迟销毁，热路径不调用 `vkDeviceWaitIdle`。

Java/Slang ABI、工作色彩空间和关键常量由 `shaders/abi.json` 统一声明并在构建时生成和验证。
更一般的依赖和状态规则见[架构与数据流](纯函数式架构.md)；生产 Shader 的依赖划分见
[生产 Shader 编译边界契约](生产Shader编译边界契约.md)。

## 诊断

设置界面提供三个互斥滑动视图：渲染器中间图像、DLSS RR 输入和 NRD 输入。每类可全屏查看
单图或查看不拉伸的方形分区总览，首格固定为降噪输出。“渲染诊断信息”以固定行报告活动路径、
内部/显示分辨率、完整计数与字节数、GPU 能力、曝光、TLAS/BLAS、面光源、light tree 和
compaction；不使用 k/M 数值缩写。

生产 shader 的零诊断成本、图像清理与历史隔离见
[生产 Shader 零诊断成本契约](生产Shader零诊断成本契约.md)；数值与着色器测试边界见
[着色器属性测试与数值诊断架构](着色器属性测试与数值诊断架构.md)。
