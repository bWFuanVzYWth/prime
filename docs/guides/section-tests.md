# Section 编译对拍与 CPU 基准契约

这是持续维护的测试设施。开发命令见 [CONTRIBUTING](../../CONTRIBUTING.md)，当前未实现的语义见 [原型缺口](../../PROTOTYPE_HACKS.md)。一次通过只证明所列输入和支持范围，不证明整个资源包、真实存档或第三方模组等价。

## 参照与输入

`adapters/section-tests` 是两个版本共用的测试源集，不进入 mod 发行 JAR。版本目录仅保留确有 API 差异的绑定。测试 JVM 在 Fabric preLaunch 中运行实际 Mixin/Indigo 和 Minecraft `SectionCompiler`，随后退出；不调用游戏 main，不创建窗口或 GPU。

每个场景使用相同的真实 `BlockState`、`PalettedContainer`、baked 模型与流体材质。Java 生产路由先生成资源和 section 源包，随后才执行参照编译，避免参照提前求值掩盖冷资源问题。场景按固定坐标顺序建立 palette，模型随机选择由真实位置种子决定。section halo、空段和实际缺失不能混为一谈。

当前资源是受控 baked 模型；使用中性光照、关闭 AO、带颜色场景使用实际原版 BlockTintSources、colormap、BiomeManager、BlockTintCache 和 ClientLevel 混合函数，输入为受控群系 palette；标签集显式为空。参照保留真实剔面、multipart、weighted、流体形状/UV、遮挡与支撑规则。不得为了通过测试，在期望端复制 Rust 的三角化算法或用近似替换实际编译器。完整资源烘焙、真实存档 biome/标签与更多颜色依赖、其他原版方块规则和存档回放仍需扩展，不允许把这些范围默认为已覆盖。

## 产物与比较

每个版本写入独立目录，场景包含 `.frame`、`.source`、`.expected`；增量场景另含编辑与重复通知的 frame/source。有颜色需求时另存 `.tint.requests` / `.tint`，以及按需的 `.biome.requests` / `.biome`，回放必须核对两个阶段的实际请求表后使用宿主结果。`.expected` 是实际 SectionCompiler 的 CPU 网格，经统一的 section-local quad 传输格式保存。保留整数 section 原点，不能先相加到全局 f32。`suite.properties` 核验测试格式、源协议和游戏版本，`cases.txt` 最后写入作为生成完成标记；生成失败不能复用旧完成标记。

Rust 回放生产源协议、调度、编译与发布。未改变语义的场景比较最终三角形多重集：允许三角形排列和同一三角形循环起点不同，但保留绕序、重复面和逐角属性。材质 ID/flags 必须整数相等；位置、UV、未照明 RGBA 的绝对误差上限为 `5e-6`，拒绝 NaN/Infinity。比较在 `f64 origin + f32 local` 上进行，不能让大世界坐标的 f32 舍入掩盖局部偏差。失败给出场景、三角形、属性、两侧数值与误差。增加误差容限需要独立数值证据，不能用放宽阈值消除几何错误。

闭合工作集的原生夹具显式把每帧格预算设为实际 section keys 覆盖的不同 4×4×4 cell 数，包括空 halo；不沿用游戏默认预算。源发布及每个基准样本都要求 `pending_cells=0`，避免只编译首个空格就记为完成。统一入口要求两版非空输入，并核验 Rust 对拍实际执行的用例；每轮测量同样重新生成并验证自身输入。

对明确的水/岩浆/群系水及大规模液体夹具，翻译会消除光栅背面、恢复已知内缩并裁掉占据区域，因此另外用双向采样的表面场 oracle 对拍。位置仍为5e-6，插值 UV/RGBA 为2e-5；静态 sprite 依据已知共享 atlas 身份映射回源 UV。仅明确的原版流体0.001内缩可规范化，移除区域须由宿主闭合 opaque 表面的独立射线占据证明或保留的 opaque 接触面解释。负例验证漏面、额外几何、错误UV/颜色必然失败。红石材质纠正按声明的cutout规则校验，其他场景不放宽严格多重集合比较。

宿主最终网格不能证明新增光学模型。Rust 独立区域/射线测试另检查半砖/活版门/竖向窄条、非仿射双层裁切、部分含水、跨三轴/负坐标/完整单元的唯一拥有者；无窗口 GPU 另验证两侧/覆盖、实际透射吸收、灯支持域/PDF、动画/mip与资源退休。语义变化与未变化源解释分开验收。

`section-oracle/cross-uv/` 独立保存实际游戏 JAR 中 `cross` / `tinted_cross` JSON、植物纹理经 CuboidModel/FaceBakery 烘焙后的字段参照。每模型的 `.quads` 为大端 count，随后按源 quad/顶点顺序保存 xyzuv 五个 f32；`.source` / `.frame` 经过生产 SectionSources 封包，`.properties` 核验版本与受控状态。单块使用无 offset 的 stone 状态绑定植物模型，tinted_cross 保留源 tint slot 并另提供受控白色 `.tint`；这不验证真实植物 offset 或群系色。

十字面正反采用不同对角线，合并后允许物理 primitive 数变化。原生回放用独立源绕序选侧，在原 `012 / 230` 三角形上求重心 UV，与编译产物的两侧分别比较，误差上限 `2e-6`；不放宽其他场景的三角形多重集比较。无窗口 GPU 测试另用同形源几何和非对称颜色/alpha 纹理，覆盖四个方向、两种主侧顺序及 opaque/cutout，参照只构建面向射线的原始源三角形以避开重合双面竞争。该测试验证 Bilateral 的选侧与 coverage 消费路径，实际宿主回放验证 CPU 配对；两者不等同于真实游戏截图验收。

除了独立完整编译，还验证同一上下文的编辑、面/棱/角依赖传播、空段、重复通知零重编译，以及活动范围与依赖范围的区别。颜色覆盖红石16级、茎秆8级、多 slot/缺失 slot/alpha、双高植物、群系混合0/2/7（整数滤波性质测试另覆盖0..7全部半径）、标准水和含水方块；纯群系变化验证不重新发送 section，结果仍等于完整原版重编译。基准的每一种编辑后状态必须也有完整参照；增量结果与完整参照比较。并行原版参照先与串行原版产物对拍，再用作耗时比较。可扩展负载通过各场景的 `.workload.properties` 保存首次请求数和编辑段数，回放检查实际工作量；旧夹具缺少该文件时只接受原有27请求/8编辑的契约。

`placement-oracle.bin` 另保存实际两版 JAR 的 `BlockState.getOffset/getSeed` 输出。遍历注册状态的声明组合，覆盖 XZ/XYZ、不同限幅、DoublePlant/Door 上下半、床的四朝向与头尾；坐标含负值、大值、i32端点及固定随机序列。Rust 对 f64 偏移位模式和 i64 种子逐项精确比较，包括 x 先 i32 wrapping 的哈希顺序。未知 lambda/方法覆写夹具只验证准备阶段不调用它们且明确标未知，不声称支持其数学。实际 SectionCompiler 另覆盖受控模型的标准偏移和 weighted 双高/床选择，保留既有几何误差阈值；这不等于完整资源包或游戏画面验收。

## 计时边界

基准使用独立的 release CPU native 库，不能测 debug 库，也不能覆盖正在运行的游戏 DLL。测试入口先生成并通过对拍，再在多轮独立 JVM 中测量，每轮再次对拍计时 JVM 自己生成的输入。失败的运行不能标记为基准通过。

两侧使用同样的只读 palette 输入；原版参照与 Rust 使用相同的配置线程数。原版测试池按完整 section 分任务，每个并行任务独占 builder；Rust 使用生产私有同步池及其真实任务粒度。原版测试池不是生产适配层的一部分。该比较包含实际 SectionCompiler 的光栅专属工作，不是算法指令数或游戏整体吞吐量的公平等价物。

记录 native 上下文首次发布、预热和每个正式样本（CSV 的 cold 指新上下文，不是整个 JVM/游戏冷启动），交替两侧测量次序。重复独立进程以观察堆布局/JIT/调度带来的波动，并分别保留两个编辑方向的分布；不能只选择较快的一轮。禁止删除离群值。负载覆盖首次发布、内部编辑、相同内容 dirty、无事件静止；密实体、阶梯地形、重复部件、液体和棋盘格默认编辑八段，可按水平边长扩展到大批量；密集着色体默认八段，支持独立水平边长，按实际工作集单独比较。着色体另测 biome 失效：交替群系输入，每次分别在两侧测量前清空实际宿主颜色缓存，缓存失效本身在计时之外；不让先测的一侧替另一侧预热颜色。固定区域批量编辑不等同于视距流送或实际移动尾延迟。

原版区间为 compile 到结果 release/builder clear。Prime 区间包括事件封包、FFM plan、响应封包、FFM accept，按需包含颜色批次与宿主源读取，覆盖 Rust 解码、展开、颜色回填、整理、发布和 CPU 退休 join。历史 CSV 字段 `tint_callback_ms` 现在表示 Java 颜色源准备总时间，包括字段读取；不能直接当成回调时间。`tint_queries` 汇总颜色源条目与 quart 请求页。native `tint_requests` 为源需求数，`tint_callbacks` 才是未知源实际回调次数；`biome_samples` 为需要重新求色的原始位置数，`biome_cached_samples` / `biome_hits` 分别为原始颜色和混合结果命中数。`biome_host_cells` / `biome_pages` 是实际读取的 quart 单元/页数，单位不同，不与位置命中数相加。`tint_pack` / `tint_decode` / `biome_plan` / `biome_source` / `biome_filter` 分列请求、解码、原始颜色需求规划、原生 zoom/源规划/求色和过滤；回填包含在 finalize。读取诊断、哈希、文件输出在计时之外。Java 分配及 GC 字段仅观察 Prime 区间的调用线程/进程 GC，不是 native 堆或原版工作池分配量。底层诊断以毫秒记录，细微阶段会受显示精度限制。

`biome-math-*.bin` 保存两版实际 BiomeManager、颜色修饰和资源色表的独立数学参照，覆盖不同 seed、负坐标、大坐标、climate 截断、全部修色、带 alpha 的覆盖色及短色表缺项；Rust 同时核对首次和缓存后的 zoom。`tint-sources.*` 对照红石全部强度、茎年龄、两种常量来源、waterParticles 的世界语义及未知有状态回调；未知回调必须恰好执行一次。已知原版场景的源准备若访问 `getBiome` / `getBlockTint` 则直接失败，并要求实际回调计数为0。这些检查不纳入性能计时。

着色负载另有 `reload` 模式：每个样本发送真实资源失效事件、重新建立宿主源字典并重发完整来源，原生颜色和 seed 选择缓存全部清空。它包括源准备、同步编译和完整冷着色，用于区分 `biome` 模式仍可复用的 seed 计算；不包含完整游戏资源加载或 GPU 重建。该模式统计的 compiled 包含来源窗口的空段，需与有色段数和三角形数一起解读。大小核平台应记录实际进程 affinity；若用固定性能核控制调度，原版与新旧 Prime 必须一致，不能与默认调度样本混合统计。

输出保存工具链、实际运行 JVM/GC/最大堆配置、系统/CPU 标识、工作区版本/补丁、未跟踪源码、native SHA256、线程数、全部 CSV、输入与结果哈希，以及 p50/p95/max 摘要。p95 使用 nearest-rank。优化优先比较大批量完整 `route` 的 p95 和吞吐量，并保留 p50、最大值、阶段时长和较慢场景；阶段 p95 不能相加当作全链路 p95。吞吐量按正式样本的实际编译段数/三角形数总和除以 `route` 总时间计算，不平均各样本速率，不把未编译的控制组计作完成工作。不同工作集分开汇总，着色/群系负载不与其他场景混合。CPU 测试不含游戏世界加载、GPU、AS 构建和呈现，没有输出分辨率，不能换算为 FPS；正式渲染性能仍按原生 1920×1080 的游戏验收契约执行。

## 扩展边界

新增规则先增加真实编译器参照与最小反例，再扩充路由字段、依赖失效和原生实现；性能改动使用同一输入复测。源准备、不可变编译输入、工作区和发布/退休副作用继续分离。以后扩展回调、SIMD、LOD 或编译缓存，都必须复用这些比较与计时入口；近似 LOD 应拥有独立语义，不能冒充原版等价路径。
