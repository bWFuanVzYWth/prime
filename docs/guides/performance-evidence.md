# 性能证据、实验保留与清理

稳定架构和接口契约进入对应 `docs/`；运行报告、失败方案、源快照、日志与捕获保存在 Git 忽略的 `artifacts/`。提炼时区分代码事实、数学证明、测量和推测，记录支持范围；不能把一次设备结果升级为所有场景的性能保证，也不要求稳定文档依赖某份本地报告才能读懂。

## 保留能够复核的证据

实验记录至少包含基线和候选提交、未提交差异、工具链、配置、输入身份、计时边界、全部正式样本及离群值、结果和未覆盖范围。端到端性能比较固定原生 1920×1080、场景、种子、画质与射线预算，分开 CPU/GPU、稳态/更新、Realtime/Offline。局部测试注明不含哪些路径；阶段 p95 不能相加，不同夹具的收益不能相乘当作整帧收益。

尚未定论、仍有探索空间的实验保留分支、方案和必要证据。单次变慢不足以判定整个方向淘汰；先确认实际执行版本和控制变量，区别实现问题与设计成本。需要复测的冻结版本保留 DLL、实际内嵌 shader、来源与启动配置，以及启动配置依赖的 Java classpath、资源和工作目录。只复制参数文件不构成自足快照；删除共享 runtime 会使多个历史版本同时失效。

已有原件的派生解包、反汇编和统计可以再生成，但删除前须确认原件仍在、工具与格式范围可复现，保留原件哈希和派生方法。捕获解码成功、CPU 数学对拍和编译通过分别证明不同事情，均不代替游戏正确性或稳态性能验收。Nsight 指标解释与私有格式边界见 [Nsight 手册](nsight.md)。

## 清理规则

清理必须限定在本次明确授权的目录。删除前解析最终绝对路径并验证仍在范围内，不跟随 junction/symlink 越界；先核对冻结启动配置的依赖，再移除缓存。嵌套 Git 工作树属于独立 checkout，移除时检查其状态并使用 Git/托管工作树生命周期，不能把它当普通缓存递归删除。

| 类别 | 处理 |
| --- | --- |
| `target`、Gradle/Python 等编译缓存 | 可重建；若冻结 classpath 或 native 路径仍引用，先保留依赖或建立并核验自足 runtime |
| 确定淘汰的候选执行产物 | 保留复盘结论和源码提交/必要差异，确认没有未提交工作及其他版本依赖后清理 |
| Section 大型 `.expected` 几何输出 | 由受维护夹具重新生成；可保留 source/frame、运行参数、输出哈希、审计和计时数据后删除，复跑使用新目录 |
| 输入、随机种子、时序、计时 CSV、原始捕获 | 影响复核；不能仅因体积大就当编译缓存，是否保留取决于结论状态与可再生成性 |
| 未定论实验、冻结对照和唯一证据 | 保留；成本或指标不利不等于已经失去探索价值 |

清理清单记录实际路径、类别、字节数、保留依赖和结果，放入本次 `artifacts` 报告。原报告中“所有生成物保留”等描述只代表当时状态；之后按清理清单核对，缺少的生成输出不得再算作刚完成的验证。清理本身不重新证明旧实验，也不改写旧测量。
