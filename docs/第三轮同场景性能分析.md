# 第三轮同场景性能分析

2026-09-06，完整实时 `3_*` 与实验 Lambert `lambert2_*`。用户确认同一 GPU、场景、视角和
分辨率；频率没有锁定证据。本文只分析捕获和当前源码，不修改渲染算法，也不恢复硬件压力测试。

## 数据口径

原始 CSV 位于 `C:/Users/linlin/Desktop/tmp`。本次两组可以比较同一场景下的热点结构；旧
`2_*` 和 `lambert_*` 的场景不同，只用于跟踪编译寄存器预算，不作前后 FPS 比较。

- `Samples` 是 PC 采样占比，不是 GPU 毫秒；不同捕获各自归一化，不能相除得到速度比。
- `# Reg` 是分配寄存器数，`Live Regs` 是编译器给出的存活峰值，二者不必相等。
  `# Warp` 是 shader 单独运行时的理论驻留上限，不是实测 occupancy。
- TopDown 的父函数包含子调用，不能逐层累加。下文函数采样注明 inclusive 或 Self；
  不通过汇总所有 Self 行重建阶段占比，因为部分叶子和共享代码采用不同表示。
- RT Live State 的调用点父行汇总多个 calling context；需逐个 context 看同时保留字节。
  这不是路径记录大小、payload 大小或寄存器数。
- LGSB 是等待 local/global/texture/surface 加载依赖，采样点可以是消费指令；不能单凭它
  认定显存带宽饱和或发生 spill。NOINST 表示取指等待，也不是指令缓存容量瓶颈的独立证明。

指标定义参见 [NVIDIA Shader Profiler 文档](https://docs.nvidia.com/nsight-graphics/UserGuide/shader-profiler.html)。
CSV 的 pipeline 复合表头在指令/停顿区存在错位，使用实际列和停顿名核对；TopDown 表头有
`###ERROR###`，只取明确的函数、位置、Live Regs 与 Total Samples 列。执行计数全零，不能
据此计算 SIMD 利用率。两组 pipeline 的 Samples 均校验为合计 100%。

## 峰值来自哪些生命周期重叠

### 完整 scatter：外层状态叠加 BSDF 临时量

`3_topdown.csv` 第 2252–2253、5944–5945 行分别对应两段 scatter 的
`primeAdvanceTransparentWavefrontRecord → primeIntegrateTransparentWavefrontSurface`，
inclusive Samples 为 1.94%、1.68%，均达到 126 live。更深处的 guided sample、foliage
初始化、介质边界 transmission 和介电多重散射补偿也在 124–126 附近。

当前 [advance](../shaders/transport/realtime/advance.slang) 在进入积分函数之前准备 PathState、
volume stack、branch result、guide 标志与可选 PSR 状态；
[transparent scatter](../shaders/transport/scatter/transparent.slang) 又在相同函数中完成
guide 决策、采样、BSDF 状态构造、RR 和路径更新。外层结果仍要在采样后写回，生命期与
BSDF 临时量重叠。函数里出现 126 不等于它独自需要 126，更不能把相邻函数峰值相加。

因此下一步应审查“已经有 guide 的普通续传”是否能用独立、窄的函数签名，明确去掉该路径
不需要的 PSR/guide 输入输出；仍需生成 guide 的路径保留完整状态。先在同一 entry 内做
源码特化，不新增队列或 GPU dispatch。BSDF 数学继续共享，不能为减少临时量删非零 lobe。
同一编译 shader 中的复杂分支即使执行少，也可能影响整个 shader 的寄存器分配预算。

### 首透明面：双 guide、两份候选和队列追加同时存活

`3_topdown.csv` 第 6 行透明初始化 inclusive 为 5.06%，峰值 121；整段 surface_split 峰值
122。单光照分支仍需要反射/折射两份候选和两套 guide，减少持久路径槽没有自动减少这些
临时量。[surface_split](../shaders/transport/realtime/surface_split.slang) 在候选采样后、
分支处理前执行透明 resolve 队列的 scalar 追加，此时大量候选和 guide 数据仍需保留。
该 scalar 追加的 Self 为 0.78% 全捕获（第 9 行）；surface_split 内 Sobol 的 Self 合计
1.30%（第 21、734 行）。阶段的 LGSB 为 68.93%，LGTHR 为 19.45%。

可先把“需要加入 resolve 队列”返回到 entry 的统一控制流位置，再复用现有 subgroup 追加；
不能直接在原来的非一致分支内换成 subgroup。这样同时减少逐 lane 原子操作和宽临时量跨
追加操作的存活。两套 guide 及有效候选、TIR、STBN 分支概率契约继续保留。

Sobol 值得单独审查，但这里不是已经替换成 STBN 的 NEE：完整 BSDF 仍使用
`primeSobolSample3D`。任何查表/位运算改写应逐位保持原随机映射，并实测寄存器与加载成本，
不能凭函数名或 Self 占比决定全面换随机序列。

### Any-hit：候选几何/UV 是共同成本，介质处理再抬高阴影峰值

完整 world any-hit 的 live 为 84，Lambert world/shadow 分别为 85/86；Lambert 不含完整
BSDF，仍未降到很低。TopDown 将这些峰值定位在 `primeCandidateSurface`、覆盖判断及 UV
链路。完整 nonopaque shadow 在同一候选链路达到 101，另有透明消光、法线和介质处理。

[candidate](../shaders/service/trace/candidate.slang) 的重复 UV 路径读取 BLAS 顶点并重建局部
位置/法线；其外围还需要 record、材质头和关系控制来处理覆盖及候选回退。阴影随后可能
再次为透射厚度求几何法线。这里的寄存器包含 any-hit 自己的控制状态和临时量；RT 调用者
的保存字节不能直接加到 any-hit 的 Live Regs 上。

当前实现已经先求 UV 再读纹理元数据，也已经延后加载 overlay 回退 record。后续若优化，
应审查常见关系类型能否源头特化，以及法线重算与跨 opacity 保存的实际取舍；不能重复提出
已经完成的窄加载，也不能为省寄存器丢精确身份、BLAS 位置、alpha 或透明介质语义。

前四项见 `3_rt_live.csv` 第 43、861、1985、1249 行；Lambert 见第 2 行。Lambert 保留的是
bounce，完整 direct 则保留 surface、throughput、介质和后续光源计算需要的数据。
[landing_direct](../shaders/transport/realtime/landing_direct.slang) 在太阳阴影之前就加载
area selection，并把 surface 留到太阳、方块光和最后 emission 全部完成。可考虑先窄读
selection 控制字段，area 详情延后到太阳返回后再取；只为 emission 保留的数据也应审查。
这会用少量重新加载交换跨调用保存，实际是否划算仍需计时，不能承诺一定降低帧时间。

tail 的 378 B context 包括约 92 B 前一 hit 返回值、48 B 分支结果/guide 相关状态，以及
path、medium 和光照临时量。源码归因可能指向合并的值，不能把这些数字当作对应 C/Slang
结构的 sizeof。tail 自身 3.61%，admission 1.35%，合计 4.95%；tail 的 NOINST 为 68.20%。
新渲染器按既定设计删 tail、12 次反弹截断有利于缩小实现范围；本轮没有改旧渲染器终止策略。

SER reorder 另有 108–196 B 的保存，多数 context 含 96–100 B 匿名编译器/hit-object 状态。
不能把它们全部归咎于应用路径记录。Lambert 4 B 阴影状态已经很窄，不是首要优化目标。

light-select 值得优先做低风险审查：两段合计 8.24%，LGSB 约 66–69%，且恰好跨过原 64
寄存器预算。[tree_select](../shaders/service/light/tree_select.slang) 仍以同一套宽参数承载
world/emitter 两级树，第一孩子的 metrics 与第二孩子的读取重叠。可试分开两个入口的
数据参数、复用相同概率数学，缩短各自地址/边界字段的寿命；不要为减少存活值撤掉已有的
两个独立控制读取预取。是否回到 64 以及是否更快均需产物和时间验证。

大气已经不再是 Lambert shade 中的旧高峰：当前 shade 最大 live 为 48，峰值出现在方向
采样、基构造和 RR 随机准备附近。完整捕获中 aerial + transmittance 预计算共 2.32%，
其中 aerial 自身仍有 120 live，但不再按每个表面展开。Lambert2 选中样本中没有对应
compute 行，不能据此认定整个渲染流程没有大气成本。现阶段不优先进一步牺牲大气质量。

## 下一轮建议与验收

优先检查 surface_split 的 scalar 追加和选灯 64 寄存器边界，再整理 scatter 中 guide 已完成
与未完成两条窄路径。这些候选有具体热点支撑，且可以先保持当前队列调度。Any-hit 的关系
特化和 direct 延后加载随后分别试验；继续暂停大阶段重排和 MSE 功能。

每项分别记录分配/live 寄存器、同一视角同内部 extent 的阶段及总 GPU 时间，另看 local
memory/spill 指标。寄存器下降而时间变差时不能按成功验收；相同画面还须覆盖透明运动、
双 guide、NRD 高光阴影及暗处深层反射。所有输入 CSV 保持原样，本轮只增加分析记录。
