# 区块簇场景翻译架构

Prime 以对齐的 `4×4×4` Section cluster 为地形替换单位。流送不依赖原版可见 Section、遮挡图
或原版 raster 编译队列；这些只代表栅格呈现，不能完整覆盖光追可见性和间接照明。

## 数据流与所有权

```text
TerrainStreamer（desired/current、调度、generation 与回压）
  ↓ render thread + resource epoch lease
VanillaClusterCompiler.capture（Minecraft 模型、atlas、region）
  ↓ 不透明 Capture
VanillaClusterCompiler.compile（worker lease）
  ↓ VanillaSceneInterpreter / VanillaSpriteResolver
CapturedSectionGeometry + CapturedSprite + CapturedCluster
  ↓ ClusterSceneTranslator（纯 CPU 翻译）
CpuClusterMesh / CompiledCluster
  ↓ TerrainStreamer 上传
TerrainScene + TerrainUpdateTransaction（staging、BLAS/TLAS、resident scene）
```

- `render.scene.vanilla` 是唯一观察 Minecraft 模型、`TextureAtlasSprite`、Mixin accessor 和
  `NativeImage` 的适配边界；
- `render.terrain` 只处理 Prime 值、CPU mesh、OMM、发光分布、light tree 和翻译算法；
- `render.runtime.terrain.TerrainStreamer` 单一拥有请求、generation、in-flight、取消与重排；
- `render.vulkan.terrain` 单一拥有 GPU staging、resident cluster、BLAS/TLAS 和 compaction；
  未发布替换资源由一次 update transaction 独占。

## Sprite 捕获契约

`VanillaSpriteResolver` 在每个 cluster 内用 `IdentityHashMap` 去重原版 sprite，并转换为：

- `SpriteId(namespace, path)`：稳定资源身份；
- `CapturedSprite`：`TextureId`、帧尺寸、动画事实和唯一帧序列；
- `SpritePixelView`：可选的只读 ARGB 像素借用。

`CapturedSprite.equals/hashCode` 只比较稳定逻辑身份、帧尺寸和帧事实，不比较原版对象身份或像素
adapter 身份。像素视图可以零拷贝借用 `NativeImage`，因此只允许在创建它的资源 generation
lease 内读取，禁止跨 cluster 或跨线程缓存。

像素不可用是显式数据状态：OMM 使用 unknown-opaque，发光重要性退化为 uniform，纹理体素
面保留标准 quad。非预期的布局、算术和编程错误仍 fail-fast，不作为 reload 降级吞掉。

静态、宽高均为二次幂、UV 映射与纹素网格 dyadic 对齐且设备等级足以解析全部纹素的 sprite
生成二值 OMM：8/16/32/64/128/256 分辨率分别使用对应微网格。铁链等非 dyadic UV 切片可额外
细分以减少 any-hit 面积，但跨 alpha 边界的微三角必须使用 four-state unknown-opaque，不得通过
增加细分等级近似成二值结果。普通 UV 三角按其覆盖的 mip 0 纹素包围盒保守分类；重复 UV 的
缝合区间也先保守展开后分类。动画或非二次幂帧只在全部候选纹素和帧一致时写入已知状态，
否则使用 unknown-opaque。cutout any-hit 固定读取 mip 0
精确纹素，与 CPU OMM 烘焙使用同一 alpha 阈值语义；ray-cone LOD 仍只影响命中后的材质着色。
宏面尺寸按 sprite 所需等级和设备上限共同收缩，不能再假设每个 tile 恒为 L4。

普通 primitive、OMM 和面光源共享 UQ0.16 sprite-local UV，`0xffff` 单独表示端点 1；二次幂
纹理在 32768 纹素以内可精确保留纹素边界，避免 FP16 坐标把铁链等窄切片量化拉宽。Minecraft
atlas UV 只允许在 vanilla 捕获边界出现。

## Reload 与异步任务

`ResourceEpochCoordinator` 以单调 generation 隔离 Minecraft 外部资源：

1. render 线程在 snapshot dispatch 前取得短 lease；
2. worker 排队期间不持有 lease，避免共享 executor 上的 reload 死锁；
3. worker 开始后重新获取同一 generation，并在 Section 编译、cluster 翻译和像素读取期间持有；
4. generation 已 retired 时返回显式 `CANCELLED`，不访问旧资源；
5. 完成队列使用 `SUCCESS`、`CANCELLED`、`FAILURE`，取消会释放 in-flight，并在 cluster 仍
   desired/current 时重排；失败保持 fail-fast，并携带失败阶段、Section 坐标和 cluster
   坐标进入统一 runtime 诊断，根异常链仍完整写入日志。

Prime 与 Minecraft 共用后台 work-stealing pool，但只向其中准入
`max(1, floor(Minecraft 最大后台线程数 × terrain.worker_percentage / 100))` 个地形任务，
默认比例为 50%；最终上限还要取 CPU 限额与构建工作集内存限额的较小值。运行时降低比例不
取消已在执行或等待上传的结果，只暂停新 snapshot 派发直至 outstanding 回落到新上限，完成
队列容量仍按最大安全 in-flight 分配，因此设置变化不会使已有 worker 无法发布结果。
普通视距流送在该上限内保留一个 admission；方块变更和全场景失效使用最高优先级并可立即
占用该名额，同一轮不会以低优先级请求回填。交互结果同样越过普通上传积压，但始终服从原有
in-flight、完成队列和 staging 内存上限。
同一 cluster 发布更新 generation 时会取消旧 worker；取消状态由 render thread 单写、对应 worker
单读，并在每个 Section 编译边界检查。旧任务因此不会继续完成整组 64 个 Section，也不能发布
部分结果；新 generation 仍等待旧 worker 正式退出后进入唯一 in-flight 槽。

reload 先 retire 当前 epoch，异步等待最后一个 reader 退出，再跨过 Minecraft preparation
barrier；apply 完整捕获并上传新纹理 generation，再安装新 epoch。只有 `TextureId`、normal/
optical availability、emission 或启用位移时的 height/material 像素改变才使对应 mesh 契约失效；
普通 normal/optical 像素替换不重建地形。异常和取消通过幂等 abort 重新开放资源，且 ticket
只影响创建它的 renderer。

## 原子替换与版本

一个 cluster 的 64 个 Section 一次捕获和翻译，普通几何作为一个逻辑替换提交。上传成功前
旧 resident cluster 继续可用；替换被 host 接受后才发布新 revision 并退休旧 GPU 资源。

desired window、dirty generation 和 worker result 必须匹配。跨线程方块通知在进入队列前先
映射为 4×4×4 Section cluster，同一 cluster 的多次通知只占一个槽。过期结果可以释放，但不得
覆盖更新的 cluster。世界切换、材质翻译契约变化和表面细节设置变更通过显式 generation 或
全场景 invalidation 收敛，不通过隐式共享对象状态传播。

几何位移仍只覆盖相机附近固定 3×3×3 cluster，以限制 TLAS instance 与追踪成本；跨 cluster
移动只枚举两个固定窗口至多 54 项的对称差，不扫描整个 resident 集合，也不引入长期 LRU、
hysteresis 或可见性 cache。跨 cluster `VoxelBlasPool` 只按不可变 GPU 内容共享仍被 resident
引用的 BLAS；最后一个引用退休即删除，不保留按路线增长的历史常驻集。

## 几何与材质边界

材质从捕获事实到闭包的完整单向契约见[统一材质 IR 与闭包](统一材质IR与闭包.md)。本页只
规定表面几何、关系和所有权，不允许 source-format 材质状态越过翻译边界。

- block、fluid 和 Fabric quad 都在 vanilla 边界转换为 `CapturedSectionGeometry.Surface`；
- 面合并仅在稳定 sprite、材质、朝向、UV 和双面语义相容时发生；
- Minecraft atlas、独立纹理和 LabPBR 只在资源边界转换为 renderer 生命周期稳定的 `TextureId`、
  sprite-local UV 与规范纹理通道；后续物理分页、常驻和 shader 契约见
  [纹理翻译架构](纹理翻译架构.md)；
- 表面细节模式在 worker snapshot 前解析：资源包法线只保留真实存在的 `_n` availability，
  无和几何位移模式清除 normal availability；几何位移单独消费 CPU height map，三者不共存；
- normal alpha 高度只驱动可选纹理体素 relief；关闭或缺少像素时沿用标准 quad；
- 动态方块实体与实体走动态场景路径，不并入持久 terrain cluster。

## 表面定义与关系翻译

Minecraft 模型常用两张相同或相差不到一个像素的面表达双层材质，例如草方块侧面的染色
覆盖、贴墙火焰、正反面纹理不同的薄片，以及相接的玻璃和流体。它们是模型语义，不应在
Prime 内继续解释成两张互相竞争的几何。CPU 翻译必须先把可合并的 authored quad 解析为
与 GPU ABI 无关的表面定义，再决定如何降低：

```text
ResolvedSurfacePatch
  geometry: CanonicalGeometry
  definition: SurfaceDefinition

SurfaceDefinition
  positiveSide: SurfaceSide
  negativeSide: SurfaceSide
  positiveMedium: MediumEndpoint
  negativeMedium: MediumEndpoint
  interfaceMode: InterfaceMode

SurfaceSide
  overlays: ordered SurfaceLayer[]
  substrate: optional MaterialBinding

SurfaceLayer
  material: MaterialBinding
  uv: UvMapping
  coverage: Coverage
```

canonical geometry 的 winding 永久由 negative side 指向 positive side；捕获的 authored normal
只允许在 CPU 翻译边界用于修正源顶点顺序，不进入 GPU primitive。CPU 语义中
禁止使用随观察方向变化的“当前/相邻材质”；命中后才依据正反面选择 side。overlay 与
substrate 是两种不同角色：按显式顺序测试 overlay coverage，全部未覆盖时才选择 substrate；
只有 substrate 的透射事件可以更新介质栈。几何法线、运动、介质方向和生命周期不随最终
选中的 layer 改变。

典型输入映射如下：

| authored 模型 | 规范表面定义 |
| --- | --- |
| 普通实心块 | 两侧同一 substrate，无介质端点 |
| 草方块侧面 | cutout 草色 overlay + 泥土 substrate |
| 静态贴墙火焰 | 空气侧 fire overlay + wall substrate；墙内侧只有 wall substrate |
| 正反纹理不同的薄片 | positive/negative side 各自独立材质与 UV |
| 玻璃 A 紧邻玻璃或冰 B | 单一 boundary，介质端点分别为 A/B |
| 同介质相接 | 无可见内部边界 |
| 分辨率以下的空气微缝 | 端点介质不变的 `BOUNDARY`，并标记可应用微缝外观 |
| 无法精确归并的可见壳层 | 保留原几何 |

解析顺序固定为：同模型反向面与内部接触、相邻 block/fluid/cluster halo、亚共面 patch 的
投影与裁剪、构造 `SurfaceDefinition`、不满足精确条件时保留原几何。关系解析必须满足：

- 一个物理 patch 只有一个 geometry owner；
- overlay 次序来自捕获的角色与稳定 provenance，不能只从浮点 epsilon 猜测；
- 参与归并的表面必须处于同一 motion/lifetime domain；静态 block fire 可并入静态墙面，
  实体或粒子火焰不得并入 terrain；
- 每一侧保留独立 UV、tint、动画、LabPBR 和 emission；
- 结果与输入枚举顺序无关、重复执行幂等，并在 cluster halo 两侧得到同一 owner；
- 任一前提无法证明时保守保留 authored geometry，不伪造材质关系。

### 重合几何规范化

进入 mesh builder 前，翻译器必须把能够由捕获事实证明为同一物理 patch 的 authored 面降为
单一 geometry owner，避免把材质关系留给深度竞争或求交顺序：

- 完全相同、同向且定义一致的重复提交只保留一个；完全相同的反向面按两侧材质降低为
  `SINGLE` 或 `BILATERAL`，发光面保留双面发光语义；
- 跨 owner 的精确共面 opaque/cutout 面按实际两侧降低为一个 `BILATERAL`，cutout 覆盖
  transmissive substrate 降为一个 `OVERLAY`；同 owner、同 UV 域而发光强度不同的 cutout 层
  由捕获的 emission 事实识别为 `OVERLAY`；
- 体素复合无法构造时仍发布一个带 relation 的平面，不能退化回两张共面 fallback geometry；
- 捕获事实已经证明相邻方块为完整碰撞体时，内部 fluid 面无条件删除。

亚共面只允许识别有明确来源的 vanilla 生成契约：模型 inner-face 的 `0.002 / 16` 偏移和
`FluidRenderer` 侧面的 `0.001` inset。比较只在这些已知常量附近容许 f32 ULP 舍入，并分别
选择外壳或精确方块边界作为规范几何；任意其他微小间距都必须保留。禁止用统一 world-space
epsilon、观察结果或材质相似度猜测重合关系。

反向 raster pair 的身份由顶点精确反序与相同 surface/UV/color 共同证明，不能再附加
“捕获 quad normal 必须互为反向”的条件。非平面四边形反序后，首三角形会切换到另一半平面，
两个派生 normal 本来就不必相反；以此拒绝配对会把两份完全重合几何送入 BLAS。最终 winding
与几何法线只以保留面的 f32 三角形为权威。

### GPU 降低与 ABI

GPU 不执行任意材质图。CPU 将表面定义特化为少量封闭关系：

| 关系 | 含义 |
| --- | --- |
| `SINGLE` | 普通单材质表面 |
| `OVERLAY` | 一层 coverage 材质覆盖 substrate |
| `BILATERAL` | 正反面使用独立材质/UV |
| `BOUNDARY` | 单几何连接两个实体介质 |

当前 packed relation 不提供任意 `OVERLAY_BOUNDARY` 组合。需要同时表达覆盖层与介质端点、
但不能烘焙为确定单材质的 authored geometry 会保守保留，不能静默丢弃 overlay 或 boundary。

`PrimitiveRecord` 保持 32 字节，原几何法线 word 为零值 `unused`；几何法线由 BLAS 的 f32
三角形顶点直接重建。`SectionRecord` 原 `mediumBoundaryAddress` 在相同 offset
泛化为 `surfaceRelationAddress`，Section 仍为 96 字节。普通 cluster primitive stream 的
地址为零且没有附加显存；存在特殊关系的 stream 使用每 primitive 一个 32-bit relation
reference，并只为非零引用保存按 kind 特化的稀疏 record。静态且可精确求值的关系允许在
CPU 烘焙；例如启用纹理 relief 时，精确共面的静态 overlay 继续进入确定性的复合烘焙。
其他不支持关系必须回退原几何，禁止在 shader 中引入无界 layer loop。

所有命中阶段共享同一纯解析流程：

```text
geometry hit
  -> determine positive/negative side
  -> resolve ordered overlay coverage
  -> select overlay / substrate / ignore
  -> evaluate selected material
  -> update medium only when transmitted substrate crosses a boundary
```

closest-hit、any-hit、shadow、OMM、emitter 提取以及实时/离线积分器必须消费同一选择语义。
积分器只接收扁平的 `SurfaceInteraction`；Prime 的关系解析位于 compact OpenPBR BSDF 之外，
材质特化通过明确的 adapter 边界进入紧凑状态。

### 当前落地状态

CPU `SurfaceDefinition`、通用 surface-relation sidecar、静态精确 `OVERLAY`、`BILATERAL`
和实体介质 `BOUNDARY` 已进入生产路径。微缝是 boundary 的受限外观标志，不是第五种表面
拓扑。fluid 接触由静态 cluster resolver
处理；同介质面消除和异介质单边界都使用稳定 owner。动态实体仍由独立逐帧 resident 路径
拥有 motion/lifetime，不强行并入静态 resolver。

## 维护门禁

修改捕获或翻译链时至少验证：

- stable sprite equality、动画帧与自定义 namespace/path；
- OMM、发光分布、双面折叠、merge 与体素采样；
- overlay coverage、正反面材质、介质端点与 relation sidecar 的可执行选择结果；
- 同向重复、反向双面、跨 owner 共面和已知 vanilla inset 各自有行为回归；任意薄壳不得被
  已知 inset 规则误归并；
- 亚共面投影不得越过原 patch，跨 motion/lifetime domain 必须回退原几何；
- 8×8、16×32、32/64/128/256 静态纹理保持二值 OMM，非二次幂和动画边界保持 unknown；
- missing pixel fallback 和 lease 释放后不再访问像素；
- 取消释放 in-flight、过期结果不发布、失败仍 fail-fast；
- `verifyArchitecture` 中纯 terrain 不依赖 Minecraft texture/model、Mixin 或 Vulkan。
