# 构建与验证

## 环境

- Minecraft 26.2、Fabric Loader 0.19.3、Fabric API 0.154.2+26.2 与 Loom 1.17.14；
- JDK 25（当前验证补丁版 25.0.4）；
- 完整的 Vulkan SDK 1.4.357.0，包含配套的 Slang
  `2026.13.1-1-g84792eb15`，以及 Windows SPIR-V Tools
  `v2026.3.rc1-0-gb707790a` 或 Linux SDK 中同版本的 `v2026.3.rc1-1-g9a49b088`。

Windows PowerShell 示例：

```powershell
$env:JAVA_HOME = 'C:\WorkSpace\_tools\temurin-25.0.4\jdk-25.0.4+7'
$env:VULKAN_SDK = 'C:\VulkanSDK\1.4.357.0'
$env:Path = "$env:JAVA_HOME\bin;$env:VULKAN_SDK\Bin;$env:Path"
.\gradlew.bat build --console=plain
```

`build` 编译 Java 和生产 Shader、运行 CPU 测试，并检查架构边界、Shader 依赖图、
RoboCute 参考一致性、Slang 工具链、ABI 和发行 JAR。它不执行需要 Vulkan 设备的
`shaderTest`。

`slangc`、`spirv-val` 和 `spirv-dis` 默认从 `VULKAN_SDK` 解析，并对 SDK 1.4.357.0 的配套
版本执行门禁。SPIR-V Tools 的 Windows 与 Linux SDK 使用同一正式版本但带不同打包提交，
两者按完整版本串分别锁定。工具链升级作为独立任务处理，不在普通功能修改中漂移版本。

每个 entry point 独立使用 Slang 直接 SPIR-V 后端，目标 profile 为 `glsl_460`、capability 为
`spirv_1_5`，并以 Vulkan 1.2 的 `spirv-val` 为最终门禁。生产和测试统一使用
`-matrix-layout-row-major` 与 `-fvk-use-gl-layout` 保持现有矩阵装饰和 raw-buffer std430 ABI。
默认浮点模式不启用全局 `precise` 或 `fast`；局部改变必须有性能或正确性依据，并完整通过数值、
分布、能量和 ABI 行为测试。生产 entry 的源码可见性、独立缓存输入和能力边界门禁遵守
[生产 Shader 编译边界契约](生产Shader编译边界契约.md)。

Gradle configuration cache 默认开启。未修改输入时，重复的 Java、Shader、ABI 和架构任务会
复用配置并保持 `UP-TO-DATE`；Shader、工具链或 ABI 输入变化仍会使对应验证重新执行。

首次完整 Shader 构建会按物理内存和逻辑处理器数量并行启动独立 `slangc` 进程。调度器为
Gradle/桌面保留 8–12 GiB，并按每个大型 wavefront 编译最多约 12 GiB 的实测提交量分配预算；
64 GiB、32 线程开发机当前默认使用 4 个进程。可用 `-PprimeSlangCompilerWorkers=N` 显式覆盖，
但该覆盖不再受内存门禁保护：大型 entry point 并发过高会产生数百 GiB 的总提交量。此设置
只影响首次构建，不引入 Shader 缓存，也不改变 SPIR-V 或游戏运行时热路径。

## 开发运行

```powershell
.\gradlew.bat runClient
```

默认开发配置使用 Vulkan 与 ZGC，以降低地形加载期间的 GC 停顿。发行 JAR 无法替
启动器选择 GC，外部启动器可自行添加 `-XX:+UseZGC`。选择 GC 不视为原生损坏引用的
修复；未确认根因的问题见 [FIXME](FIXME.md)。
当前开发配置未启用 Vulkan validation。验证 OpenGL 下 Prime 不接管渲染：

```powershell
.\gradlew.bat runClient -PprimeBackend=opengl
```

不要使用 Gradle `--args` 覆盖图形后端；Loom 会将它与已有参数合并。

## 验证任务

常用门禁：

```powershell
# CPU 测试
.\gradlew.bat test --rerun-tasks --console=plain

# 完整非 GPU 构建与发行检查
.\gradlew.bat build --console=plain

# 在 Vulkan compute 设备上运行真实 Slang 属性测试
.\gradlew.bat shaderTest --console=plain
```

主要任务：

- `test`：Java、状态机、codec、ABI 和数学性质；
- `:build-logic:test`：依赖域门禁自身的正反例，验证合法规模增长、间接越界和环；`build`
  通过 `check` 一并运行；
- `compileSlangShaders`：按 `shaders/programs.json` 为清单中的每个 artifact 聚合独立
  `@CacheableTask`，以 `-O2`、
  默认浮点模式、row-major/GL ABI 和直接 SPIR-V 后端生成实际 scalar/SER artifact；默认 `-g2`
  保留函数、源码和行映射，每个 artifact 独立运行 depfile 闭包核对与 `spirv-val`；
- `verifyShaderArchitecture`：检查 module/path、层级矩阵、禁止边、环、生产 include 禁令、
  manifest 完整性、诊断不可达性和阶段依赖边界；规模、fanout 与 artifact 失效集合位于
  `build/reports/prime-shaders/architecture.txt`；
- `verifySlangToolchain`：核对固定 Slang 版本，编译最小 Vulkan 1.2/SPIR-V 1.5 Shader，
  并验证 descriptor、push constant 与矩阵布局基线；
- `verifyGeneratedSlangAbi`：从 `shaders/abi.json` 生成 Slang 类型后，在最终 SPIR-V 中逐字段
  验证 offset、storage-buffer stride、push constant 和矩阵装饰；
- `compileSlangTestShaders`：以默认浮点模式和直接 SPIR-V 后端编译 Slang 属性测试；
- `verifySlangArtifactAbi`：一次反汇编检查生产 SPIR-V 的 payload location 与生产者/消费者
  类型兼容性、descriptor 闭包与数组容量、wavefront record stride，并保证 SER 产物只使用
  标准 EXT invocation-reorder 方言；成功报告可增量复用，位于
  `build/reports/prime-shaders/artifact-abi.txt`；
- `verifyRoboCuteReference`：核对锁定的第三方 RoboCute 版本与不可变 author overlay；
- `verifyArchitecture`：对已编译 class 运行 `jdeps`，检查六层允许矩阵、平台依赖和跨层 SCC，
  报告位于 `build/reports/prime-architecture/`；
- `verifyDistributionJar`：检查发行 JAR 的资源、许可、Shader 和 Windows 原生库；星图还需
  逐分片检查布局、压缩/解压字节数、SHA-256 与 gzip CRC，不能仅凭文件存在认定完整；
- `shaderTest`：在 Vulkan 设备上执行 Slang 数值、状态、分布、能量和 ABI 行为测试。

调度测试观察实际执行计划，检查队列消费/发布顺序、guide 临时区复用与配置边界，不锁定阶段
总数。GPU 用例检查窄接收面读取的逐位一致性、miss 对旧存储的隔离、secondary 控制转换，
以及真实 scalar/SER 追踪后的身份、命中后 miss、BLAS 压缩和唯一后继发布。源码规模、产物
体积与指令统计仅作诊断，不代替行为测试或 GPU 帧时间测量。

Windows x86-64 测试会实际加载 NRD、FidelityFX 和 DLSS RR 桥接库并验证 ABI。其他平台
跳过 Windows native 执行，但仍编译 Java/Shader 并检查 JAR。

星空专项验证：`shaderTest --tests '*Starmap*'` 检查完整 BC6H mip 链、分数 LOD、亚像素
移动的滤波能量和覆盖率合成；`python -m unittest discover -s src/test/python -p test_starmap_mips.py`
检查球面降采样的常量、总能量和分块边界，需要 NumPy、OpenEXR。真实 RTX/NGX 与生产
合成 pass 的移动、抖动和 reset 验证见 [DLSS RR bridge](../native/dlss_rr/README.md)。

## Shader 调试

生产 SPIR-V 默认使用 Slang `-g2` 保留符号、源码和行映射；非语义调试信息不改变执行结果，
但会增大 SPIR-V 并增加编译器与驱动处理调试信息的时间。只在无需分析的专项构建中临时降为
`-g1`：

```powershell
.\gradlew.bat compileSlangShaders --rerun-tasks -PprimeShaderFullDebug=false
```

### Nsight Graphics 抓帧

需要从 Nsight Graphics GUI 启动开发客户端时，先运行正式构建任务：

```powershell
.\gradlew.bat prepareNsightCapture --console=plain
```

该任务构建 `clientClasses`、生成 Loom 启动配置和参数文件，并验证生产 SPIR-V 确实包含 Slang
标准 `NonSemantic.Shader.DebugInfo.100` 调试信息。成功后打开
`build/reports/prime-nsight/launch.txt`，将其中的 Executable、Working directory 和
Command-line arguments 分别填入 Nsight Graphics。任务要求 `primeShaderFullDebug=true`，
不会接受只含 `-g1` 信息的专项构建。

## CI

GitHub Actions 在 Ubuntu 24.04、JDK 25、完整 Vulkan SDK 1.4.357.0 和 Mesa Lavapipe 上运行：

```text
clean build shaderTest
```

CI 保存失败测试报告并上传构建生成的 JAR。
