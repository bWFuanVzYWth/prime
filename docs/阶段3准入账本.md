## 当前结论

阶段编号不再作为实施门槛。允许把规范、正确性修复、测试、布局和性能改造合并为同一批次，
只要每个数据族仍有明确的不变量、可执行 oracle 和回退边界。

尚未建立误差证明的 transport 连续量不得借组合改动压窄；对它们的优化仍以当前精度和语义
为不变量。发现现存越界、错误生命周期或错误转换 owner 时，优先在同批改动中修复并补门禁。

## 可立即组合的工作

1. **Wavefront 存活期与物理布局**

   以 phase-specific typed view 证明最后消费者，再缩短 live range、拆分宽 record、减少按像素常驻字节。
   可在 SoA/AoS/混合中选择，但不改变数值精度、事件映射或 history owner。

2. **材质表和命中热路径**

   利用现有全局 MaterialId 继续移除 triangle 重复事实、收窄 companion data 并减少无关读取。
   保留合并读取能力，不强制整项加载，不把完整 MaterialRecord 带入路径状态。

3. **NVIDIA 坐标与多余 pass**

   将 top-left 规范前移到最近 producer，删除 Streamline 的全屏 Y flip/重打包，NRD/FSR adapter
   显式承担兼容转换。这同时是正确性收尾和明确的性能收益。

4. **资源存储与 alias**

   删除未启用 backend 的 targets，按已证明的 last-read 复用图像/buffer，审计 starmap、固定表和
   临时 upload 的真实使用通道。所有 alias 都必须通过 resize、backend switch 和 debug-view 生命周期测试。

## 改动门禁

每个任务在开始前必须写明：数据 semantic，保持不变的精度/拓扑/身份，变化的 physical encoding/lifetime，
预期减少的字节、访存、pass 或 live range，以及行为 oracle 和 GPU 测量点。

验收至少包含：

- 原有 Java/artifact/Shader/ray tracing/native 门禁不回退；
- ABI、Shader 编译闭包、非法输入和资源生命周期受测；
- 重构前后的行为或数学结果等价；有损改动单独按误差合同准入；
- 对寄存器、cache、occupancy 或 GPU 时间的判断使用 Nsight/逐 pass 数据，不用总 FPS 猜测；
- 生产 Minecraft 画面与 reload、resize、backend switch 在需要时由用户做最终实机确认。

## 最近完成的结构切片

- surface 跨 dispatch 存储共享 96 B exact core；realtime 只追加 4 B texture LOD。
- realtime scratch 从 320 降到 296 B/pixel，4K 容量减少 189.8 MiB。
- offline stage 从错误声明的 112 B 改为 `96 B surface + 12 B light = 108 B`；原布局实际需要
  120 B，会侵入 queue command/indices。4K 容量再减少 31.6 MiB，并由 ABI 公式与 GPU round-trip
  性质测试锁定不重叠边界。
- offline path 将两项 exact MediumId 和 IOR/count/active/bounce/flags 合并，同时移除两个 padding
  字；所有连续量仍逐位 f32，stride 从 144 B 降到 128 B，4K 容量减少 126.6 MiB。
- realtime output/branch resolve 不再物化完整 112 B transport；tail admission 直接读取 control，
  仅在实际执行 roulette 时读取 throughput/etaScale，并只回写 reweighted throughput。ABI 与随机
  映射不变，tail-admission 生产闭包从 40 个文件降到 25 个；SPIR-V 仍按 16 B 向量 load，后续
  带宽收益以 pass 计时为准，不按源码字段数推算。
- fixed/landing light-select 只读取 direction、bounce 和 volume 所在的 4 个向量，跨阶段读取从
  112 B 降到 64 B，生产闭包分别从 86/84 个文件降到 76/74 个。detached-guide 每次迭代只读取
  owner 的 control/PSR 所需 3 个向量（48 B），终止和续接仅回写对应 lane；其闭包从 112 降到
  107 个文件。landing continuation 同样只读写两个 control 向量。SPIR-V member access 已核对，
  transport ABI、随机映射、精度和 buffer 生命周期均未改变；Minecraft 实机验证通过并观察到
  轻微性能回升，具体幅度留待逐 pass 测量。
- realtime delta-walk 不再为下一次 transition 预读完整 transport：首次 active 判定只读取 control，
  每轮 trace 后仅加载一次 112 B record，额外 transition 因此少一次整记录读取。chain-limit、guide
  detach/disable 改为局部 lane 写，已驻留的 guide owner 直接复用，不再重新加载整记录；fixed
  bridge 同时删除重复 control 读取。delta-walk 生产闭包源码减少约 6.5 KiB，行为与 ABI 不变。
- fixed/landing/visible direct 使用 80 B phase state，只读取 direction、throughput、bounce/control 和
  volume；origin、previous event、source identity 与 eta 不进入 direct live range。medium attenuation API
  直接约束为修改 throughput，不再借完整 `PathState` 传递。transport storage 与 NRD direct
  accumulation 已拆为独立叶模块，使三套 direct 闭包各减少约 24–25 KiB，并同时缩小 scatter、
  surface-split、delta-walk 与 tail 的无关源码闭包；SPIR-V 只访问 transport 成员 1–5。
- primary prefix 不再在 camera trace 发布随后会被 surface split 整体替换的 144 B path。visible direct
  与 surface split 从 pixel、camera sample 和相机水体标志重建逐位相同的初始 path/medium；visible
  direct 成为 diffuse、specular、sun 和 penumbra 的唯一初始生产者，其余 guide/output 推迟到 split。
  每像素因此删除一次 144 B path 写、surface split 的 144 B path 读、visible
  direct 的 80 B path 读，以及命中像素 5 个无条件、2 个 SH 条件下的死 image 写；miss 像素的
  signal 初始化全部取消。产物测试要求 camera trace 与 visible direct 的 SPIR-V 不含 path
  descriptor、split 仍拥有该 descriptor；当前闭包分别为
  camera `40/178661`、visible direct `122/470479`、surface split `160/608540`（files/bytes）。持久容量、
  相机采样、随机映射、介质吸收、guide 精度及路径 ABI 均未改变。
- detached-guide 的 40 B/pixel 临时记录与随后 landing light-select 的两份 12 B staged-light
  记录具有严格不重叠的 phase lifetime，现共享同一 40 B/pixel scratch 区。realtime scratch 从
  296 降到 272 B/pixel，总 backing 从 624 降到 600 B/pixel，4K 容量再减少约 189.8 MiB；
  guide/光源字段、队列容量、dispatch 顺序和同步不变，ABI 生成器按
  `32 + 2 * 100 + max(40, 2 * 12)` 锁定物理边界。

## 已登记延后

- `translationBenchmark` extreme fixture 存在约 0.82 ms / 1.6 ms 两簇结果，在排除 JIT/系统负载前不设阈值。
- 主观透明材质、极暗亮度和重建稳定性只在数值/图像 oracle 无法判定时请用户确认。
- RR+FG 运动透射界面在需要支持前保持 invalid motion，不为未验证场景预留持久图像。
- starmap 紧凑格式与离线转码按维护者要求延后；当前固定资产和运行时路径保持不变。
