## 可立即开始的阶段 3 工作

1. **Wavefront 存活期与物理布局**

   以 phase-specific typed view 证明最后消费者，再缩短 live range、拆分宽 record、减少按像素常驻字节。
   可在 SoA/AoS/混合中选择，但不改变数值精度、事件映射或 history owner。

2. **材质表和命中热路径**

   利用现有全局 MaterialId 继续移除 triangle 重复事实、收窄 companion data 并减少无关读取。
   保留合并读取能力，不强制整项加载，不把完整 MaterialRecord 带入路径状态。

3. **NVIDIA 坐标与多余 pass**

   将 top-left 规范前移到最近 producer，删除 Streamline 的全屏 Y flip/重打包，NRD/FSR adapter
   显式承担兼容转换。这是尚未完成的阶段 2 正确性收尾，同时也是明确的阶段 3 性能收益。

4. **资源存储与 alias**

   删除未启用 backend 的 targets，按已证明的 last-read 复用图像/buffer，审计 starmap、固定表和
   临时 upload 的真实使用通道。所有 alias 都必须通过 resize、backend switch 和 debug-view 生命周期测试。

## 当前测量摘要

2026-09-01 的一次 RTX 4090、DLSS RR Performance 随机世界跑图仅用于决策边界，不是性能门槛：

| 观察 | 结果 | 决策 |
| --- | ---: | --- |
| unique BLAS triangles | 69,939,362 | triangle/emitter 身份保持 u32；按 triangle 的每字节都很重要 |
| MaterialId / MediumId / TintId | 939 / 21 / 3,087 | u16 安全；全局表远小于 triangle 数 |
| material core active / reserved | 7,520 B / 512 KiB | 固定 dense 一跳表开销可控 |
| relation source / GPU | 493,761,604 / 240,748,544 B | tail-only 3/7-word 布局有实际显存收益 |
| tint surface references | 50,372,269 个常量，0 个变化 | 当前常量 sample table 正确；保留 mod sparse path |
| active tint samples | 3,087 项，24,696 B | 8 B 全局 sample 合理；不预展开 3×3 operator |
| visible motion / view-Z max | 1,477.33 px / 47,654.42 blocks | `RG16F` motion 和 FP16 depth 不具备全域精度 |
| dynamic half projected error | 0.1765 px max | previous-position/dynamic motion 保持 f32 |
| raw hit distance saturated | 25,554,051 samples | 不用当前 half 观察图推导 path distance 可压窄 |

测量默认关闭且只输出聚合值。临时采集时使用：

```powershell
$env:JAVA_TOOL_OPTIONS="-Dprime.renderer.measure=true -Dprime.renderer.measure.intervalFrames=120"
.\gradlew.bat runClient
```

结果位于 `${gameDir}/prime-renderer-measurements/latest.json`，新运行会覆盖旧文件。样本可随时重采，不作长期测试资源。

## 阶段 3 任务门禁

每个任务在开始前必须写明：数据 semantic，保持不变的精度/拓扑/身份，变化的 physical encoding/lifetime，
预期减少的字节、访存、pass 或 live range，以及行为 oracle 和 GPU 测量点。

验收至少包含：

- 原有 Java/artifact/Shader/ray tracing/native 门禁不回退；
- ABI、Shader 编译闭包、非法输入和资源生命周期受测；
- 重构前后的行为或数学结果等价；有损改动单独按误差合同准入；
- 对寄存器、cache、occupancy 或 GPU 时间的判断使用 Nsight/逐 pass 数据，不用总 FPS 猜测；
- 生产 Minecraft 画面与 reload、resize、backend switch 在需要时由用户做最终实机确认。

## 已登记延后

- `translationBenchmark` extreme fixture 存在约 0.82 ms / 1.6 ms 两簇结果，在排除 JIT/系统负载前不设阈值。
- 主观透明材质、极暗亮度和重建稳定性只在数值/图像 oracle 无法判定时请用户确认。
- RR+FG 运动透射界面在需要支持前保持 invalid motion，不为未验证场景预留持久图像。
