# 阶段 3 准入账本

本文记录阶段 2 中可以由契约、自动测试和测量直接决定的事项。只有需要主观画质判断、
Nsight 管理员权限或现有证据不足的项目才延后给阶段 3 决策；不得用尚未稳定的性能数据反推
精度或语义。

## 自动准入原则

- 精确身份、离散分类和拓扑事实必须保持整数或枚举语义；样本高水位只能决定当前物理编码，
  不能把逻辑身份上限改成样本上限。
- 连续量只有在全域性质测试或真实样本加解析误差上界同时证明误差不可见时才能收缩。
- 纹理源码域、页面布局、transport 数值和坐标分别测量，不能用一种数据的分布替另一种做决定。
- 测量格式只保存聚合值，不保存世界坐标、玩家身份或纹理像素；它不是长期兼容的生产格式。
- 任一迁移必须先有旧路径 oracle、误差门限和资源/时间基线，再切换生产消费者。

## 可重复运行时采集

运行时采集默认完全关闭。显式开启后，渲染线程每隔固定帧数采样 VMA，并将阶段 2 聚合值
原子更新到 `run/prime-renderer-measurements/latest.json`：

```powershell
$env:JAVA_TOOL_OPTIONS = "-Dprime.renderer.measure=true -Dprime.renderer.measure.intervalFrames=240"
.\gradlew.bat runClient '--args=--quickPlaySingleplayer 新的世界'
```

`prime.renderer.measure.intervalFrames` 的合法范围是 1–3600，默认 120。关闭开关时不会查询 game
目录、扫描源像素或访问文件系统。采集器只由 `VulkanRenderer` 的渲染线程拥有，不增加锁域。
目前记录：

- atlas、mip、TextureId 高水位与空洞、动画、最大 sprite/padding；
- 当前 block atlas 的 RGBA8 mip 理论字节；该值属于 Mojang 图像，不计入 Prime VMA；
- normal/optical 源数量、texel、帧数、各字节通道码域；
- 翻译后普通图元、surface relation、area-light emitter 与实例化 voxel 的精确
  `(TextureId, packedTint)` 集合和引用高水位；动态纹理与 baked material 单独计数；
- 将实际使用的纹理/tint 集合与 source catalog 的逐纹理 mip texel footprint 连接，报告预合成
  tint variant 的数量、动画数量、texel/`RGBA16F` 字节和相对单纹理 canonical catalog 的膨胀；
- 页面数、mip 总字节、基础层面积、占用矩形和 ABI 坐标高水位；
- MediumId renderer-lifetime 分配量与高水位；
- MaterialId renderer-lifetime 分配量、高水位与 u16 剩余容量，以及由旧 primitive/relation/emitter/
  voxel 数据独立恢复出的材质候选 key 和引用规模；
- 迁移期离散 TintId 分配量与高水位；该统计仅用于解释旧 operator 试切片，后续由四顶点/连续
  tint field 数量、RGBA16F 字节和复用率替代；
- TLAS、唯一/实例化三角形、area light 和 light-tree 规模；
- render/display extent、重建 backend/quality、相机单帧位移峰值；
- VMA block/allocation 与 heap usage 的采样峰值。
- 生产帧 `VisibleMotionUv` 与 `LinearViewZ` 的 GPU 极值、非有限/无效/天空/越界计数和两倍频程
  对数分位；`prime.renderer.measure.gpuIntervalFrames` 控制采样间隔（1–3600，默认 120），
  history reset 帧会优先采样。GPU reduction 与异步回读只在总开关开启时创建。
- ray resolve 完成、backend adapter 改写前的 noisy diffuse/specular radiance、surface normal、
  roughness、diffuse/specular albedo 与两路 hit distance；记录非法值、极值、饱和计数和固定桶分位，
  不从 frame 结束后的 wavefront 残留记录推测仍存活的 path 状态。
- 动态场景当前/上一帧顶点位移、binary16 round-trip 误差，以及通过 clip-W 和扩展视锥筛选后的
  投影像素误差；只聚合计数与极值，不保存实体、玩家或世界坐标。

聚合文件会被新运行覆盖。需要对比时复制到 `build/reports/renderer-data/world-samples/`；该目录
属于一次性本机报告，不进入版本库。

### 全局去重与查表层级现状

目标层级已锁定为 renderer-generation 全局 dense table，不采用 section/cluster-local material
palette。GPU triangle 以 u16 `MaterialId` 一跳寻址固定 schema；每个 wavefront 阶段按需窄加载，
不得被迫整份加载或把完整材质状态延长到后续阶段，同时保留需要多个事实时的合并加载能力。
具体采用 AoS、SoA 或混合布局由 load、合并访问、寄存器和 path-state 测量决定。冷 companion data
最多一次条件读取，不使用变长编码、hash probing 或指针链。
`TextureId` 是全局 material key 的首要组成，只有确实改变语义的 medium/recipe/coverage/source
facts 扩展该 key；section 身份不得进入 key。常规 terrain 以 `MaterialId`、exact orientation、由
命中得到的 world position 和连续 tint 推导其余状态，例外须具名且保持固定访问上界。

当前实现中，canonical texture catalog/page 已全局拥有；`OpacityMicromapPool` 已按 immutable block
content 在所有 BLAS 间共享物理 micromap storage，并只保留 BLAS-local triangle remap；
`VoxelBlasPool` 仅对有稳定完整内容键的 texture-voxel geometry 做共享。普通 terrain BLAS 保持
cluster 唯一，符合随机世界几乎无整 BLAS 重复的假设。仍需迁移的明显重复是：当前 32 B primitive
内联 texture/medium/recipe/control，surface relation 复制 secondary material primitive，以及
`EmissionDistribution` build cache 目前只覆盖单次 cluster translation、没有 generation-global
唯一化。

`MaterialTableCandidate` 在 `prime.renderer.measure=true` 时从旧 primitive、surface relation、emitter 和
immutable voxel mesh 独立恢复 exact key。key 由 u16 `TextureId`、exact medium identity 和去除
tangent handedness/front-face-only 后的 semantic control 组成；tint、world position 和 orientation
不会制造材质变体。`latest.json.materialTableCandidate` 报告 observed unique count、maximum resident
references、relation/emitter/voxel 引用和暂未纳入的 dynamic/baked 引用。

一轮 4,812 帧、3840×2054 display、DLSS RR Performance 的随机世界跑图得到 671 个 exact key；
同时驻留候选引用峰值为 22,217,493，其中静态 surface 20,010,331、relation 1,837,910、emitter
369,252，另有 816 个 dynamic 引用明确排除。相对 671 个 key，每个材质平均对应约 33,111 个驻留
引用；材质相对实际 texture 仅产生少量语义扩展。这证明 generation-global table 能消除数量级重复，
而 u16 仍剩 64,864 个可分配 ID；数据不支持 cluster-local palette 或按 triangle 内联完整材质状态。

identity carrier 迁移后的独立运行覆盖 2,281 帧和 31,425,734 个驻留引用，实际 registry 与候选
oracle 均得到 705 个 renderer-lifetime ID，高水位完全一致，u16 尚余 64,830 个 ID；画面无变化，
日志无 Prime/Vulkan validation 或资源生命周期错误。这同时验证了 primary、relation、emitter-backed
primitive 和当前世界切换路径没有漏分配或额外制造 key。

基于该结果，`TerrainScene` 已拥有 renderer-lifetime dense `MaterialId` registry。0 专用于尚未纳入表的
dynamic/baked 路径，静态 primary、secondary relation、boundary relation、emitter 和 immutable voxel
均在上传边界解析为非零 ID；ID 不复用，超过 u16 容量立即失败。每个 cluster 只缓存 local facts 到
global ID 的解析结果，避免逐 triangle 重做 HashMap/key 分配；该缓存不是局部材质表，也不复制记录。
`PrimitiveRecord` 原 word 4 现在以高 16 bits 保存 `MaterialId`、低 16 bits 保存 `MediumId`，stride
仍为 32 B。closest-hit、shadow any-hit 和 relation 只通过具名 accessor 窄读所需 ID。

身份 carrier 的独立运行已经验证。其后的第一条 GPU material core lane 固定为每 ID 4 B：低 16 bits
保存 `TextureId`，高 16 bits 保存 recipe/semantic control。u16 全域物理容量为 262,144 B；buffer
device-local 且生命周期固定，上传只复制当前 dense 高水位前缀。静态 primary、secondary relation、
boundary、emitter-backed 和 immutable voxel primitive 的非零 `MaterialId` 已通过一次 32-bit 窄读取
解析 `TextureId`；dynamic/baked 的 ID 0 明确回退旧来源。closest-hit 将解析后的 `TextureId` 同时
用于采样和 ray-cone LOD，不再重复查表；emitter-backed primitive 也不再为纹理身份追逐 light
record 指针。

这不是要求加载完整 `MaterialRecord` 的 AoS。一个 core word 只组合高频 exact facts，允许需要两项
事实的阶段一次读取，也允许只取其中一个 field；冷参数和用途专属 companion data 继续分离并按需
读取。recipe control 目前只被编码和 ABI 门禁验证，尚未切换生产消费者：overlay 的 recipe override
必须先变成显式语义，不能用 primary material 的 core control 覆盖。该切片也没有批准 medium 参数表、
连续材质参数或新的有损编码。

GPU lookup 的独立运行覆盖 5,165 帧、两次资源重载和 43,264,870 个最大驻留候选引用。实际 registry
与独立 oracle 均得到 765 个 key，高水位 765；`activeCoreBytes=3064`，精确等于 `(765 + 1) * 4`，
`reservedCoreBytes=262144`。画面无变化，日志无 Prime/Vulkan validation 或资源生命周期错误。这
验证了固定 table 生命周期、dense prefix 更新和当前 TextureId consumer；后续仍需以 Shader load、
寄存器、cache 和阶段生命周期测量决定 AoS/SoA/混合 companion 布局，不能把当前 4 B core lane
外推为完整 material schema。

用户侧可在不启用 replay 的情况下采样：

```powershell
$env:JAVA_TOOL_OPTIONS="-Dprime.renderer.measure=true -Dprime.renderer.measure.intervalFrames=120"
.\gradlew.bat runClient
```

结果写入 `${gameDir}/prime-renderer-measurements/latest.json`。迁移后的验收要求 `materialIds` 的
assigned/high-water 与 `materialTableCandidate` 的非排除 exact key 一致；`activeCoreBytes` 等于
`(highWaterId + 1) * 4`，`reservedCoreBytes` 固定为 262,144，dynamic/baked 保持 ID 0。当前运行只
验证全局表覆盖率、生命周期和画面等价，不用于比较最终材质表性能。

`RayConeParameters` 是首个不依赖主观画质或场景分布的安全收缩：上层一直保留 semantic f32，
binary16x2 只存在于现有 4-byte Vulkan push lane。producer 生成的 spread 与 mip bias 在构造时必须
证明打包导致的最终 unclamped LOD 绝对误差 `<= 1/512 mip`；下溢、上溢和误差超限会在 dispatch
前失败。五档 production quality、offline native 与历史 push bits 均有行为门禁，Shader 继续用 f32
计算 distance/incidence/UV density/log2 和最终 LOD。这批准的是用途专属 ray-cone ABI，不是通用
transport FP16。

### 连续 tint 与资源生命周期

离散 RGB8 `TintId`/3×3 operator 试切片暴露了两个错误假设，因此不再是批准的目标编码。第一，
`PrimitiveRecord` 中的 RGBA8 物理字采用 R 位于 bits 0..7 的 little-lane 顺序，试切片曾按
`0xRRGGBB` 解码并交换红蓝；非对称 biome tint 回归已覆盖该局部错误。第二，也是架构上的主要
问题，捕获层能够保存四个顶点颜色，但翻译层当前通过 `averageColor()` 把它们降成单个 RGB8，
无法表达资源包 colormap、biome blend、mod provider、顶点插值和 alpha。

阶段 2 的目标现锁定为与 albedo binding 关联的 `RGBA16F` 连续 tint field。Tint sample 在上游完成
EOTF，保留四顶点/采样过渡；material adapter 必须执行与 `M * (base * tint)` 等价的色域转换。
若仍使用 ID，它只可作为连续 field 的无损地址，不能把 tint 重新解释成离散材质身份。非均匀 tint
在证明保持同一插值场以前不得进入会改变顶点域的 rectangle merge。

扩展 vanilla 样本累计观察到 329 个 texture、1840 个 packed tint、4165 个 texture×tint pair；
若预合成 `RGBA16F` variant，需要 35,727,934 mip texel、约 272.58 MiB，是同一组 canonical
texture 的 12.7045 倍。该结果只证明不能按 `(TextureId,tint)` 复制完整 color page；历史
`assignedCount=1840/highWaterId=1839` 也只描述面平均后的离散结果，不能作为连续 tint 的编码或
容量依据。后续测量必须改为四顶点/field 数量、RGBA16F 字节、插值复用率和 material adapter 成本。

TintId 接入时还暴露了两个独立生命周期缺口。资源 reload 期间，frame boundary 曾可能读取已经
替换、但尚未完成 Prime upload 的 atlas generation；现在 render-thread-only transaction gate 会在
`begin` 后 withholding frame snapshot，只允许同一 token 在材质页 bootstrap、可选 Shader reload
和 terrain epoch commit 全部完成后发布。F3+T 实测完成第二个 texture generation、继续渲染并正常
退出，未出现未上传 generation、device loss 或 validation 错误。

DLSS RR 与 Streamline 共享 NVIDIA NGX 进程状态，旧关闭顺序先执行 `slShutdown`，随后才释放 RR
feature，曾在 `nvngx_dlssd.dll` 内稳定触发 native access violation。关闭所有权现固定为 FG feature
→ Reflex feature → Prime renderer/RR → Streamline base runtime；失败会聚合但不跳过后续 owner。
普通退出和 F3+T 后退出两轮都由 `runClient` 返回 0，未再出现 NGX native crash。

### RR motion 第一切片

RR 的 trace-private `TransportScratch` 和重建期 `VisibleMotionUv` 已改为独立图像，主 motion 从
`RG16F` 升为 `RG32F`；reflection motion 继续保持 `RG32F`。原生 bridge ABI 升至 v10 并在调用
NGX 前验证精确格式。RTX 4090 上以 DLSS RR Performance、427×240 render / 854×480 display
连续运行 13,320 帧，未出现 NGX evaluate、Prime 或 Vulkan validation 错误。RR render-extent
图像账本由 135 B/pixel 增至 147 B/pixel：其中 8 B 是不再错误复用的 transport scratch，另 4 B
是主 motion 精度提升。该切片证明格式可执行，不替代下一步 motion 范围、重投影误差和 camera-cut
测量，也不批准压回 FP16。

### RR motion/depth 初始生产帧范围

同一 RTX 4090 环境对 vanilla 世界进行了两轮 opt-in GPU reduction。静止轮覆盖 164 帧、
16,806,720 pixels：motion/depth 非有限值与非法 depth 均为 0，静止 motion 峰值约
`0.000509 px`，表面 `LinearViewZ` 为 `1.4905–219.124 blocks`。自动前进和转头轮覆盖超过
6,000 个抽样帧，单帧相机位移峰值约 `0.08645 blocks`，motion 峰值约 `28.535 px`，没有
`|motionUv| > 1` 或非有限值；观察到的表面深度扩展为 `1.1984–2908.05 blocks`，P95/P99
对数桶上界为 `128/512 blocks`。这些是编码输入范围，不是画质或性能阈值；自动采样采用
Windows 输入驱动测试世界，未保存玩家位置。

同一世界的 NRD-FSR Performance 兼容路径覆盖 3,294 个抽样帧。自动前进/转头下相机位移峰值
`0.03947 blocks/frame`，motion 峰值 `24.459 px`，表面深度 `0.8797–1768.87 blocks`；同样没有
motion/depth 非有限值、非法 depth 或 `|motionUv| > 1`。这证明 GPU reducer 可跨两套生产 adapter
工作，也说明 RR 与 NRD 的当前常见范围相近；它不授权把二者的 semantic 或 validity 合并。

### 精确重建控制与 Streamline 可见 guide

重建输出现使用 `R8_UINT ReconstructionControl`：bits 0–1 是四类重建行为，bit 2/3/4/5 分别是
surface、history、motion validity 和 visible object motion。`history` 由帧计划逐位写入 ray push control；RR、NRD/FSR
和 Streamline 都在投影前检查，且 Streamline 自身漏帧/重新启用会再做一次本地 reset 门控。
因此 camera cut 不再依赖 sample index 或异常数值，miss 也不再借用 material float sentinel。

原 Streamline 路径把 RR 的 virtual reconstruction motion/depth 当成真实可见表面 guide；NRD
路径则混用了 visible motion 与 virtual view-Z。现在 ray resolve 写入真实可见 `R32F LinearViewZ`
与精确 object-motion bit；FG 在 backend prepare 前读取既有 f32 历史位置，随后才翻转 HUD-less
color。普通/RR 使用 `primaryPosition`，NRD 使用可区分真实接口的 `displayPosition`，没有增加持久
图像或每像素内存。生产 Shader 全量编译、
Vulkan 性质测试和 RTX 4090 上 FG 2x + UI recomposition 连续 16,680 帧通过；Prime、NGX、
Streamline 与 validation 均未报错。该静止样本覆盖 56,978,880 个 GPU reduction pixels，depth
`0.5–1324.275 blocks`，motion 峰值 `0.0004864 px`，非有限/非法/越界均为 0。

原 `RGBA16F transportMetadata` 动态位移候选已撤销。首批动态实体测量覆盖 3,517,920 个顶点和
1,917,833 个运动顶点，观察到最大位移 `0.508535 blocks`、最小非零位移 `4.768e-7 blocks`，
binary16 最大 component/vector round-trip 误差约 `1.1444e-4/1.2778e-4 blocks`。当前选择直接
复用 f32 position，所以这组误差不会进入 FG。RR 对运动中透射可见接口缺少独立历史位置；此时
显式清除 motion validity，而不是借用 virtual primary。若未来要求 RR+FG 精确重投影运动玻璃，
需要新增或重排一个 f32 visible-history owner，登记为窄功能缺口，不阻塞其他场景。

切换到 f32 history producer 后，同一 RTX 4090、RR Performance、FG 2x 与 UI recomposition 又运行
18,000 个逻辑帧；Prime、NGX、Streamline 和 Vulkan validation 均无错误。GPU range 抽样覆盖
15,372,000 pixels，motion/depth 非有限或非法计数为 0，表面 depth 为
`0.8857–1895.41 blocks`。该运行验证资源选择、descriptor format 和生命周期，不替代运动透射
界面的已登记缺口。

### ray-resolve 原始重建信号范围

同一 vanilla 世界分别以 RR 与 NRD-FSR Performance 运行新 reducer。采样点固定在 ray resolve
完成且 backend adapter 尚未改写 raw frame 的位置，因此两套 backend 观察同一组上游语义；
它不是 frame 尾部可能已经失效的 wavefront path buffer。

| 项目 | RR（153 次 / 15,679,440 px） | NRD-FSR（152 次 / 15,576,960 px） |
|---|---:|---:|
| radiance 非有限 / 负 / `>=65504` | 0 / 0 / 0 | 0 / 0 / 0 |
| radiance max / P50 / P95 / P99 桶上界 | 20832 / 0.03125 / 0.125 / 0.25 | 38912 / 0.0442 / 0.1768 / 0.5 |
| normal 非有限 / 最大长度误差 | 0 / `1.1921e-7` | 0 / `1.1921e-7` |
| roughness 非法 / min / max | 0 / 0 / 0.96 | 0 / 0 / 0.96 |
| albedo 非法 / max | 0 / 1 | 0 / 1 |
| hit distance 非法 / min positive / max | 0 / `5.9605e-8` / 65504 | 0 / `5.9605e-8` / 65504 |
| hit distance `>=65504` | 3,181,088 | 2,867,650 |

这批数据证明 raw reconstruction 图像当前的有限值和范围契约可执行，但不能反向批准把 transport
radiance 或 path distance 收成 FP16：这些图像本身就是 backend-facing `RGBA16F` 观察点。
尤其 hit distance 同时触及 binary16 最小正 subnormal 与最大有限值，且饱和值占比不低；在区分
真实远距离、无命中约定和格式截断之前，不得用典型分位数决定更窄 encoding。roughness 的零值也
必须继续与 exact delta/topology bit 分离，不能靠连续值是否为零推断 closure。

## 已登记延后项

- Nsight register、occupancy、cache、memory transaction 与逐 pass GPU 时间由用户统一采集；当前不
  以 JMH 抖动或总体 FPS 猜测具体瓶颈。
- `translationBenchmark` 的 extreme fixture 两个 fork 出现约 0.82 ms 与 1.6 ms 两簇结果；在排除
  harness/JIT/后台负载前只记录为测量稳定性问题，不设性能阈值。
- 主观透明材质、极暗亮度细节和重建稳定性只在数值/图像 oracle 无法判定时进入阶段 3 反馈清单。
- RR+FG 的运动中透射界面缺少独立 f32 visible history；当前明确输出 invalid motion，后续只有在
  该组合成为目标场景时才为它增加资源或重排生命周期。
