# 源路由边界与批量数据流

## 路由与截断

Java 在上游已足以描述对象外观的位置路由源数据，并停止本次提交对应的下游计算。保留第三方定义局部模型、选择模型、设置姿态/变换、材质和源颜色的能力及必要调用顺序；具体顶点变换、几何展开、光栅明暗、三角化，以及修改这些实现的第三方钩子不属于兼容范围。

截断单次几何提交，不跳过后续仍会设置姿态或提交其他部件的外层模型回调。模型自身生成/修改局部网格属于源定义；不能把已经包含相机、光照或下游变形的最终顶点冒充可复用局部模型。没有接入的源类别须明确标注；不得为兼容下游修改恢复整条 Java 编译，也不通过再次运行有状态回调猜测输入。

Rust 消费自足的版本无关数据，管理纯几何编译、驻留场景、失效传播、合批、资源与工作池；返回后不保留 FFM 借用，不查询 MC，也不反向调用 Java compiler。Java 保留 MC 源对象关联、源事件合并、宿主回调和封包所需状态；这些状态不是另一套渲染网格或 BLAS 缓存。

## 地形源输入与编译职责

26.2/26.3 使用 `ExclusiveTerrainCapture` 路由宿主的 section 脏通知、源可用性与生命周期。加载窗口进入/退出按条带增量枚举；窗口用于 PT 场景覆盖，不能把光栅 `visibleSections` 当作全部追踪场景，否则视锥外的阴影和间接光来源会消失。封闭批次在宿主 owner 上取得真实 `RenderSectionRegion`，由 `TerrainRouter` 读取本次源状态。没有 Prime Java 编译线程池，也不调用 `SectionCompiler`、地形 `BufferBuilder`、AO/方向光照、透明排序或 section 遮挡图。

路由的活跃输入是当前覆盖内的新来源，以及收到真实宿主脏通知的来源。`LevelExtractor.setSectionDirty` 的重复通知在封批前合并；区块/光照/生物群系包应用后由原版发出的范围通知保留，不再由 Prime 的加载、卸载或生物群系回调额外扩散整列及相邻列。新列进入时请求一次全部实际高度位置，退出撤销该列；全局失效仅在宿主 `invalidateCompiledGeometry` 接管点重置一次源状态。

首次非空来源沿用当前版本实际 `SectionUpdateTracker.hasAllNeighbors` 前提：八个水平相邻列已经存在，并且其 `lightOnInColumn` 为真。这里只调用宿主源资格谓词，以半径零的上下文承载，不恢复原版视图或编译调度。已发布段遵循原版重建规则，无需再等待首次前提；已核验的空段可以直接发布可用性。光照就绪是源资格，不会把光栅明暗写入材质。

未就绪请求只留在版本层的按列等待集合；不会创建 region、读取模型、注册 token 或生成 FFM 包，也不在空闲帧轮询。真实区块到达、`LevelLightEngine.setLightEnabled` 事件及宿主缓存窗口新增可访问条带，只唤醒附近已存在的等待请求，不令已发布几何变脏；新脏通知也可唤醒自己的请求以重新观察状态。卸载、窗口退出、epoch 与 owner 退出撤销等待；封批期间的新脏通知保留至下一批。这里保存的是源身份与宿主前提，Rust 仍独占几何计算、依赖传播、空间合批与工作池。源状态相同但收到真实脏通知时仍可能需要调用自定义模型，不能仅按“光照通知”等名称过滤其依赖。

模型入口是实际 `BlockStateModel.emitQuads`，不绕过第三方模型去重放 vanilla `collectParts`。自定义局部 quad 变换在这里仍属于模型定义。路由内容分为：

- **资源定义**：局部四边形、作者 RGBA/UV、材质层、cull face 和 tint 槽。原型是源几何，不含放置和光栅光照。
- **放置**：资源身份、源 offset、实际面可见性及本次源 tint。Java 的 `Block.shouldRenderFace` 保留源可见性规则；Rust 执行选面、平移、编码域颜色组合、三角化和边界计算。
- **流体描述**：实际 FluidModel 材质、未照明 tint、同类邻接、九点高度、流向、背面/overlay 属性和面遮挡区域。Rust 构造角高度、表面和 UV，不调用 Java fluid tessellator。仅在下游 `FluidRenderHandler.renderFluid` 中定义的新几何不受支持。

模型定义和实际面可见性求值后，没有任何存活面的放置不进入 op12；这不省略应执行的模型或可见性回调，也不隐藏不带 cull face 的几何。不可复用且完全不可见的临时定义不发布、不退休；正式 key 的定义仍可由后续放置使用。段内流体独立处理，全部过滤的段仍发布空的可用性。

几何定义用 op13 批量发布，段放置/流体用 op12 原子替换；布局见 [ABI](abi.md)。同一封批内先提交全部定义，再提交有效的 section，最后退休临时/逐出定义。定义不能被 section 合并覆盖丢失；退休发生在其最后一次同步编译消费之后。native 编译后的逐段网格拥有独立存储，不借用资源字典或 Java 对象。完整空段也发布可用性，卸载撤销可用性。卸载只作用于当前世界；没有已发布段或未完成 token 的列不生成撤销包，也不推进 FFM 水位。

Rust 完整验证输入后，逐层将本次选面、平移和颜色组合的结果与已发布网格按位比较。整层相同则保留原 Arc，不分配输出、不重复求边界；出现差异时复制已证明相同的前缀，只展开剩余部分，再原子发布完整层。比较仍有实际计算和读取成本；没有另一份持久源描述缓存，也不把资源身份当作内容相等证明。

Rust 的源编译池按连续输出范围同步 fork/join，小批直接运行；几何作业不回调 Java。每个 quad 的四个角只求值一次，再写入两个三角形；变化结果直接写入尚未共享的 Arc 存储，返回前全部 join，发布时不再复制整份 Vec。源回调仍在宿主 owner 上顺序执行，不能仅因转入 native 而省去尚需执行的真实模型/材质回调。首次大量源观察、FFM、内存分配和整格 AS 构建仍可能形成长帧。

普通世界中，已核验的 `hasOnlyAir` 与 region 语义可直接发布空段；重复空通知重新检查真实空状态，保持为空时不再生成 token/字节。未知源注入、调试世界合成内容和自定义 chunk 不采用空段快捷路径，仍读取实际 region；它们不会恢复 Java section 编译。epoch、卸载与所有者退出撤销空段证明。

## 源资源复用

Fabric `createGeometryKey` 只证明相同上下文、`cullTest=false` 的精确几何；null 表示不可按该契约复用。地形使用本次真实 world/pos/state/seed 上下文，展示模型 wrapper 使用其实际 EMPTY/ZERO 上下文，二者的身份空间不混用。key 查询可消耗随机数，emit 前恢复同一 seed。tint、放置和可见性不因 key 命中而被缓存。

地形 Java 仅保留最多 4096 个 key 到 native 身份及 tint/face 元数据的关联；局部几何由 native 持有。null key 每次观察实际 emission；有存活面才发布定义，在本批消费后退休。资源/图形选项变化与 epoch 撤销关联及 native 输入；逐出不是全场景容量限制，也不使已有逐段网格失效。

展示 wrapper 另按正式 key 复用宿主不可变 Mesh（4096 key、32 MiB 编码字节上限）；这是宿主提交引用的源对象。其具体 wrapper/state 能力检查保护上游更新语义；不推断任意改写均可缓存。可变 item quad 列表和 Vector3fc 值不能仅凭容器 identity 缓存。源值精确比较及哈希候选筛选用于避免重复路由；哈希不能单独证明相等。

## 模型、物品与粒子

模型在 `ModelPart` 调用每个 `Cube.compile` 之前读取实际局部 polygons 和已求值 pose，发布 op7 原型/实例，随后截断该次虚调用，包括 Cube 子类的下游 compile 覆盖。外层 `setupAnim`、模型遍历及后续姿态设置继续执行。资源顶点引用变化才重新读取局部坐标；原型共享不意味着任意不同资源身份都会去重。consumer、UV 或非空 polygon 布局无法解释时明确失败，不猜测材质或重播下游实现。仿射合法性由 native 入参验证；当前实例通路要求有限可逆变换，奇异姿态不静默丢弃，也不在 Java 补算。

普通 item 在实际 `putBakedQuad` 调用点路由本次局部位置、UV、QuadInstance 颜色及 pose。统一 tint 保留在实例记录，逐角 tint 保留为局部源颜色；按本次材质、tint 和 pose 分组，内容相同可共享原型。未知下游 consumer 明确拒绝，不调用它补算；foil/outline 与特殊投影仍不属于普通源通路的完整支持范围。

Fabric 不可变 Mesh 通过公开 `forEach` 读取源 quad，不要求具体 MeshImpl 类型；在 `outputTo` 调用前按源 layer/tint 连续分组路由。材质回调沿源组顺序调用，实际 BufferCache 保留相邻 layer 复用。多层源受支持；未知材质不能静默用白色替代。source 与实例上下文分离，几何变化、成员消失、epoch 退出分别解除引用，GPU 回收另等完成证明。

标准 quad 粒子在 `buildLayer` 调用前按实际 layer 读取已提取参数：位置、四元数、尺寸、UV、RGBA。每粒子传 52 字节，省去源记录中的光栅 light；同层合为 op6 参数 span。Rust 归一化旋转语义并构造四角/三角形，Java 不执行 `renderRotatedQuad`、逐顶点旋转或顶点编码。粒子 tick、碰撞、姿态选择和提取仍属于真实上游。GPU 展开可后续测量接入，当前展开在 Rust 同步池完成。

尚未提供更早源描述的自定义直接网格提交，仍通过 `Draw.append` 作为显式原始网格来源；这不提供对标准模型下游 consumer/展开改写的兼容保证。原始网格与参数粒子共用 op6 快照，持久实例使用独立 op7 增量。已路由标准叶节点不再产生重复 raw 顶点。手/HUD 属于宿主路径。

## 上下文、空间与完成证明

源资源、世界身份、帧观察、native 发布和 GPU 生命周期分别管理。Java 的成功封包只证明输入已自持；FFM 返回证明借用已消费；CPU 内容发布、命令录制、宿主提交和 GPU 完成仍是不同事件。资源定义可在同步编译后退休，上传/AS/输出依其各自最后消费者回收。

源变化按事件触发，未变化实例不发包。封闭批次没有跨帧数量/时间配额，重入事件进入下一批。没有后台翻译、全局共享可变缓存或主动源背压；实际 GPU 在途依赖仍保留。边界验证失败不发布该记录，失败批次不确认生产者水位。

空间分组完全由 Rust 决定：静态和动态均按世界原点对齐的 4×4×4 区块段网格，静态每个完整格使用一个 BLAS，CPU 保留逐段缓存，更新整格替换。Java 不知道桶/BLAS 归属，GPU 不知道 MC 区块，见 [空间合批](spatial-batching.md)。不把所有实体合为一个有大量空隙的 BLAS。

方块实体候选索引由列/成员生命周期维护。已知默认距离类型查询邻近列，幸存者仍执行真实 dispatcher 的球形谓词；未知距离、getter 或外逃可变 map 保留完整源观察，全局对象独立处理。这里的源资格与下游计算兼容范围不同。

## 验证边界

双版本 Fabric CPU 夹具在游戏 main 前退出，检查真实 Mixin 路由、源回调计数、下游零展开、同帧变更和退出。地形请求另覆盖真实脏/光照钩子、首次源阻塞与唤醒、无事件零轮询、实际 region/model 发布和卸载取消；这些是工作量与行为验证。地形、流体和粒子同时导出自足输入与参考结果，Rust 独立重放并比较几何、颜色与 UV；缺少输入文件是失败，不能算跳过通过。native 另验证截断/无效输入原子性、资源退休、空段、内容复用与单/多线程等价。

流体流向 UV 使用数学 atan2/sin/cos，不复刻 MC 的近似查表；对照允许明确的小量浮点差异，不改变面、层、颜色与可见性。源 callbacks 可依赖 MC 环境，已迁移的纯计算不能再依赖该环境。

真实游戏的完整覆盖、编辑响应和帧时间仍须用户手动验收；CPU 夹具不能证明 FPS。性能比较固定原生 1920×1080、场景、相机、种子、画质与射线预算，记录源路由/FFM/native/AS/trace 及慢帧。命令见 [CONTRIBUTING](../CONTRIBUTING.md)，未完成工作见 [TODO](../TODO.md)。
