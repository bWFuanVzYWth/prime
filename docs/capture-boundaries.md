# 捕获边界与批量数据流

本设计已经采用，按独立可验证的步骤接入。这里规定边界与目标数据流，不把待实现的能力当成现有支持；实际状态见下表，剩余工作见 [HACK](../HACK.md)。具体 ABI 和 GPU 同步分别见 [abi.md](abi.md)、[pipeline.md](pipeline.md)。

## 边界选择

优先使用有正式缓存契约的源，其次接收已求值的局部网格与姿态，再考虑已知纯叶节点的机械展开，最后保留实际原始输出。不同来源不必共享一个捕获入口。Java 执行 Minecraft 与模组的源语义，Rust 持有版本无关的资源、场景和更新计划，GPU 执行适合批量处理的纯数据计算。

缓存命中可以省去契约明确允许缓存的几何生成。实际模型选择、动画、tint、可见性和未被该契约覆盖的回调仍执行原来的一次；不能重放有状态回调来猜原输出，也不能依据对象类型、blockstate 或连续几帧不变推定几何恒定。资源身份与内容不变性是两个条件。

兼容范围按实际提交的源能力划分。遵循同一源协议的模组可以共享适配；未知 consumer、特殊材质或自定义展开在局部回退，不使其他已识别提交丧失快路径。类名、`final` 或 Mixin 注解检查不能证明任意字节码修改都安全。回退也有明确支持范围：已混入光照的颜色、任意 shader、文字和 glint 不能冒充普通未照明表面。

| 来源 | 采用的目标边界 | 保留的语义与代价 | 接入状态 |
| --- | --- | --- | --- |
| 展示框框体及 `BlockStateModel` 装饰模型 | 实际模型选择后，以 Fabric geometry key 复用不可变局部 Mesh | `null` key 继续实际 emit；tint、外部变换、随机规则、资源与图形环境分别处理 | 双版本缓存；受支持的实际不可变 Mesh 提交接入持久原型/实例，未知能力局部回退 |
| 框内物品、掉落物、item display | 实际 item 选择和 layer 求值后、逐 quad 变换前 | 组件、上下文、tint、pose 和 special renderer 继续执行；可变 quad 值每次观察 | 普通 `ItemFeatureRenderer` 的受支持提交按材质、tint 与姿态分组建立持久原型/实例；ExtendedItem、特殊输出和未知 consumer 仍回退 |
| 标准 `ModelPart` 实体与方块实体 | 实际动画和 render 遍历中的 Cube/part 叶节点 | 同帧公开源数组变化仍须可见；不能另走一遍模型树 | 已共享局部原型与实例；独占 pass 下受证明的纯叶节点可省机械展开，未知输出保留 |
| 骨骼或自定义变形模型 | 明确适配后的 bind mesh 与真实已求值 pose | 任意 Java 变形不能从最终矩阵反推；变形几何可能需要独立 BLAS | 尚未接入 |
| 标准 quad 粒子 | 实际 `QuadParticleRenderState` 的有效语义数组、四角展开前 | tick、碰撞、facing 和自定义提取继续；特殊粒子局部回退 | 目前仍捕获实际展开顶点 |
| 地形与流体 | 实际接受 quad 后、原版光照混入前 | 保留邻接、随机、tint、transform/cull 与流体规则 | 独立源窗口仍调用实际 compiler；op8 完整 section 原子替换与内容世代已分离 |
| 未知局部模型或 consumer | 实际 `MeshData` / Draw 批次输出 | 顶点生成与全量回退解码仍有成本 | 已有 op6 和空间桶局部 GPU 重建 |

展示框框体与框内物品是不同通路：前者经 `BlockModelResolver.updateForItemFrame`，后者经 item resolver，地图还有独立提交。框体的 geometry-key 缓存与普通物品的 quad 内容复用分别验证，不能互相外推覆盖范围。

不可变 Mesh 快路径要求实际提交来源身份、已识别的实现/输出器、普通材质绑定和 PT 独占帧，并限定已支持的单 layer、无 decal 等语义。首次读取未照明 position/RGBA/UV，按实际 tint 索引分组建原型；后帧继续求值真实 pose、tint 和材质。多 layer、未知实现/consumer 或缺少身份的提交继续原始输出。通用 item quad 不因外层容器看似不可变而自动接入缓存。实现状态不代替各版本的游戏验收。

## 几何缓存契约

26.2 和 26.3 的 Fabric `createGeometryKey` 允许以 `equals/hashCode` 相等的 key 共享相同上下文、`cullTest` 恒 false 下的精确几何；`null` 只表示该上下文无法按此契约缓存。适配器限定在真实 `BlockStateModelWrapper` 的 EMPTY/ZERO、固定 seed 调用路径，不把此规则泛化到所有模型调用。

key 查询可能消耗随机数。miss 时必须遵照原调用规则，以同一 seed 重新设置供 emit 使用的随机源。缓存只保存不可变 `Mesh`，不保存复用的 `MutableMesh`、整个 render state 或 tint 结果。每次真实更新仍计算本次材质标记、外部变换和 tint，再把 Mesh 交给实际 Fabric 提交入口。

key 不自动包含所有环境输入。资源重载与影响几何的图形选项变化必须使对应缓存世代失效；当前已知输入包括 `cutoutLeaves`。资源上下文跨世界复用 EMPTY/ZERO 几何，atlas 重载与选项变化显式清除缓存。LRU 上限为 4096 个 key、32 MiB Indigo 编码 Mesh 字节；字节预算不含 Java key、map 与对象头。逐出只移除缓存所有权，不能让仍被 render state 引用的不可变源失效。资源缓存的释放也不代替 GPU 完成证明。

当前试行仅接管已核对的 Indigo renderer、精确 wrapper/render-state 类型和已知 Fabric 注入组合。子类、替换 renderer 或可检测的外部 Mixin 保留真实原路径；这个保守能力门控不等于任意字节码修改检测。命中/缺失、null key、实际 emit 和省去的 Mesh 编码复制量按批统计，其中避免的编码字节不能当成整个进程少分配的总字节。

item 通路另需内容契约：26.2 的 layer quad 列表会被复用，26.3 的 `ItemQuads` 列表即使结构不可变，其内部 `Vector3fc` 仍可能指向可变向量。不得仅凭容器 identity 永久复用深层几何。

普通物品快路径观察实际 `prepareMainSubmit` 中的 `putBakedQuad` 调用，在本次材质、tint 和 consumer 回调完成后检查局部位置与 UV。仅接受已核验的纯 quad/输出实现、普通材质、无 foil/outline、统一顶点 tint 和有限可逆仿射；不重复调用 item resolver 或 special renderer。每个实际 submit 按材质、tint 和 pose 分组，而非每个 quad 创建一个实例。每次仍比较可变源值；值不变时省去机械坐标变换、顶点打包和原始几何传输，不省略源模型和动画语义。

局部几何经精确字节比较后可跨源实例共享；哈希只定位候选，统一 tint 属于实例状态。资源上下文显式维护几何引用，组内容改变时先取得新引用再解除旧引用；本帧未使用的组及未再出现的 submit scope 在帧结束解除引用，不依赖 GC 推进原型删除。公共实例上下文仍须等实例引用迁移或消失后才能删除原型，GPU 资源继续按完成证明退休。

## 方块实体候选筛选

PT 的方块实体来源是已加载源区块和实际全局实体集合，不依赖已退休的原版 raster 网格。对已核验的默认距离语义，可在全局集合查询、破坏阶段查找和实际提取前，用以方块中心为原点的 64 格轴向距离排除必定在默认球形距离之外的候选；立方体内的幸存者仍执行真实距离谓词及提取。这个筛选没有增加方块实体视锥裁剪，也不改变全局实体的独立提取路径。

资格按实际 dispatcher、资源世代、实体类与 renderer 的实现核验。自定义距离/可见性回调、有副作用的 getter、未知 Mixin 或替换 dispatcher 回退原路径；不能对所有方块实体强加 64 格距离。dispatcher 身份或资源世代变化，以及 `allChanged`、世界重建和 PT 退出会清除资格缓存；不检测绕过重载与世代机制的私有 renderer 映射改写。筛选仍扫描已加载候选，因此不代表方块实体提取已与总候选数无关。

## 上下文与更新频率

数据流保留显式所有权和副作用边界：

1. **资源上下文**持有局部几何、材质来源、generation 与预算，按源内容变化发布或释放；共享同一源资源的对象复用原型，正式 geometry key 也可提供跨对象等价证明。当前 Cube 缓存不对不同资源身份的相同顶点普遍去重。
2. **世界上下文**持有对象身份、资源绑定和存活关系；出生、消失与重绑定形成成员增量，不重建所有共享原型。
3. **帧上下文**收集实际可见提交、pose 和材质覆盖，复用连续封包存储；没有变化时不发实例包。未成功提交的脏数据保持有效。
4. **Rust 源上下文**验证完整批次和最终引用，再原子应用更新；工作区容量可复用，不要求每帧新建临时树或复制完整常驻状态。
5. **GPU 上下文**执行纯计划产生的上传、AS 和渲染命令，依最后消费者完成值回收资源。

这些上下文通过显式参数和借用协作。CPU 封闭批次先确定工作集、并行纯计算、返回前汇合，再发布与录制；不引入跨帧后台翻译。Java 编译器工作区和 Rust packing 工作池各自私有、显式持有；GPU 继续正常在途执行，完成等待不作为源吞吐限流政策。

op7 仍以每条 128 字节传输本次变化实例的完整源状态；native 使用独立 `InstanceInput`/cursor 传播身份与字段差异，稳定槽位支持 pose、材质分别失效及局部上传。更紧凑的线格式可后续按测量接入，不能把它与已实现的局部 CPU/GPU 工作混为一谈。游标缺口重新同步，GPU 完成槽保留待应用世代；身份有效期不按帧数猜测。

地形使用 op8 一次原子替换完整 section。完整批次验证后才发布；合法新编译仍推进源序列，精确相同的三角位置、源 RGBA、UV、材质和原点保留原 Arc/内容 revision；失败不消耗序列。不存在的层被移除，空 section 清空几何并标为已完成；op11 批量卸载撤销可用性。初次调度覆盖所有真实位置，包括已观察到的空段，由翻译层等待 64 段齐备再提交整格静态 BLAS；捕获层不判断合批时机。完整替换/卸载均受源序列与完成水位约束；完成水位回收已不可能被生产者引用的历史。哈希不能独自作为内容等价证明。源数据仍需读取比较；相同层直接与已验证的常驻三角形逐字段核对，不再展开临时三角形或重复计算边界。不同内容仍完整解码验证，局部真实变化的簇和 TLAS 仍有更新成本。

已知 compiler/region 与 `hasOnlyAir` 语义下，普通世界的真实空段直接发布空 op8，省去邻域快照和逐方块编译；首次空段和非空变空仍完整更新就绪与几何。仅在本 renderer/epoch 内保存已经发布的空段身份，后续脏通知重新读取实际空状态，仍为空时不再创建 producer token 或重复提交；非空进入真实 compiler 路径，卸载、全量失效、epoch 变化和 owner 退休清除对应证明。调试世界的合成方块、未知 compiler/region 注入与自定义 chunk 类型继续实际编译，不用缺少数据推断为空。能力检查仅覆盖已核验的 MC/Fabric 语义与可识别 Mixin，不承诺任意字节码改写。

私有编译工作区复用源顶点缓冲区，成功封包后才允许清空复用；已发布包拥有独立字节，嵌套捕获另有缓冲区，不覆盖外层未封包数据。容量保留到所属工作区退休，不增加逐 section 的 Java 顶点缓存。源阶段计时由可选 profile 记录，关闭时不读阶段时钟。

源调度与 raster 调度分离：PT 的加载窗口、脏 section 和邻接快照驱动真实 compiler，而原版专属地形网格/上传在后端移交时退休。资源上下文可跨世界保留，世界停止不能使随后标题界面的实际资源重载被忽略；切换到原版则释放 PT 自己的源缓存，重新进入时取得真实上传。

方块实体由列加载/卸载、真实成员增删和资源 epoch 驱动索引。默认纯距离类型仅检索邻近列；无 renderer 的已知类型不进入候选。真实 dispatcher 仍处理球形范围、removed/global、破坏覆盖与提取回调，原列/成员顺序保留。未知类、源 getter、自定义距离及外部可变 map 别名不使用该缓存；全局对象保持独立路径。成员变化在下一次候选封批时求值，不每帧重新遍历全部加载列。

私有源 compiler 的排序参数及 `MeshData`/compiler 能力均得到证明时，可省去不会被消费的透明索引排序。compiler、Results 与 VisGraph 能力也得到证明时，私有结果不构造原版 section 遮挡连通图，省略 setOpaque/resolve 并留下未消费的空 visibilitySet；owner 只调用结果的 release，不交给原版遮挡图。实际几何、tint、面 cull、模型选择与回调保持执行；未知改写或外部排序参数回到原始调用，普通 raster 顶点编码与光栅光照计算并未全面省略。

## GPU 批量工作的范围

优先消除工作，其次压缩必须传输的数据，再迁移仍有收益的机械计算。目标命令顺序是同一宿主队列中的上传、compute 展开/打包、BLAS/TLAS、路径追踪和原版手/HUD。CPU 已知成员数量时不需要回读 GPU 计数；生产图像合成也不经 CPU 回读。阶段依赖必须涵盖真实 shader、transfer 和 AS 输入访问。

适合 GPU 的工作包括局部 pose 层级组合、实例矩阵打包、标准粒子四角展开和有明确 bind/pose 契约的蒙皮。Java 已经执行的网格分配、模型选择和动画回调不能通过后置 compute 被消除。大世界坐标仍在 CPU 用 f64 减去 frame anchor 后收窄，不要求设备支持 shader float64；任意可逆仿射中的非均匀缩放、剪切和镜像须保持。

两版标准 quad 粒子的语义数据为 12 个 float 与 2 个 int，共 56 字节；应按 layer 和有效数量批量接收。不能直接套用 128 字节实例包并假定流量更小，也不能将任意已扭曲的四角重新解释为标准 billboard。

空间合批完全由 Rust 翻译层管理，捕获层不编码桶或 BLAS 归属。地形、实例、raw 回退与未来光源树统一按世界原点对齐的 4×4×4 区块段网格组织，静态与动态资源分离，规则见 [空间合批](spatial-batching.md)。静态地形每个完整单元合并为一个 BLAS，内部保留不同材质 geometry；动态单元内的 BLAS 粒度依据运动与几何范围选择。刚体整模型或刚性 part 可共享紧致原型，多关节模型可按 part 实例化；不把全世界实体合入一个带大量空隙的 BLAS。普通 KHR 光追层级是 TLAS→BLAS，不能靠嵌套 TLAS 表示模型层级。真正变形模型采用 GPU 蒙皮时，应比较 compute、独立 BLAS 更新、TLAS、遍历和存活内存的总成本。

TLAS `UPDATE` 不是任意成员变化的增量接口：需要相应构建标记、完整输入并满足数量、拓扑和活动状态等约束，实际增删仍须保留 `BUILD` 路径。少传 pose 不代表 AS 只处理变化实例。UPDATE 的构建时间、遍历质量与内存代价须一起验证。

大量独特模型与重复模型同等重要。独立 BLAS 的 storage 与 scratch 已采用页子分配，静态/纹理上传共享常驻映射页，区间依据实际完成值复用。页保留高水位容量，仍需针对真实活跃范围、碎片和扩容检查峰值，不能用共享原型的静止场景替代独特资源持续增删验收。

## 实施次序与验收边界

geometry-key 缓存、op7 CPU 批次工作区、受支持的 Mesh/普通 item 实例和标准叶节点输出抑制已按各自边界接入。只有 PT 独占后端已经取得资源、当前 pass 和纯输出契约成立时，才能省去原版顶点展开；手/HUD 和未知提交继续真实输出，不能失败后重播回调。宿主切换、源资源重载及实际模组输出仍须游戏验证。

section 内容世代、实例字段增量、同步工作池、GPU 页及 Java 封闭源批次已接入。后续功能包括更紧凑的 pose 协议、粒子语义与 GPU 展开、条件适合的 TLAS UPDATE，以及有实际需求的骨骼适配。真实游戏中的稳态、编辑响应与首次加载尾延迟仍需独立验收。

验收矩阵覆盖重复与独特资源、静止/1%/100% 姿态变化、持续出生删除、全部 raw、共享源同帧突变、未知 consumer、null key、随机分支、图形环境变化、资源重载与长时间流送。比较实际几何、颜色、UV 和可见性，并记录回退比例和原因，不能以静默丢对象换取性能。

正式渲染比较使用同场景、固定相机和预算的原生 1920×1080；详细逐叶计时关闭或明确单独列出。CPU 微基准分开记录 capture/seal/native/ack 或 parse/plan/apply，GPU 记录完整上传、AS 与 trace 区间。局部收益不换算为游戏 FPS，保留预热、离群值及未覆盖范围。可复用测量入口见 [CONTRIBUTING](../CONTRIBUTING.md)。
