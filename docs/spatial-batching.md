# 全局空间网格与几何合批

## 架构决策

地形合批、实体分桶与静态光源归属采用同一个世界原点对齐的 **4×4×4 区块段网格**。每个区块段为 16×16×16 世界格，因此所有者单元边长为 **64 格**，三个轴都使用 `floor(world / 64)`；负坐标向负无穷取整。这里的区块段是 section，不是整根垂直 chunk column。生产局部灯采样另用与其对齐的 16 格子单元，不改变源几何的所有者。

网格尺寸与相机、视距、捕获包边界、对象数量和 GPU 分配容量无关。它是翻译层的全局空间组织策略，不是可调画质项。静态地形和动态对象共用坐标系及单元尺寸，保留不同的更新世代、几何批次和资源生命周期；每个完整且非空的静态单元恰好一个 BLAS，动态对象仍可有多个独立 BLAS。

[表面编译](surface-compiler.md)是唯一静态几何编译入口，按同一 `prime_scene::spatial::Cell` 组织最终发光 quad。生产选择使用半径 24 的单级局部 alias 与全局功率 alias；一个规范灯页可以供多个材质格式范围引用。局部格按真实灯中心散射创建，允许跨所有者引用，不复制几何。动态灯和纹理重要性 proposal 尚未接入。逻辑总量与页内寻址/设备容量分开，不能将单张 alias 或单个 buffer 的限制作为全场景的光源数量上限。

## 分层职责

- **捕获层**发布实际源、原型、实例、纹理与生命周期增量；只知道源身份和坐标，不知道空间合批、桶号或 BLAS。生产地形经 MC 源批次由 Rust 编译、发布；实际空段计入就绪，卸载事件撤销可用性。封闭网格诊断入口使用 op8、op3/op11；不把卸载伪装成已完成的空编译。线布局见 [ABI](abi.md)。
- **Rust 区块管理器**[`ChunkManager`](../crates/prime-minecraft/src/chunks.rs) 独立维护来源活动范围、section 驻留/可用性、邻接与颜色依赖、群系缓存及待编译格的合并、选择和取消；版本字段解析、资源目录、纯几何编译与 GPU 构建各留在原职责层。当前只有固定 4×4×4 section 格预算，未来 LOD 尚未实现。
- **`prime_scene` 翻译层**持有空间归属、成员顺序、内容签名和计划工作区。`SourceScene` 保留逐段源缓存与完整性，`TranslatedScene` 增量维护只读快照和格成员，`TerrainPlanner` 管理静态整格替换，`Planner` 管理共享原型、实例单元与原始回退桶。它们不访问 Vulkan，也不执行 MC 回调。
- **Vulkan 执行层**提供单资源容量上限，消费不透明批次身份、三角形范围、局部偏移和实例变换；负责 shader 记录打包、资源分配、上传、AS 构建和按完成证明退休。GPU 不接收 MC section key、网格坐标或区块尺寸，不计算区块归属。

`SceneMesh` 与 `DynamicScene` 保留绝对 f64 源原点和不可变局部顶点。先以绝对坐标确定单元，再计算单元内 f32 位置与相对 frame anchor 的 f32 变换；不能先将源原点收窄到相机相对 f32，再逆推全局分桶。相机附近的 256 格 frame anchor 仅用于数值重定位，与这里的 64 格组织网格职责不同。

计划上下文显式持有 CPU 缓存，执行器显式借用计划；执行器完成打包后可回收计划工作区，GPU 只引用自己的上传/设备资源。没有隐式后台任务、共享可变全局缓存或按经过帧数猜测释放时机。

## 静态完整性与整体发布

翻译层按实际绝对源原点增量维护格内 64 个区块段位置的就绪掩码和位置引用计数；每次发布/卸载只更新对应位置，不重新扫描全部已知段。只有 64 个不同位置均完成当前 epoch 与资源目录代的源编译发布后，该单元才能合批；重复身份、重复位置和不同材质层不能增加就绪数量。真实完成的空段计入，未捕获、未加载或已卸载的位置不计入。源 key 保持不透明，不解析 MC 的位编码。

到齐前只接收、验证并保存逐段 CPU 数据，不为该单元上传静态顶点、材质或构建部分 BLAS。到齐后进入待构建集合，轮到该格时以当前 64 段缓存生成一份整格计划；同一帧收到多段更新只排队一次。全空单元不分配空 BLAS。

发布后仍保留逐段 CPU 缓存和各层内容 revision。后续某段变化时更新该段缓存，在所属格轮到构建的渲染边界整体替换静态 BLAS 与材质范围；来源和资源身份仍有效时，此前继续显示该格上一份已发布几何。合批不主动重编译其余段，也不保留旧格中的部分 BLAS。源接触、颜色及完整单元变化仍按真实邻域依赖失效。相同源内容与单纯动画帧推进不重建几何；无依赖的格和动态资源保持有效。旧 GPU 资源按已有完成证明退休。

源卸载（封闭网格入口为 op3/op11）撤销该段可用性并删除其源层，整个格退出 GPU 场景；其余段的 CPU 缓存保留，重新集齐后整格恢复。epoch/reset 清除旧世界可用性。加载窗口边缘或维度边界若不足完整的 64 段，则继续等待，不根据超时或位置推定缺失段为空；当前没有补齐未知区域的机制。

## 每帧构建预算

`terrain.batches_per_frame` 默认 8，范围 1–128；一个批次就是上述一个 `Cell`，不是单个 section、源协议包或上传页。CPU section 网格编译和后段静态格构建各自每帧最多选择 N 个格，两个阶段分别计数，不共用一个总计数。后段在成员分组、表面编译、打包、上传及 BLAS 构建之前选择工作集；生产首建和后续更新都受限，显式参考夹具仍可使用无上限入口。

CPU 待办以格身份和 64 个 section 脏位合并，后段以唯一格身份合并；持续编辑只更新待办，执行时读取最新自持源、当前纹理与 anchor，不跨帧保留 Job、宿主指针、完成证明或一份额外完整几何快照。两个阶段各自按有序格游标轮转，避免低坐标格的重复更新饿死其他待办。当前帧选中的 CPU 工作仍同步完成颜色源请求、编译汇合与发布，同一源事务内的颜色/群系往返不重复领取预算。

源发布消费与网格构建完成分开记录；即使没有新源发布，后续帧仍继续处理待构建集合。未选中的普通替换保留旧签名和放置，强制重建原因也保留到实际替换。源卸载、可用性撤销、整空格退出和 epoch/owner 取消不占构建额度，不能因排队继续显示失效来源。校验失败不确认待办或推进轮转游标。64 段真实完成证明保持不变，但跨格编辑可以在不同帧生效，不承诺跨格原子替换。

资源目录（catalog）显式整代换新由 `scene.terrain_resource_generation` 标识，与普通纹理像素和动画版本区分。CPU 源事务撤销尚未按新目录完成编译的旧 section 发布，后段观察到该代次变化时立即撤去旧驻留格，再按 N 格预算补回新代完整格；同一 epoch 内也不能用旧 mesh 的 UV/材质解释新目录。当前运行时纹理身份撤销机制下，后段同样立即撤去仍引用该纹理的旧格，未完成替换继续排队。上述撤销不占构建额度，可以暂时产生空缺；被撤去的 GPU 资源仍等最后实际消费者完成后退休。地形纹理的目标是初始化/资源重载后全局常驻；现有按引用回收机制属于[待纠正偏差](../TODO.md#待纠正的资源生命周期偏差)，这里仅规定分帧期间的最小正确性保护。

离线冻结暂停尚未完成的 CPU 源编译，不能为补齐积压隐式调用宿主颜色或群系来源。已经发布且由 renderer 自持的源仍可按后段预算继续构建；实际几何内容新增、改变或移除会使相关场景数据失效并重置离线累积。仅调整 N 不重置 RR 历史或累积；等价 OMM 重建和实例禁用退路也保留累积。旧 OMM coverage 的分帧过渡通过实例禁用、shader alpha 与真实完成证明处理，见 [OMM 失效契约](opacity-micromaps.md#资源代次动画与失效)。

预算限制工作单元数量，不是毫秒、上传字节或显存硬上限。源读取与验证、纹理及 OMM 资源代次准备、全局 TLAS、动态对象、紧急撤销和完整重同步有各自成本。该策略将构建分散到多帧，以增加加载/编辑可见延迟换取每帧较小的构建工作集；不保证减少总工作、提高稳态帧率或消除初始卡顿。

## 各类几何的归属

| 输入 | 单元归属 | 单元内组织与更新 |
| --- | --- | --- |
| 静态地形 mesh | 绝对源原点所在单元 | 64 段到齐后生成一个 BLAS；内部按材质分类与容量划分 geometry 范围。源身份、内容 revision、局部偏移和三角形范围构成整格签名。变化时整格替换。 |
| 持久模型实例 | 实际仿射变换后包围盒中心所在单元 | 单元保存实例放置，实例仍引用共享的局部原型 BLAS。实例出生、移动、消失不烘焙或重建原型；空单元移除。 |
| 原始动态回退 | 实际三角形的世界重心所在单元 | 按材质分类与容量分段；保持桶内源顺序，逐字段比较，只上传和重建变化段，消失的段移除。 |

材质分类保持 opaque/cutout/alpha 语义。局部容量上限由执行器提供；静态的 opaque/cutout/alpha 范围在同一个 BLAS 内按各自标记构建，opaque 保留硬件快路径；局部材质寻址超限只增加内部 geometry，raw 则仍按独立 BLAS 拆段，不扩大网格或截断几何。静态 TLAS custom index 指向本 BLAS 的首个 geometry 材质地址，shader 加硬件 geometry index 后取得对应地址，再以局部 `primitiveIndex >> 1` 取quad、最低位选原三角半面；不增加逐三角形搜索或额外指针层。超过设备单 BLAS 的 geometry/primitive 上限明确失败，不静默拆成多个 BLAS。单个共享原型目前仍须满足执行器的局部几何上限，超限明确失败；这与全场景总量上限不同。

归属点只决定所有者，不代表几何被限制在该立方体内。跨格的大面或长模型完整保留、只出现一次，不裁剪、不复制；真实 AS 包围盒由实际几何决定。局部灯表的半径只影响提议分布，完整灯几何与全局支持仍保留，不能把单元边界当成裁剪边界。

共享原型可以由不同单元中的实例引用，其几何资源没有唯一世界单元。这里的实例分桶不引入嵌套 TLAS，不把一格内的全部模型强制烘焙为一个 BLAS。shader 继续使用实际 object-to-world 变换及每实例材质覆盖。

## 成本与验证边界

没有待办的稳定场景直接复用计划结果。生产路径按源变更维护成员索引，仅校验变化 mesh，按预算重组受影响的完整格并比较其签名；未完整的格不遍历成员做 GPU 分组。无 coverage 失效的纯纹理变化不重组格或重建静态 AS；OMM 依赖变化按上面的失效协议处理。首次绑定、epoch/来源更换或消费者遗漏增量需要完整同步；任意可变 `Scene` 诊断输入仍走完整索引与校验。类型与消费确认契约见 [静态增量发布](architecture.md#静态增量发布)。

重定位仍校验全部驻留源的相对坐标范围并更新放置，不改变单元身份和局部 BLAS。实际几何修改仍需整格打包/上传/构建；静态执行器在放置或 BLAS 地址变化时仍重写静态地址/实例表并触发 TLAS BUILD。因此只保证静态源翻译和分组的普通更新工作集与受影响 mesh/格相关，不声称整个更新帧只与一个变化三角形有关。

raw 输入仍是快照，变化时需要完整分桶与内容比较，连续桶数组和计数工作区跨帧复用。仅 raw 改变时不重做持久实例的仿射与包围盒检查。持久实例使用类型封闭的成员/姿态/材质变化与反向原型索引，仅处理受影响实例。稳定稠密槽位在删除时只移动末项；元数据与完成槽的 AS 输入按合并后的脏范围写入，材质变化不重算姿态。真实成员/姿态/AS 地址变化仍 BUILD 综合 TLAS；首次同步、重定位和来源断档仍处理完整集合，不能将 CPU 增量等同于 GPU TLAS 增量。

行为验证覆盖 63 段等待与第 64 段发布、空段/卸载区分、CPU 缓存保留与整格替换、同 BLAS 混合材质与 geometry 寻址、64 个相邻 section 合批、三轴及负坐标边界、跨格移动/出生/删除、密集单元分段、跨格长三角形、材质顺序、大坐标与 anchor 变化、epoch 切换、静态/动态互不失效，以及实际 GPU 像素与保留资源身份。无窗口检查不能代替真实存档测试；正式性能比较仍使用固定配置的原生 1920×1080。
