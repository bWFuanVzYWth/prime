# 灯光与大气采样

所有渲染器共享规范灯光、纹理发光和摄像机大气条件，各积分器明确决定 NEE 与路径命中
的贡献归属。树中的功率只影响 proposal，不能替代最终 radiance。

## 方块光

采样单位为发光三角形。世界树选择 cluster，局部树选择 emitter，两层共用一个随机数
并按分支重映射。接收点、完整 f32 接收法线和发光边界参与树目标；有限多条目叶保持
非零支持域，正向选择与反向 PDF 使用同一归一化过程。

面内统一使用 256-cell 纹理面积 alias 分布，再在选中小三角形中均匀取点。不使用投影
采样、近远切换、混合权重或 ReSTIR。动画多帧最大重要性与正概率 floor 保证支持域，
实际帧 Le 独立读取规范颜色、tint 和 vanilla/LabPBR 发光。

```text
p_select = p_world × p_local
p_area   = p_select × m_cell / (A / 256)
p_omega  = p_area × distance² / lightCosine
```

正向取点与 emissive-hit 反向求值使用同一密度、mip-0 发光和精确 emitter 身份。
贡献中不得再次添加距离平方衰减。面内取点不需要接收法线，但树选择仍需要，因此
完整路径的 previous receiver normal 必须保留到反向 MIS 消费完毕。

| 积分器 | NEE 与命灯 |
| --- | --- |
| 完整实时 | 每个合格非 delta 顶点采太阳和方块光，保留阶段对应的 BSDF MIS |
| 离线 | 每个合格非 delta 顶点采太阳和方块光，命灯重建竞争 PDF |
| 轻量 | 仅首 Lambert 双族 NEE，深层只采太阳；注册灯直达项按上一顶点资格独占 |

灯光树、面内取点、阴影、BSDF 是窄能力叶。太阳阴影与完整面积光样本不同时存活；
已消费样本立即结束生命周期。当前未拆成独立 area visibility / sun visibility / BSDF
调度，也不为暂缓的 MSE 诊断分配参考图或执行 reduction。

完整透明阴影提供直线滤光和 BSDF-only 两种模式；轻量固定有序直通滤色。主路径和
阴影都遵守[精确端点契约](GPU几何追踪精度契约.md)。动态对象的可见发光只有注册为
emitter 后才参与 NEE，不能将可见发光宣称为已实现任意手持或粒子动态灯。

## 灯光树构建与数值

CPU 建树将每个 section/emitter 作为单条目叶；候选划分先按 SAOH 排序，只在最优值的 2%
质量带内，以聚合功率加权的平衡二叉树后续深度作第二排序键。该项只改变树拓扑，不改变 GPU
节点 ABI、运行时概率或可反向重建的 bit trail。
多条目的 world 叶按各 section 根节点重算接收者相关目标，多条目的 section 叶按实际发光三角形
边界重算目标；单条目叶保持概率 1 的快速路径。目标近似 projected solid angle，并以完整 f32 着色法线的
余弦朝向代理 BRDF 支持域，形式为有界角度功率除以距离平方，另保留 `1/256` 的支持域地板。它不是
OpenPBR BSDF 的近似求值；BSDF 仍作为独立 MIS 技术精确处理。正向选择与发光面命中的反向 PDF
共用同一个缩放、求和顺序和接收面法线，避免叶内重要性破坏无偏 MIS。

两级树共用的 `LightNode` 为 32-byte ABI：质心和功率保留完整 f32，不能
改回 f16、固定范围、裁剪或丢弃远处驻留簇；render-origin 重定位后，world tree 可能在旧簇
退出驻留前暂时跨越很大的相对坐标。记录保留原 RGB10 量化后解码成 f32 的 centroid、
功率、方向和子节点引用；末尾两个 word 在叶节点中直接携带精确 entry 索引及原叶功率位，
内部节点仍写零。正向选灯与反向 MIS 读取兄弟记录后沿用选中孩子的控制字，不再逐层重读
当前控制字或追踪叶表。原叶流与 child/leaf 索引编码暂保留，节点大小及 GPU 生命周期不变。

## 摄像机大气条件

采用空间近似 `T_atmosphere(x,ω) ≈ T_atmosphere(camera,ω)`。太阳、天空和星图均保留
方向依赖，表面 BSDF、法线响应、太阳盘 PDF 和实际几何阴影不变。低太阳高度角与较大
高差的空间误差没有统一最坏界，不能把 LUT 数值误差误作该空间近似的误差证明。

`AtmospherePipeline` 拥有共享 `8193×1 RGBA16F` 方向透射表，纹素数据共 65,544 bytes。
令 mu 为方向竖直分量，采样坐标为
`u = 0.5 + 0.5 × sign(mu) × sqrt(abs(mu))`，在地平线附近加密；消费者读取相邻两个
RGB texel 并插值。太阳盘与星图乘各自方向的透射，地平线判定按实际方向执行，不能
以太阳中心遮挡整块圆盘。

该表由既有 sky dispatch 的前 8193 个 invocation 写入，复用海拔/太阳高度更新 key、
屏障与提交成功后发布规则。无额外 dispatch、CPU 光谱副本或读回。光谱 low/high
透射表只供预计算生产者使用，不进入日常 RT 照明闭包。

天空继续读取摄像机条件下的二维 sky-view LUT。空气透视仍使用方向和距离相关的
散射、消光纹理：`Lout=T(view,distance)×Lsurface+S(view,distance)`，并保留太阳体积
阴影；不能简化成一份与距离无关的全局 RGB。离线冻结并消费同一大气模型。

## 星图资源

星图使用 NASA Deep Star Maps 2020 的 `16384×8192` EXR，保留 ICRF/J2000 等距圆柱投影、
赤经方向和原有 `0.025` 辐亮度倍率。来源 EXR 不含 chromaticities；预处理延续现有的
linear-sRGB 解释，将数值一次转换为 D65 linear Rec.2020，不能声称 NASA 保证该色度解释。
不执行 EOTF、曝光或色调映射；16K 基础层不缩放、不重采样。

离线编码为 `VK_FORMAT_BC6H_UFLOAT_BLOCK`，每个 4×4 块 16 bytes，基础层为 128 MiB。
另从未压缩的线性 Rec.2020 源按球面纹素立体角生成 14 层 mip，直到 1×1；完整链约
170.67 MiB。相邻行按各自纬度区间的 `cos(theta0)-cos(theta1)` 加权，不能在 encoded RGB
中缩小，也不能从已压缩层逐级生成误差。设备必须支持该格式的 16K、15 mip sampled/transfer
image 和线性过滤。运行时仅解开 gzip、上传 BC6H 块，无 EXR 解码器、转码或 RGBA 镜像。
U repeat、V clamp，mip 间线性过滤。四个基础分片和各 mip 的 staging 在首个成功提交完成后退休。

相对未压缩 16K 工作空间图，完整扫描要求有限、非负值；RGB NRMSE ≤8%、亮度 NRMSE ≤6%、
亮像素亮度 NRMSE ≤6%、球面积加权总亮度相对误差 ≤1%。NRMSE 定义为
`sqrt(sum((decoded-reference)^2)/sum(reference^2))`；亮度权重为 `(0.2627,0.6780,0.0593)`，
亮像素指源亮度 ≥0.1，球面积按每行的纬度区间积分。这些是该固定资产的整体误差合同，
不保证单颗星的最坏相对误差。当前实测依次为 7.06%、5.78%、5.75%、0.66%，
最大单通道绝对误差为 0.383。以上实测属于未修改的基础层。每个 mip 相对其未压缩球面滤波
参考独立检查有限性、非负性、RGB NRMSE ≤8%、亮度 NRMSE ≤6%、球面总亮度误差 ≤1%；
逐层结果写入清单，不能用总体平均掩盖某层失败。

`tools/build_starmap.py` 锁定源 EXR 和 DirectXTex may2026 `texconv.exe` 的 SHA-256，
0–9 层以 DirectCompute 编码 BC6H，16×8 及以下的 10–14 层使用精度更好的 CPU 编码器；
所有层再用 CPU 解码器做全图误差检查。逐层通过后写入块资源，完整链通过才更新 mip 清单
和 GPU 样本；失败的生成过程不能用于发行，发行构建还会逐文件核对清单。Gradle 不重新压缩纹理。
预处理依赖 Python、NumPy、OpenEXR，以及 Microsoft 官方 DirectXTex may2026：

```powershell
python tools/build_starmap.py '<source>/starmap_2020_16k.exr' src/client/resources/prime/starmap `
  --texconv '<tools>/texconv.exe' --work build/starmap-bc6h `
  --fixture src/test/resources/prime/starmap_2020_16k_samples.json
```

只追加 mip 时使用 `--mips-only`，脚本先核对现有基础层哈希，不重新编码基础层。

## RR 原生分辨率星空

仅 DLSS RR 且相机不在水中时，完整和轻量积分器的直接相机 miss 不计星图；大气天空和太阳
继续进入 RR。完整路径通过精确 source primitive 身份区分直接视线，轻量路径使用已有 visible
标志；反射、折射和间接 miss、其他重建后端及离线仍按既有 LOD 0 求值。

`rr_stars` 在 NGX 之后、自动曝光之前，按输出像素中心的非抖动相机射线生成星图坐标。
赤经差分先跨缝折回，再由 UV Jacobian 求椭圆长短轴；短轴选择三线性 mip，长轴最多 8 taps。
超过 8:1 时扩大短轴滤波，避免欠采样。它复用同一天文帧、地平线判定和方向大气透射，按
`Lout = Lrr + (1 - foregroundCoverage) * T * Lstars` 在线性 Rec.2020 合成，无时间历史。

前景覆盖率由 RR alpha upscaling 重建；输入取真实可见表面有效位，不能取虚拟反射/折射 guide。
NGX Preset F 在 reset 首帧可能低估实体内部 alpha，因此仅在当前抖动对齐的 3×3 输入邻域
全部为前景时禁止追加星光；混合轮廓仍使用 NGX 覆盖率。该校验不替代亚像素可见性重建，
树叶、细几何和反遮挡仍需游戏运动验证。水下保持原路径，不能漏掉介质消光。

新增成本是一张共享星图约 42.67 MiB 的 mip 尾部和一次 compute dispatch；不新增 TLAS
追踪、历史纹理或独立队列提交。实际帧耗与游戏画面仍需实测。

## 验证边界

方块光验证全部 cell、alias 边界、正反 PDF、动画支持域、真实遮挡和发光归属；大气
验证端点、近地平线、f16 量化和 RGB LUT 相对光谱生产者的误差。恒定消光积分使用
解析零消光极限，不能用 epsilon 分母制造能量。

星图的发行检查验证源身份、15 层 BC6H 布局、精确分片集合、长度、SHA-256 和 gzip CRC。
`StarmapBc6hGpuTest` 在 Vulkan 上上传完整块数据，将亮星、随机点和分片边界的 texel fetch
及线性过滤、mip fetch、分数 LOD 与独立 CPU 解码样本比较；全图有损误差由预处理检查。
`StarmapFilterGpuTest` 使用生产滤波函数检查 64 个亚像素相位的星光总能量、赤经跨缝、
退化 Jacobian 和覆盖率合成。真实 NGX 与生产 `rr_stars` 的组合测试见桥接库 README。

场景回归覆盖远小灯、近大灯、隔墙、染色介质、夜间间接照明和日落太阳盘。实时比较
运动重建与 GPU 时间，离线比较相同模型的等时方差；不同模型的图像差不能当作纯采样误差。
