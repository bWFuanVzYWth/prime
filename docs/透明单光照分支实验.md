# 透明单光照分支与双 guide

2026-09-06，用户实测确认质量达到需求，实验收敛为固定策略。完整实时采用 STBN 等概率
首透明面单光照分支，每像素只分配一条完整路径，并补齐另一分支的 guide。Lambert 不使用
透明分支；离线保留原有完整闭包随机路径。三个会话调试控件及备用实现已删除。

离线、完整实时和 Lambert 统一使用线性 RR：`p = clamp(max(beta) × etaScale, 0, 1)`，
存活时仍执行 `beta / p`。删除平方根和按首表面反照率去调制的概率策略及专用 guide 读取。
DLSS 固定只提交反射命中距离，不提交显式反射 MV；NRD 太阳 diffuse/specular 共用 SIGMA。

## 光照估计器

首可见透明接口仍通过原适配层得到条件透射、反射两个候选，保留原 Fresnel、介质转换、
几何支持检查与条件 PDF。两候选都有效时，正式 STBN 表的低 16 位中点将选择分成各 50%。
地址使用 bank 0、vertex 0、branch 0，与首面 NEE 从 vertex 1 开始的地址区分。

选中分支仅将后续光传输 throughput 乘 2。首接口已经结算的 NEE/emission 不重复补偿，
guide albedo 不乘 2。若 `P` 是首接口已结算项，`T/R` 是原双支后续估计，则
`E[P + 2 I_T T + 2 I_R R] = P + T + R`。这保留原双支、既定截断估计器的期望，
没有修改 BSDF 内部的随机映射或 MIS 权重。之后的 RR 仍独立按实际 `p` 执行 `beta/p`。

仅一个候选有效（包括 TIR）时，该事件概率为 1、权重为 1；两个都无效时不继续照明。
TIR 标记根据物理候选而非随机选择确定，不能把“本帧选反射”误标为“透射身份不存在”。

## 两套 guide，只有一条完整照明路径

选中分支沿现有光传输路径生成 guide；后续离散事件若与优先透射的规范 guide 事件分歧，
仍通过已有 detached-guide 遍历补齐。未选首面分支直接进入同一个 guide-only kernel：

- 粗糙首面已拥有可见接口 guide，只补出射首段的真实命中距离；miss 为 65504。
- 离散首面以该条件事件初始化 PSR，随后沿规范离散链追到替代表面或天空方向。
- 保留精确源图元、BLAS 权威位置、介质身份/IOR 和 f32 PSR，沿用运动、溢出、链上限的回退。
- 不计算光照 emission、NEE、RR 或消光 RGB，不进入后续照明队列。

未选 guide 在 split 后先完成；选中照明路径之后才执行 delta walk。这一顺序避免它稍后
产生的 detached guide 与未选 guide 共用每像素暂存。复用已有 raygen/SBT group，增加一次
guide queue drain，不新增管线模块。NRD 保留两套重建信号。DLSS 仍受单套 primary guide
的接口限制；补 guide 不代表能同时提交两套主表面给 DLSS。

补 guide 避免身份随是否选中而消失；照明仍有一半帧未采到某一分支，重建依靠时间积累。
该组合已通过用户画质验收；没有新增辐亮度 clamp 来掩盖稀疏信号。

## 存储与生命周期

逻辑队列索引仍为 `pixel + branch × N`，便于保持两套信号与精确 branch 身份；
只有完整 transport 访问映射到 `[0,N)`。导向图像、surface 和阶段暂存仍按逻辑身份寻址。

| 数据 | 当前固定策略 | 历史双光照策略 |
| --- | ---: | ---: |
| 完整路径记录 | 112 B × N | 112 B × 2N |
| 未选 guide | 40 B 射线 + 28 B 控制/PSR，复用其闲置的 100 B surface 槽 | 无此角色 |
| surface、阶段暂存、guide 图像 | 既有容量 | 既有容量 |
| 队列索引与命令区 | 既有容量 | 既有容量 |

未选分支的 28 B 控制/PSR 在 guide 完成后继续驻留至 resolve；只有选中分支的完整路径
可被后续光照更新。guide ray 位于表面槽字 0..9，控制/PSR 位于字 10..16，两者都不越过
100 B 槽。split 的初始表面已先加载到当前 invocation，随后允许未选透射 guide 复用该槽。

同时修正已有 detached-guide 与 receiver normal 的跨像素重叠：早期 guide 的 40 B 紧密
排布与后期按分支排列的 24 B/path 记录并不具有相同像素归属，写 guide 或清零 normal
可能破坏其他像素，甚至覆盖仍存活的不透明路径 normal。现在阶段区为每像素连续 48 B，
早期 guide 占前 40 B，后期两个分支各占 24 B。总容量不变。
同一像素的两个 detached guide 仍按阶段串行消费；分支尚有独立 guide 时，它们的上一
接收面必为透明／离散面，面积光反向 MIS normal 为精确零，因此完成时可重置两份 normal。
GPU 测试混合两个 guide 像素和两个不透明像素，验证写入及完成清理不改变后者存活的 normal。

完整 Wavefront backing 从 `540 B × N + 112 B` 降至 `428 B × N + 112 B`，另有不足
256 B 的路径区对齐。1920×1080 渲染分辨率省 221.48 MiB，3840×2160 省 885.94 MiB。
这个数字按内部渲染分辨率计算，不包括独立重建图像、几何、纹理或后处理资源。

此前实验的静态检查发现 Slang 把含 uniform 开关的三元地址选择展开为每次字段加载的
重复分支。现已去掉开关，保留整数表达式 `pathIndex - uint(pathIndex >= N) * N`，
在逻辑索引 `[0,2N)` 内精确等价，避免依赖编译器跨控制流合并地址表达式。

## 测试与实机对照

GPU 行为测试覆盖正式 STBN 表的完整 128×128×64 周期、各候选有效性与全部 16 位选枝值、
估计器平均能量、guide 距离更新而不改变辐射/几何身份、混合像素阶段覆盖，以及至 4K 的
完整路径与 guide 槽边界。
CPU 测试验证实际 push 字节、固定 N 槽 backing 大小及队列边界；原 BSDF/介质/PSR 性质
与分布测试继续运行。RR 测试保留线性概率、etaScale、边界补偿、12 次散射的解析积分
期望与首段距离语义，删除已撤销策略的测试。编译与静态成本见[寄存器记录 L7](轻量渲染器寄存器记录.md#l7-收敛固定策略与删除实验分支)。

画质由用户确认达到需求；本轮只收敛已验证组合。静态指令数量不代表物理寄存器或帧数，
后续扩展仍需观察 shade、admission、tail 和 guide 的 allocated/live/spill 与 GPU 时间。

收敛验证：`gradlew build shaderTest nativeTest` 通过，633 项测试无失败、错误或跳过。
