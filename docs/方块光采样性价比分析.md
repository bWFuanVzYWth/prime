# 方块光采样性价比分析

2026-09-05，基线 `8570c0e7`，更新为删除投影采样后的实现与调度评估。

用户复测确认删除投影后帧数进一步提高。后续优先暗光深层反弹与萤火虫；实时以重建稳定性为
目标，离线比较同一积分目标的等时方差。阶段拆分与 MSE 均明确暂缓，下述对应章节仅保留设计
记录，不再等待 MSE 参考图选择。继续调查见[暗光深层反弹与萤火虫分析](暗光深层反弹与萤火虫分析.md)。

## 已确定的方向

用户实测近处大灯的降噪没有问题，需要改善的主要是远处和深层反射。删除投影采样，统一使用
纹理面积分布；保留两级光源树、必要的 BSDF MIS 和实际发光求值。不引入 ReSTIR，也不再增加
距离阈值、动态混合权重或近处投影特例。优先把预算用于有效的路径延续。

本次已删除投影实现、混合常数、投影专用测试和许可说明，同步修改正向与反向 PDF，并将旧实时
fixed/landing direct 的方块光取点移到太阳阴影之后。没有改 BSDF 模型、树选择、纹理分布表、
几何身份、路径记录大小、RR 或反弹上限。完整的可见性/着色阶段拆分仍是下述设计评估，尚未落地。

## 当前共享采样

采样单位是发光三角面，辐射值来自规范颜色页面、tint 与 vanilla/LabPBR 发光。树的功率只影响
proposal；不能以它替代最终发光，也不能在最终贡献中重复施加距离平方衰减。

1. 世界树选择 cluster，局部树选择 emitter，两层共用一个随机数并按分支重映射。
2. 完整的面内随机数域用于 256-cell alias 表，再在选中小三角形中均匀取点。
3. 计算立体角 PDF，按精确源图元/目标 emitter 身份追踪阴影与透明介质透射。
4. 求实际发光、BSDF 与 MIS，按对应路径的 NRD 分量归属累加。
5. 后续 BSDF 命中灯且存在竞争 NEE 时，从前一接收点重算树 PMF 和纹理面积 PDF。

设世界与局部树 PMF 之积为 `p_select`，小三角形概率为 `m_cell`，完整灯面面积为 `A`，则
`p_area = p_select * m_cell / (A / 256)`，`p_omega = p_area * distance² / lightCosine`。
正向取点和 emissive-hit 反向求值均使用这份密度。动画多帧最大重要性与正概率 floor 保留，
保证纹理 proposal 的支持域；实际帧的发光仍单独读取。

取面内点不再需要接收法线；**两级树仍需要**，因此 previousLightNormal 的 12 B 不能随投影
采样一起删除。只在取点接口和重复调用处删除该参数/计算。

| 模式 | 方块光行为 |
| --- | --- |
| 旧实时 PT | 共享树与纹理面积 NEE；主表面分量的既有独占/MIS 归属保留 |
| 离线 PT | 同一树、面内分布、发光及反向 PDF；随机数来自 Sobol |
| Lambert 基线 | 当前只有阳光 NEE，没有方块光；以后接入同一组窄模块 |
| 仅主光线 | 输出主表面颜色，不引入灯光采样闭包 |

## 本次成本变化与验证

旧 sampler 无论最终走哪一支，都先构造投影域取得面积；投影分支又构造采样域，反向 PDF
也需要投影面积。删除后移除了半球裁剪、椭圆边、排序、反三角函数及迭代反演，没有留下运行时
关闭的旧分支。新的 cell_sample 模块只供取点与行为测试使用，反向 PDF 不依赖取点代码。

fixed/landing direct 原先让 AreaLightSample 跨越太阳 TraceRay。现已先完成太阳项，再取方块光
面内点。太阳随机身份和各项累加顺序保持不变；仍可能存活的面积树选择为 12 B，不能声称所有
灯光状态都已消除。完整光源样本的语义字段原为 52 B，其中真正动态使用约 36 B；这些数字不是
驱动实际 RT 栈或 allocated register 的测量。

`build shaderTest` 通过：579 CPU、1 artifact、43 GPU，共 623 项，无失败或跳过。新的 GPU
性质测试覆盖全部 256 个 cell、alias 边界/概率 0 和 1、内部点正反 cell 身份、独立双精度取点
与 PDF 参照、几何缩放下的密度一致性。原有 CPU 表归一化、支持域与动画测试保留。
后续游戏验收覆盖夜间密集灯、远处小灯、近灯、隔墙、稀疏/动画 LabPBR 和玻璃/水。

## 调度：生成样本并完成阴影，再求 BSDF

这个划分适合作为新渲染器的目标：最关键的收益是阴影入口从源码上不再包含 OpenPBR 求值，
以及 BSDF 临时状态不再与 RT 遍历存活期叠加。只移动调用位置而仍使用宽 primary.slang import
不能建立这个保证；必须拆出实际独立编译的窄入口。

| 阶段 | 工作与需要的数据 | 不应引入的依赖 |
| --- | --- | --- |
| Surface trace/prepare | 权威命中点、身份、材质类型与必要的表面/介质状态；处理 miss/emission | 灯光样本、阴影结果 |
| Area visibility | 两级选灯、纹理面积取点、有限阴影、实际 Le 与透射 | 完整 BSDF evaluate/sample；太阳/星图 |
| Sun visibility | 太阳方向样本、无限阴影、大气 LUT、首表面半影/可见性 | 光源树、Area 分布、完整 BSDF |
| Shade/scatter | 消费灯光结果，BSDF evaluate/PDF/MIS；scatter、RR、subgroup 入队 | 树选择、发光纹理查找、TraceRay |

可见性阶段仍需要源/目标精确身份、起始介质与方向支持判定。它可以使用材质离散类型和必要
法线做便宜的零贡献检查；“BSDF 只在 shade”不意味着阴影不再处理透明介质。避免将完整
SurfaceInteraction、VolumeStack、PathRecord 一次性加载进局部变量；按实际阶段提供窄 loader。

首表面的太阳是特殊输出：SIGMA 要未遮挡光照、visibility 和 penumbra。不能提前把被挡太阳项
全部清零，只存 `Le * visibility`。方块光和非首表面太阳则可在遮挡后输出零，无需让目标身份与
UV 继续进入 shade。太阳、天空和星图仍保留方向依赖；位置近似继续共享相机大气缓存。

### 暂存显存是拆分的约束

一个方块光可见性结果可以先按固定 f32 表达为 `direction.xyz + radiance.xyz + pdf`，28 B，
按 32 B 预算。radiance 已合并透射，保持 PDF 独立，继续使用现有数值稳定的 MIS/乘除函数，
无需提前形成可能溢出的 Le/pdf。太阳 PDF 是帧常数，`direction.xyz + radiance.xyz + visibility
+ penumbra` 可用 32 B；首表面以外也可以复用这份固定布局。

两种光都完成后只执行一次 shade，需要两份结果同时存活，约 64 B/path。旧实时现有 staged
区为 24 B/path：选择 12 B 加 previousLightNormal 12 B。若机械替换为 `64 + 12 = 76 B/path`，
增加 52 B/path；旧实时两个路径槽、3840×2160 内部渲染分辨率下，约多 **823 MiB**。
即使不考虑更高对齐，这也不符合当前显存目标。控制字段不能让仍同时存活的数据互相覆盖。

优先采用以下实施顺序：

1. 新渲染器先将 **Sun visibility 与 shade/scatter 分开**，用生命周期表证明样本可复用哪些路径
   字段。Lambert 当前仅有太阳，正好作为闭包、队列和寄存器对照；先不为未接入的方块光预留表。
2. 加入方块光时，再选择“两份结果、一次 shade”或“Area visibility → Area shade → Sun visibility
   → Sun shade/scatter”。后者只需一份暂存，但重复读取材质并多一个 shade dispatch。
3. 表面、前一顶点 MIS、相机 guide 等仍活着的数据要在生命周期图中明确列出；先消费本顶点
   emission/MIS 后才复用其字段。源位置也常是下一条 continuation 的起点，不能因为阴影结束就
   判定它死亡。严格保持当前顶点光照在 continuation RR 之前结算。

旧普通路径当前为 `bridge → light_select → direct → scatter`。若 area visibility 合并现有
light_select/area shadow，拆分为 `bridge → area_visibility → sun_visibility → shade/scatter`，
**逻辑阶段数可以保持四个**，但 RT/compute 队列和 barrier 仍需测量。Lambert 从 trace→shade
变成 trace→sun_visibility→shade/scatter 则明确多一次 dispatch，空队列与 subgroup 紧凑化要保留。

旧实时主表面、guide、landing、固定段、tail 的路径归属不同；离线也有自己累加与介质契约。
共享可见性算法和固定输出契约，在各自调度入口接入。不要把旧状态机连同大量无关闭包复制到
新渲染器；这次未改完整调度，避免在没有暂存预算和驱动数据时给旧路径直接扩容。

## MSE 诊断接口（暂缓）

当前诊断只有资源/场景/曝光数据和通道预览，没有参考图生命周期。MSE 需要明确比较对象；
曾讨论与固定视角的离线收敛图比较或显示明确标注的帧间 MSE；用户现已暂缓此项，尚未接入运行时计算。

建议质量指标采用曝光、tone mapping、UI 之前的线性 Rec.2020 RGB：
`MSE = sum_pixels(sum_RGB((image - reference)^2)) / (3 * width * height)`。
原始与重建后误差应分开标注。高动态范围亮点对绝对 MSE 影响很大，可以另报归一化指标，但
不能将它冒充原始 MSE。NaN/Inf 应显式报告，不能忽略像素后给出看似更好的分数。

参考必须匹配相机、场景/时间、内部 extent 和材质/积分模型。Lambert 对 OpenPBR 离线图的误差
包含模型差异，不能据此判断其采样器质量。相邻帧 MSE 包含运动、抖动、动态光照与采样变化，
只能作为时间稳定性指标；没有重投影/静止门禁时更不能解释为纯噪声。

实现应挂在现有 frame submission 的诊断边界：只在 rendererDiagnostics 启用且参考有效时记录
独立 GPU reduction，异步读回小量统计，禁用时不 dispatch、不读回、不保留全尺寸诊断图。
无需给生产 trace/shade 增加计数器、分支或原子操作；不能为诊断阻塞等 GPU。

## 后续性价比排序

先采同场景、相同内部 extent、相同频率条件下的阶段时间、live/allocated registers、spill 和跨
TraceRay 状态，再决定是否拆更多阶段。过去不同场景 CSV 不能用于这次 A/B。深层有效反射还应
看按 bounce 的存活路径数与非零贡献，不用 DI 质量已经足够的场景为 ReSTIR 增加成本。

树仍值得保留：全局功率 alias 会忽视距离，有限近邻会截断远光支持。可进一步按 world/local
显式特化访问，缩小候选加载；正向和反向共用概率数学，避免通用运行时 leafMode。

光源显存主要为约 `168 * emitter数量 + 3072 * 独立分布数量` 每 cluster；不是每个 emitter 都
独占 3 KiB。GPU 分布仍未跨 cluster 去重，有必要先统计重复率，再评估固定表共享。矩形灯合并
可以减少 emitter/树，但要保持纹理、法线、发光与精确目标身份。暂不提前优化编码。

独立积分脚本 tools/analyze_light_sampling.py 保留为历史分析工具，既不参与生产，也不构成保留
投影采样的建议。其理想模型不包含真实遮挡、树、材质、STBN 与降噪；用户实测决定了本次策略。
