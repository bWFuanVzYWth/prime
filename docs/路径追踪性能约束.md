# 路径追踪性能约束

本文件维护已采用的性能结构和容易回退的边界。采集时间、逐轮指令表、临时日志路径和
未采用方案不作为当前设计。源码可见性首先遵守[生产 Shader 编译边界契约](生产Shader编译边界契约.md)。

## 状态生命周期

持久 GPU record 与消费端临时类型分开。每个阶段按需读取字段，不能先加载完整
PathState、SurfaceInteraction、guide、介质和灯光再依赖 Slang 删除无用成员。
互斥状态可以复用存储，仍同时活跃的身份、guide 或前一顶点 MIS 数据不能覆盖。

完整 landing / secondary scatter 的普通和透明命中共用一个 BSDF 采样调用点，避免
重复展开；noisy RGB、guide 和 PSR 在采样后才加载。guide 已完成时仅更新需要的距离
lane，不读写整套 RGB/PSR。普通路径吸收后不更新距离、透明路径吸收后仍更新距离的
语义保持独立；首透明距离在所有新 guide 消费前保持 f32，不经 FP16 图像回读。

surface_split 在初始化结束后统一发布 resolve / guide；互斥两支向同一 steady queue
最多发布一次。该阶段没有 trace / reorder，可以使用 subgroup 合并。

## 候选解析

any-hit 的成本包括驱动遍历上下文、payload/attributes，以及应用提前读取的数据。
raygen 的跨 trace 保存字节不能解释为 any-hit 的全部状态，工具也不直接列出驱动每个
寄存器的来源。

应用侧顺序固定为：精确 source/target 身份 → geometry/relation 分类 → 必需 header →
coverage 的纹理与 UV → 确有投影需求时才取 BLAS 几何。备用材质仅在被选中后加载；
切换备用材质时使旧 alpha 缓存失效。常量或普通重心 UV 不引入投影几何重建。

持久 PrimitiveRecord 为 32 B，候选可用 16 B 句柄按组读取 header/UV。class 2 relation
提供精确快速退出；无 coverage 工作的候选不读 UV/顶点。相机无 source 时尊重几何
opaque 标志；有 source 时保留精确端点检查。所有优化仍使用 BLAS f32 顶点、硬件重心
和完整身份，不能恢复 epsilon、宽泛图元忽略或不安全的逻辑短路。

## SER 与 subgroup

轻量 SER 将 12 B traversal 请求与 96 B shading 输出分开，后者在遍历返回后初始化。
camera / guide 只使用 HitObject，深层 trace 额外按 hit object、geometry 与 instance
提示重排。提示中的截断位仅影响分组，不能成为几何身份。SER 只能整理遍历后的工作，
不能消除已经执行的 any-hit 发散。

**HitObject/SER 后的 Lambert camera 入队使用逐 invocation 原子操作。** 同一路径使用
subgroup ballot/elect/broadcast/prefix 合并会触发 device lost；取消显式 reorder 或
恢复宽 payload 都不能替代此规避。HitObjectTrace 本身允许 invocation repack，见
[Vulkan 光追执行模型](https://docs.vulkan.org/spec/latest/chapters/raytracing.html)。
不将其归因到未经证明的具体编译器或驱动缺陷。

完整实时的 post-trace appender 同样在 SER 变体选择标量。未包含该追踪组合的
surface_split、scatter 以及轻量 first / shade 保留既有 subgroup 产物。安全性必须按
实际 entry 验证，不能以“函数在 trace 后重新取 lane”证明整个 subgroup 序列正确。

生产 SPIR-V 门禁检查 camera SER 无上述合并指令、camera subgroup 与 shade subgroup
保留合并。GPU 行为测试覆盖实际生产 trace helper、分歧循环、hit/miss、身份、BLAS
压缩与追踪后唯一发布；独立 payload 小测试通过不能代替生产组合与游戏场景回归。

## 队列与持久存储

每条输入照明路径最多发布一个后继，容量与所有者对应；包括终止 lane 在内的参与者
统一到达 subgroup 追加点并使用同一 queue。最后消费者清理已消费队列宽度，不能依赖
可能因空队列而不执行的下一次 trace。精确调度与 alias 分别由完整、轻量文档维护。

前置无 RR delta 窄 megakernel 只处理离散链，主体全程 wavefront。没有 tail，也不把
求交、灯光、BSDF 和 RR 重新合进一个宽循环。新增阶段必须同时核算 dispatch、barrier、
中间读写与显存，不能只比较局部寄存器峰值。

## 测量口径

- 以同场景、视角、内部/显示分辨率、设置和设备的降噪前 GPU 时间为主要指标；频率、
  热状态与历史积累条件要记录。不同场景或模型的 samples 百分比不能直接计算加速。
- allocated registers、peak live、occupancy、active threads、spill 和跨调用保存量分别
  报告；RT Live 多 context 聚合值不是单条射线同时携带的字节。
- 有效 SPIR-V 指令统计排除 NonSemantic 与行号；规模下降不等于每条路径少执行同样
  比例的指令，也不能换算为物理寄存器或帧率。
- local-memory、long scoreboard 和低 active threads 可能涉及不同成本。必须用实际
  内存流量、生命周期和阶段样本归因，不能仅凭这些指标断言严重 spill。
- 先完成相关行为/ABI 门禁，再看同时间重建稳定性。功能受限的 Lambert 基线不能作为
  完整 OpenPBR 的图像真值。

场景上传、AS 构建、压缩和 CPU 分配另按[场景资源生命周期](场景资源生命周期.md)归因，
主线程等待 GPU semaphore 不能单独定位耗时阶段。
