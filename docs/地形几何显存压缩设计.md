# 地形几何显存压缩设计

静态地形从 BLAS 获取权威顶点，以跨 cluster 的全局 SurfaceKey 表复用着色记录。
与逻辑图元线性增长的常驻数据只保留 4 B key；去重表采用固定 32 B 元素直接索引，避免
变长编码与多级跳转。动态运动数据、发光采样几何和 AS 自身使用各自的生命周期。

本设计服从[渲染核心数据 IR](渲染核心数据IR.md)和
[GPU 几何追踪精度契约](GPU几何追踪精度契约.md)。字段、位分配和 descriptor 的权威定义
是 `shaders/abi.json`；本文解释它们的用途与成本。

## Position fetch 与位置退休

`VK_KHR_ray_tracing_position_fetch` 及对应 feature 是强制设备需求。BLAS 查询尺寸和
实际构建都使用允许 data access 的标志；不能只在其中一步启用。geometry transform 为
null，实例变换单独应用。GPU 以提交给 BLAS 的 f32 三角形顶点和硬件重心坐标重建命中，
不使用射线算术命中点、固定 epsilon 或截断源/目标身份替代。

所有静态输入位置在最后一次 GPU 构建读取完成后都可退休，不必等到 compaction 完成。
这包括非矩形、流体斜面、cutout、带关系与发光的三角形；形状不规则本身不要求保留第二份
着色顶点。压缩前后的 BLAS 都必须支持相同的 fetch 行为。

动态几何仍保留当前与上一帧位置以支持运动重建。面积灯的采样几何也有独立用途，不能因
静态 shading 顶点退休而删除。上传和构建中的临时输入不计入最终常驻表，但必须计入峰值。

## 逻辑图元与 SurfaceKey

硬件三角形数 H、宏矩形数 R 和其他逻辑三角形数 T 满足：

```text
H = 2R + T
P = R + T
```

P 是需要 key 的逻辑图元数。宏矩形的两张硬件三角形共用一个 key；局部半面从
`(PrimitiveIndex - macroBase) & 1` 恢复，不能假定全局 primitive index 的奇偶表示半面。
没有额外 8 B 矩形几何记录。

每个 key 是完整 u32，直接索引固定 32 B `PrimitiveRecord` 数组。静态实例通过独立标志
选择 key 布局，不占用 key 的高位。材质记录独立存储，动态图元继续直接读取 32 B 记录。

Minecraft 中可合并矩形占比高，这体现在 P/H 上；非矩形继续使用同一规范记录，不引入
稀有三角形回退链。水、发光或带关系的面是否能合并，取决于精确的几何与语义条件，不能
仅因外观近似矩形就丢失独立身份。

## 跨 cluster 去重

`SurfaceRecords` 对最终 32 B 记录逐位精确 intern。材质、关系和 emitter 等 payload
完成翻译后才能参与比较，不对浮点字段做容差合并，也不按 cluster 建重复表。

记录中的 cluster-local 关系或 emitter payload 仍由当前 section 上下文解释。相同 key
只表示记录相同，不表示两处世界几何是同一表面。SurfaceKey 不替代源/目标图元身份、
`MediumId`、`TextureId` 或 section/instance 身份；阴影、自交、MIS 和运动必须继续读取
各自的精确身份。

固定数组允许一次地址计算后窄加载所需字段。表的元素大小优先服务消费效率，压缩重点
是 P 个重复引用与可退休的位置，而不是为小表引入变长格式或多级索引。

## 槽位与 GPU 生命周期

render thread 是全局表的唯一可变所有者。一个 BLAS/prototype 对其唯一 key 集合持有
lease，不按每次 shader 读取计数；最后一个 lease 释放且 GPU 引用退休后，槽位才进入
free list。GPU 完成回调只投递退休通知，由 render thread 排空。

活 key 在生命周期内稳定。释放留下的空洞可复用，不移动活记录来压实数组，也不因资源
reload 重编号仍存活的 key。这里的 SurfaceKey 空槽复用不改变 TextureId 单调且不复用的
独立契约。

GPU 表按容量增长，不预分配整个 u32 地址空间。扩容保留已有索引，新表完整上传后才发布
新 descriptor；旧帧继续引用旧表并延迟退休。脏槽合并为有界连续上传区间，不能为了减少
提交覆盖仍未退休的数据。容量、设备 `maxStorageBufferRange` 和地址计算在 host 边界
验证，字节偏移使用不会被 u32 元素数乘法截断的宽度。

## 显存模型

对 P 个静态逻辑图元、C 个全局表槽，着色记录常驻成本为：

```text
4P + 32C bytes
```

C 包含尚未复用的孔洞和数组容量余量。该式不含 BLAS、OMM、关系、灯光、动态位置、TLAS、
allocator 对齐或构建暂存；不能把它当作整个场景显存。诊断分别报告 live/slots、table、
static keys、static BLAS、未压缩 backing 和压缩目标预留，区分压缩收益与退休滞后。

静态位置退休的显存收益允许伴随少量 position-fetch 帧时间代价；帧率仍需同场景测量，
不能从字节数推断。上传和 compaction 的预算与所有权见
[场景资源生命周期](场景资源生命周期.md)。

## 验证

真实 RT 测试覆盖实例变换、硬件重心、宏面两半、非矩形、源/目标身份、自交以及 BLAS
压缩前后 fetch。host 行为测试覆盖跨 cluster intern、lease 共享与释放、孔洞复用、扩容、
旧 GPU 引用退休和失败回滚。整数身份逐位检查，连续误差按几何与核心 IR 门禁验收。
