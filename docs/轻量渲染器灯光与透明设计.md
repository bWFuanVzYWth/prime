# 轻量渲染器：灯光与首面反射

2026-09-06，按用户确认的设计完成实现；[首版基线](轻量路径追踪首版.md)保留为历史对照。
代码与 GPU 数学门禁已接入，游戏内重建和性能验收仍待实测。
用户的新定位是性能优先、效果克制、正常游玩不受影响：透明固定为 delta，其余固定 Lambert，
补齐灯光与透明；不要求物理折射，只保留首 delta 接口反射，后续透明直线透过并滤色。
用户随后补充采样预算：只有首个主表面同时采太阳和方块灯，后续表面只采太阳，减少灯光树查询。
架构按最新要求采用无 RR 的前置 delta 窄 megakernel、Lambert 主体 wavefront；不恢复 tail。
复用额外镜面、最小、最大反弹三个设置，现有硬编码 12 次上限退出运行时轮数控制。

用户已确认“首接口”是**相机直接命中的第一个可见表面**：若它透明，允许一次镜面反射；
若它不透明，整条后续路径不再产生镜面反射。本文不是 OpenPBR
等价实现，也不修改完整实时、离线的材质模型或采样策略。

## 推荐的最小范围

| 项目 | 本轮目标 | 明确舍弃 |
| --- | --- | --- |
| 普通表面 | 规范线性 Rec.2020 颜色、tint、几何法线、双面 Lambert | 金属 / 粗糙高光、SSS、完整 PBR |
| 覆盖 | 保留 alpha cutout、玻璃装饰边框与几何 / 材质身份 | 不能把所有带 alpha 的对象当玻璃 |
| 灯光 | 可见自发光、每层太阳 NEE、仅首接收面方块灯 NEE、天空 / 星图、Lambert 多次反弹 | ReSTIR、投影取点、深层选灯、额外近远灯策略 |
| 透明 | 水 / 玻璃可见，首接口理想镜面 + 直通，其余界面只有直通与吸收 | Snell 折射、TIR、焦散、镜中镜、透明粗糙散射 |
| 重建 | 原有 Noisy / NRD / DLSS RR / FSR 输出；透明双 guide、单光照路径 | 为省 guide 而让身份随随机选枝改变 |
| 大气 | 共享摄像机位置近似与现有方向 LUT、曝光、显示链路 | 新的大气散射积分或光柱效果 |

这里的“灯光”同时包含看到灯和灯照亮周围。仅输出亮纹理不能解决夜间室内、洞穴、火把和
红石照明。发光是附加属性，不需要第三种 BSDF。沿用现有 catalog 中的发光强度、动画支持域
与真实 Le 求值，不用树中的功率代替 radiance，也不额外重复乘一次距离平方衰减。
动态对象中仅有可见发光、没有注册为 area emitter 的部分仍按现有事实处理，不能宣称已经
提供手持动态光源或任意粒子的 NEE。

金属在此模式中也按底色显示成 Lambert。这符合用户定位；不要为了少数金属额外引入
OpenPBR。现有 `x^1.04` 底色补偿用于补偿完整模型的观感，不自动施加到没有这层高光的 Lambert。
普通法线贴图、水面波纹、体积水雾可在基础验收后单独评估，不作为本轮前置能力。
岩浆保持发光 Lambert，不能因为它是流体就归为可透过的水。手持物、粒子 / 文本、方块
描边、UI，以及已有的水下和玩家视觉状态适配，作为正常游玩的集成回归范围；模型简化
不能顺便删掉它们。此项不宣称当前已支持所有原版视觉效果。

## 灯光：首面双族，深层只采太阳

“首主表面”在调度中定义为相机所选照明分支遇到的**第一个 Lambert 接收面**。透过玻璃
或经首面反射看到的接收面也包括在内；透明接口本身没有 Lambert NEE。guide-only 分支
始终不采灯。因此每像素仍至多执行一次方块灯树选择，不因补反射 guide 变成两次。

| 接收面 | 太阳 NEE | 方块灯 NEE | 延续 |
| --- | --- | --- | --- |
| 第一个 Lambert 接收面 | 1 个样本 | 1 个样本 | 余弦半球 + 线性 RR |
| 后续 Lambert 接收面 | 1 个样本 | 不调用灯光树 | 余弦半球 + 线性 RR |
| delta / 直通接口、guide-only | 无 | 无 | 按透明 / guide 规则 |

每个顶点先结算其直达项，再按反弹预算采样余弦半球；达到最小轮数后才对后续照明执行 RR。
没有灯、接收余弦为零等可证明零贡献
情况直接跳过。首接收面的两种光顺序完成，不同时保存两套样本。方块灯复用两级树、纹理
面积分布、精确 emitter 身份和实际发光求值。

在本模型中，Lambert 之后只有 Lambert 和不改变方向的滤色，没有会弯折方向的镜面链。
因此可以将首 Lambert 接收面到注册灯面的全部直达项交给 NEE：

`Ld = beta * albedo / pi * Le(y) * T(x,y) * max(dot(n,wi),0) / pOmega(y)`。

只要 proposal 覆盖所有非零贡献灯点，且 NEE 与实际穿越使用相同滤色 / 可见性模型，
这已经是该直达积分的完整估计；不再叠加余弦方向偶然撞到同一灯面的 Le。这里是对
**受限模型**的估计器划分，不是对物理折射 PT 的等价变换；反弹截断另有明确偏差。

| 抵达灯 / 太阳圆盘的路径 | 是否累计其自发光 / 圆盘 |
| --- | --- |
| 相机直视，允许中间直通滤色 | 是 |
| 首相机透明接口反射，此后尚未发生 Lambert | 是，否则水中灯与太阳倒影会消失 |
| 首 Lambert 散射后，未经过第二个 Lambert 就命中注册方块灯 | 否，由首接收面的 NEE 负责；中途直通玻璃不改变归属 |
| 已经过至少两次 Lambert 散射，再命中注册方块灯 | 是，上一个接收面没有方块灯 NEE |
| Lambert 后逃逸到太阳圆盘 | 否，延续当前太阳独占 NEE 规则 |
| Lambert 后命中未纳入灯表的可见发光 | 是，没有竞争 NEE，不能把它误删 |
| Lambert 后到天空 / 星图 | 是，二者仍由延续方向采样 |

“由 NEE 负责”是可执行采样域的归属，**不取决于本次是否抽到该灯、是否被挡或最终样本
是否非零**。命中注册灯时，只有上一接收面拥有对应 NEE 的情况下才省略 Le，不跳过灯面
作为 Lambert 接收面的后续反射。尤其不能看到“当前已是第二个面”就恢复 Le：首接收面
直接照到第二个灯面的项已经在首面 NEE 中计算过。

实现只需“上一 Lambert 接收面是否拥有 area NEE”这一控制位：首接收面发布后继时置位，
下一接收面先消费 emission 归属，再在发布自己的后继时清零；直通不修改它。另一个
“是否已经过 Lambert”标志控制太阳圆盘归属。也可从精确的 Lambert 深度导出，不能拿
包含首镜面反射的总反弹数直接替代。若新增了 Lambert 之后的反射 / 折射，本节支持域
证明立即失效，必须重新设计。

收益是无需 previous BSDF PDF、previous light receiver normal / position 和 emissive-hit
反向树 PDF；只需紧凑的光源归属控制。也避免部分“余弦方向偶然撞亮灯”的样本。
它不能消除小 PMF 的 NEE 样本、深层 RR 和弱分支的所有萤火虫。

代价分两部分：首面近处大灯可能放弃余弦采样的方差优势；深层小灯则只能靠余弦延续
偶然命中，稀疏亮点、间接照明噪声可能增加。**没有删除深层方块光的传输项**，在采样支持
与滤色一致的前提下，改变的是方差和成本；短时间重建仍可能显得更暗或反应更慢。
不能把省掉深层灯光树查询描述为普遍改善萤火虫。

用户此前实测近大灯已易于降噪，并明确接受这一采样质量简化，因此先按上述固定策略设计，
不另增距离阈值、深度概率或补偿环境光。验收重点增加“方块灯只能经一次漫反射才照到的
暗角”和动态小灯的深层响应，以同渲染时间下的运动稳定性判断性价比。

## 透明的显式外观模型

首可见透明接口的目标为：

`L = F * Lreflection + (1-F) * Lstraight`。

`Lreflection` 和 `Lstraight` 各自在后续段中包含有色吸收。反射方向使用面向入射侧的
几何法线作一次理想镜面反射；直通方向原样保持。默认建议固定水 F0=0.02、玻璃 F0=0.04，
使用 `F = F0 + (1-F0)*(1-abs(dot(n,wi)))^5`。这是本模式的外观近似，不调用 OpenPBR
Fresnel / 微表面 / 层叠闭包，不携带 etaScale，也不产生全反射。

其余透明接口不再计算反射、不损耗一份未输出的 Fresnel 能量，只改变段吸收与介质归属。
这避免多个窗面因为重复扣除反射而无故发黑。忽略的反射相当于在该模式中归入直通，
每段仍满足 `0 <= T.rgb <= 1`，首接口满足 `R + T <= 1`。这不保证全局互易或物理正确的
介质光传输；它保证不靠叠加满强度反射与满强度透射凭空增亮。

首反射资格永不恢复：反射中再看到水 / 玻璃也只直通；普通墙面 GI 中遇到水面也不反射。
相应焦散和多重倒影是有意舍弃的画面效果。首反射保持场景空间追踪，不能改成只取屏幕内
颜色或只反射天空，否则墙后灯光、视野外物体与室内水面会出现明显缺失。

### 仍需处理的基础语义

1. **Cutout 不等于透明介质。** 树叶、栅栏洞、粒子、文本先按 coverage 决定有无表面，
   命中的可见部分仍是 Lambert。玻璃纹理的可见装饰边框按现有分类成为 Lambert，不能
   因忽略 PBR 粗糙度而把窗框也一起穿透。只将规范材质翻译已确认的透明部分归入 delta。
2. **吸收不能按三角面次数计算。** 实体水 / 染色玻璃按真实介质段长
   `T=exp(-sigma*distance)`；薄片按一次明确的参考厚度结算。沿用规范拓扑、内部面消除
   与相邻介质端点。同一物体入口和出口不是两次完整染色，重新三角化不能改变颜色。
3. **初始介质不能漏掉。** 摄像机在水下时，第一段就有水吸收；跨越浅水表面、玻璃接水、
   光线从吸收介质内指向灯时都要一致。可利用现有按 fluid height 判断的摄像机水状态。
   若所支持几何需要嵌套介质，保留最小的精确 medium 身份 / 边界状态，不能把它默认为空气。
4. **阴影也要直通滤色。** 太阳与方块灯都使用同一吸收函数。仅让相机透过玻璃，却让 NEE
   将它当墙，会使玻璃房和水下过暗；完全忽略阴影滤色则会漏掉染色。
5. **透明事件与 Lambert 轮数分开。** 前置首反射和直通消耗 delta 链预算，不占 Lambert
   轮数，也不做 RR；后续直通同样不占 Lambert 轮数。三个设置与端点处理见下一节，
   不再使用合计 12 次散射的旧提案，也不因窗口层数减少 GI 阶数。

固体吸收系数来自规范材质 / 关系数据，优先复用已有采样与翻译结果。消费端只加载类型、
滤色、必要 medium ID；不为它构造完整材质、IOR 栈或 BSDF。若移动计算到查表，需要显式
包含 tint、参考 UV 和动画 generation 依赖，不能错误地只按 MaterialId 缓存一种颜色。
不以此次设计为由新建全量纹理镜像或扩大三角面记录。

首版建议保留吸收但不添加体积散射。水的可辨识性先靠首面反射、深度吸收、轮廓与既有
显示 / 大气功能验收；“不折射”不等于“水成为完全无色的空气”。

## 反弹设置与终止语义

复用现有配置字段、取值范围和默认值。完整实时实现已经在 landing 后重新开始常规计数，
把前置 delta 链排除在常规最大反弹数之外；轻量版沿用这层分离，不复制完整模型的材质分派。
代码依据为 `BounceSettings`、`RealtimeRayTracingPipeline.recordTransport`、
`transport/realtime/delta_walk.slang` 和 `transport/realtime/landing_publish.slang`。

| 设置 | 范围 / 默认 | 轻量版语义 |
| --- | --- | --- |
| 额外镜面反弹次数 `D` | 1–64 / 16 | 前置 delta 链最多执行的透明事件数，首接口反射或直通均算 1 次；仅首接口有反射资格 |
| 最小反弹次数 `M` | 1–8 / 2 | 包含首 Lambert 接收面的无 RR 照明轮数；到达这些轮次之前不因 RR 终止 |
| 最大反弹次数 `B` | 1–64 / 16 | Lambert 照明轮数的配置上限；沿用实时最小值优先规则，实际上限 `K = max(M, B)` |

默认是至多 16 次前置透明事件，随后最多 16 轮 Lambert，其中前 2 轮保证不被 RR 提前截断。
minimum 的保证不包括 miss、零 throughput、阻挡或配置的透明穿越截断。`D=1` 仍允许首接口
事件后的落点查询：落到 Lambert 或天空就正常交接；只有需要处理第二个透明接口才超限。
guide 从相同的首事件计数起步，不能因为未计算照明而多穿一层。

前置链不消耗 `M` / `B`；首面反射后仍有首 Lambert 的双族 NEE 和完整 Lambert 预算。
只有完成 Lambert 散射才增加常规计数，后续直通不会增加该计数、重置 RR 或恢复首面选灯。
为避免另增一个隐藏的 64 接口常量，轻量版建议同时用 `D` 限制每条后续直通段及 NEE 连接的
透明事件数，各段从 0 开始。这是该模式对额外镜面设置的明确扩展，应在模式说明中写明；
相机、guide、BSDF 延续和 NEE 使用相同穿越计数规则，coverage 拒绝的候选不算透明事件。
NEE 与 BSDF 必须对同一连接得到相同的超限可见性，避免独占 NEE 的支持域出现缺口。

第 `j` 个 Lambert 接收面先结算 emission 与 NEE。若 `j < M`，后继不做 RR；
若 `M <= j < K`，仅在发布通往下一轮的后继时执行一次现有线性 RR。进入下个 trace 或 shade
不能重复 RR。概率依据乘入本次 albedo 后的真实 throughput，包含首选枝补偿与段吸收；
不使用去调制补偿，也没有折射 etaScale。

保持当前 Lambert 的终点约定：完成第 `K` 次散射后允许一次终点查询，穿过本段透明后仅结算
环境或按上一顶点归属允许的 emission，并补必要 hit distance；不在落点执行第 `K+1` 轮 NEE
或散射。这次终点查询不再额外做 RR。它是有限阶传输的收尾，不是 tail，也不能由端点重新
发布照明后继；仅含环境 / emission 的源码入口不导入灯光树。`K=1` 时仍能完成首面双 NEE
和散射后的端点 / 距离，不能因关掉后续 GI 就破坏重建通道。

穿越结果显式区分 Lambert / blocker、miss 和配置预算耗尽。允许做完第 `D` 次透明事件后
查询落点，但不能处理第 `D+1` 个透明接口。超限截断剩余辐射，guide 标记未到达有效接收面，
保留可见接口 fallback；不伪造天空、无阻挡或有效远距离。这是透明工作预算引入的显式偏差，
与常规反弹截断分别验收；正常玻璃场景若经常触及默认预算，需要调整策略。

host 调度、shader 停止条件和诊断 pass count 必须来自同一帧的 `M / B / D` 快照。
`lambertContract.maximumBounces=12`、对应生成常量、host 固定循环以及测试中的固定轮数
一起退出运行时合同，不残留 `min(B, 12)`。现有公共 ABI 的 128 是编码容量，产品合法上限
仍是 64，不能拿容量常量决定每帧轮数。三个配置已有 renderer revision 通路；接入时验证
切换配置后历史正确失效，且 host / shader 看见同一配置。更新选项说明以分别描述完整实时的
tail 和轻量版的 wavefront，不把所有实时模式都标成带 tail。

## 单光照路径、稳定双 guide

延续已经验收的 STBN 等概率策略：首接口两项非零时以 1/2 选择一条照明路径，反射权重
为 `2F`，直通权重为 `2(1-F)`，滤色继续作用于实际段。恰好零权重的分支不抽样。
这是选择概率的补偿，不能乘到 guide albedo 上，也不能在 resolve 再乘一次 F。

不采用 Fresnel 概率作为首版默认：法线视角的水反射只会有约 2% 采样，容易重新出现移动
模糊；1/2 与既有实测一致，逆选枝概率也固定不超过 2。RR 按上一节的最小轮数延后，
只在 Lambert 本顶点光照结算后决定后继存活；前置照明 delta 链和 guide 链都不做 RR。
不为弱反射恢复去调制 RR。

未选分支只追 guide，不采灯、不散射、不做 RR、不算照明。选中分支提供另一组 guide 后
继续唯一完整路径。没有后续随机 delta 分歧，因而不需要旧实现的通用 detached-guide
状态机、反射链矩阵栈、TIR 分派和变换 Jacobian；反射只需一个镜面平面的 PSR。

| 数据 | 所有者与语义 |
| --- | --- |
| 可见透明接口 | 屏幕覆盖、最终显示 depth / motion、接口法线、反射率 |
| 直通替代表面 | 玻璃 / 水后第一个 Lambert 接收面或天空；稳定主 guide |
| 反射替代表面 | 一次反射后、允许直通透明的首个 Lambert 接收面或天空；反射 guide |
| 两路照明 | 固定通道归属，未选分支当帧样本为零但 guide 仍有效；不随选枝互换主表面 |
| 距离 | 相机到接口、接口到替代表面、替代表面散射后首段 hit distance 分开表达 |

NRD 两组 history 跟随各自接收面 / 虚拟接收面，不能因为材料只有 Lambert 就把首镜面结果
混入同一普通 diffuse 历史。镜中接收面的 Lambert 照明，在 NRD 反射层中仍按该接收面的
性质组织；“经过首镜面”不意味着把所有输出粗略塞入单个 specular 图像。
PSR 的位置、法线、方向和 motion 必须一起变换；hit distance 从替代表面之后的散射段开始，
不是从相机累计到反射目标。见 [NRD 固定版本 PSR 说明](https://github.com/NVIDIA-RTX/NRD/blob/9a3fe938a7558fd16b6c91a1c0456305cdcd9f16/README.md#interaction-with-primary-surface-replacements)。

DLSS 保留已验收的主 guide + 反射 hit distance，显式 reflection MV 仍不提交。有效直通
接收面作为主 guide 时，接口 specular albedo 不能被接收面值覆盖。DLSS 的单主表面不能
完整描述同像素两套几何，此限制不会因没有折射而消失。见 [DLSS RR 输入契约](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_RR.md#41-buffers-to-tag)。

即使主面是 Lambert，其太阳阴影也可能穿过染色玻璃。当前 sunLighting 的阴影输出只有
一位可见性，接入滤色时需将 `未遮挡太阳贡献 * RGB透射率` 写入 RGB，另存不透明遮挡
的 visibility，不能把透射率压成布尔值。这保持普通主表面的 SIGMA 组织与 Noisy 的正确
组合，但 SIGMA 仍只重建遮挡，不会重建 RGB 滤光本身；首版接受与共享路径类似的局限，
必须测量彩色阴影边界的运动稳定性。若明显不够，再比较整份太阳项走 noisy diffuse 的
方案，不能按本次是否碰巧采到玻璃临时改变信号归属。

首可见透明接口两路的太阳按各自
已遮挡、已滤色的 noisy 层输出，不能把接口的一份 SIGMA 套到反射目标或对已遮挡贡献再乘
一次。此前 NRD 高光漏光的经验意味着这部分必须单独做阴影边界的运动验收。
稀疏选枝得到的镜面天空 / 发光也不能被误标为每帧确定的 stableRadiance。

## 调度与寄存器边界

总体采用“**前置无 RR 的 delta 窄 megakernel + 全程 wavefront 的 Lambert 主体**”。
主光线的 delta 链在一次 raygen invocation 内连续 TraceRay 和直通 / 吸收，不逐接口排队。
用户已有经验是这一阶段发散轻微，融合通常优于逐接口 wavefront；此次以此作为架构依据，
实际增量仍测量寄存器和 GPU 时间，不预先声明固定加速比。Lambert 主体维持 trace → shade
的粗粒度，不恢复已暂缓的 area / sun / BSDF 独立调度，也不在最小轮数后切换 tail。

```text
相机 + 前置 delta 窄 megakernel（无 RR，至多首接口反射一次）
    → 未选分支的 guide-only 窄 megakernel（仅透明相机像素，无 RR）
    → 首 Lambert shade（太阳 + 方块灯；结算后按 M 决定后继 RR）
    → 最多 K-1 轮：trace + 直通窄循环 → 后续 Lambert shade（仅太阳；按 M 做 RR）
    → 最终端点 trace / emission / 环境结算
    → resolve / 重建输入
```

调度中的前置 kernel 只处理相机可见接口分类、一次首选枝及 delta 链；遇 Lambert 立即交接
命中数据，遇 miss 交给环境结算。它不调用 Lambert shade、NEE 或天空 LUT，不把落点光照
嵌入循环。普通不透明相机像素只做一次命中与交接，没有透明循环的迭代工作。

| 路径阶段 | 允许工作 | 唯一前进方向 |
| --- | --- | --- |
| 相机首接口 | coverage / 分类；若透明则首反射或直通选枝 | 前置直通链或首 Lambert |
| 前置链 | 只直通、滤色和更新介质；无 RR | 首 Lambert、miss 或预算耗尽 |
| 首 Lambert | 双族 NEE、余弦散射；消费首面选灯资格 | 后续 trace 或结束 |
| 后续 trace | 最近命中与透明直通；无反射、无 RR | 后续 Lambert、miss 或预算耗尽 |
| 后续 Lambert | 仅太阳 NEE、余弦散射与有条件 RR | 后续 trace 或最终端点 |
| 最终端点 | 直通、emission / 环境和必要距离 | 结束 |

这个状态机从结构上排除了前置 kernel 中的普通材质算法，以及后续链上的再次反射。
“命中分类可识别 Lambert”不等于“该 kernel 可以着色 Lambert”。phase 控制位用于持久状态
与队列归属，shader entry 仍分开；不能用一个运行时 phase 分支重新包含所有阶段的闭包。

| 编译范围 | 应包含 | 不应包含 |
| --- | --- | --- |
| 最近命中与分类 | 权威几何、coverage、窄材质与 emission / filter 所需字段 | 光源树、太阳 LUT、OpenPBR |
| 前置 delta megakernel | 最近接口、直通吸收、至多一次首反射、精确身份 | RR、NEE、Lambert evaluate、通用 PSR 链 |
| 后续 trace / 直通 walk | 最近接口、直通吸收、Lambert 落点或 miss | 首反射选枝、RR、NEE、材质散射 |
| guide-only walk | 同一几何穿越、两个接收面的必要属性、一次反射的虚拟几何 | 光照、RR、完整 transport 状态 |
| 首 Lambert shade | area NEE → 结算；sun NEE → 结算；余弦散射与线性 RR | 反向 light PDF、OpenPBR、后端 guide 构造 |
| 后续 Lambert shade | sun NEE → 结算；余弦散射与线性 RR | 光源树、area 取点 / PDF、OpenPBR、后端 guide 构造 |
| 终点结算 | emission 归属、环境、最终距离 | NEE、余弦散射、RR、照明后继发布 |
| resolve / 后端准备 | 信号路由、去调制 / 重调制、后端约定 | 灯光遍历、材质散射算法 |

建议先用**有序最近命中**完成主路径与 guide 的直通，透明交点返回窄 raygen walk 后处理；
any-hit 继续只承担精确源 / 目标身份与 coverage。不能在普通最近命中查询中对所有透明
any-hit 无条件累乘颜色：Vulkan 不保证候选按距离顺序执行，最终最近墙面后方的玻璃可能
已被访问，最终颜色就会受到墙后的物体影响。
候选顺序的规范依据见 [Khronos Ray Traversal](https://docs.vulkan.org/spec/latest/chapters/raytraversal.html)。

轻量阴影也先用窄的最近命中穿越，遇普通遮挡立即返回；遇透明才继续本段。普通不透明
阴影仍只需要一次查询。它会使多层透明阴影多做几次 TraceRay，因此要单独测量玻璃密集
场景；若代价高，再评估旧阴影的无序光学矩累积叶函数。不能直接导入包含完整栈、颜色
转换和旧策略开关的宽 shadow adapter，并期待编译器自动缩窄。

主光照 / guide 的有序穿越还避免为不折射模型保留任意深度的散射事件分派。穿越仍遵守
精确图元、BLAS 顶点与硬件重心契约，使用上一节的配置预算与终点规则。

首接口阶段保留原接口及随机选枝信息，把未选分支的窄 guide seed 写入暂存，然后在前置
kernel 内把选中路径推进到 Lambert / miss / 上限，一次性发布照明落点与选中 guide 数据。
独立 guide-only kernel 消费未选 seed，在一次 invocation 内走完对应直通链并发布 guide；
随后才进入首 Lambert shade。这个边界不随接口数增加 dispatch，也不让前置 kernel 跨
TraceRay 持有两条 ray、两套 medium 或重建输出结构。guide 只保存输出，不占第二条完整
路径；guide 队列只为首可见透明且需要补 guide 的像素填充。
没有必要为所有像素常驻两份宽 surface、两份光源样本或两条照明记录。是否能完全复用
现有 128 B 记录，须先列同时存活字段再落 ABI，
不能仅用“阶段互斥”覆盖仍需由 resolve 或另一路 guide 消费的数据。

首层与后续 shade 应是明确的编译边界：复用小型 Lambert / sun 数学叶，后续 entry 从源头
不导入灯光树和 area sampler，不能只在一个宽 shader 中写 `if (bounce == 0)` 然后指望
Slang 删除深层的无关数据。host 首轮与后续轮次选用各自 shader record / group 即可，
不为此增加主 wavefront 轮数或每 bounce 的 dispatch 数。首 delta walk 只负责把照明
路径交给首 Lambert shade，不因经过几个直通接口而切换到深层入口。
最小轮数只改变 Lambert shade 发布后继时是否执行 RR，不再决定调度架构。host 按 `K`
记录有界间接调度，空队列不启动 raygen；不逐轮 CPU 读回队列计数。相较完整实时的 tail，
轻量版 dispatch / barrier 数随 `K` 线性增长，空队列的命令开销也仍存在；需要分别记录
默认 16 与上限 64 的空队列尾部成本，不能把“纯 wavefront”当成没有调度代价。

首版性能目标如下，都是待测目标而非已实现数字：

- 方块灯 NEE 的主要新增成本是每个有效首 Lambert 接收点一次选灯，以及至多一次初始
  阴影查询；后续层数不再增加灯光树查询。若一条路径访问 k 个 Lambert 接收面，方块灯
  选择次数由逐层方案的 k 次降为 1 次，太阳仍为 k 次；这是调用预算，不是 GPU 加速比。
  多层透明会增加穿越查询。它不是免费功能，不预估固定 FPS 降幅。首反射只
  增加透明相机像素的 guide 工作，不把每个 bounce 的照明路径翻倍。
- 完整路径容量维持 N，后继队列不超过 N；以现有 128 B/path、136 B/像素传输缓冲为
  比较基线。新增重建图像、queue / guide 暂存和对齐必须另行完整计入预算。
- 材质字段按阶段读取；太阳 TraceRay 不跨越整份 AreaLightSample，阴影前不提前加载
  Lambert 后继、RR 与 guide 数据。滤色介质只保存精确身份和本段确实需要的量。
- 前置 delta 循环的持久寄存器仅保留当前 ray、精确 source 身份、throughput / 介质、
  紧凑控制与所需段距；原接口、未选 guide seed、已生成的 PSR / guide 输出按阶段落存。
  不能直接复用完整渲染器的宽 `PathState` / `SurfaceInteraction` / context，再依赖 Slang
  删除 PBR、IOR 栈、灯光或历史字段；命中 payload 也按实际消费者拆分。
- 普通非透明像素保持直接快速路径；delta-walk 不引入灯光树，普通阴影不加载玻璃色彩。
- 保留 subgroup 批量 append，继续使用原 STBN 表和 hash RR。方块灯占 bank 0/1、太阳
  bank 2 后，Lambert 方向必须分配独立地址域，不能继续与 area 共用原 bank 0 样本。
  可将每个 bounce 的 lighting / continuation 分成不同 vertex 地址，并保留首面选枝的
  vertex 0；验证完整 64 帧周期、分支、配置允许的 64 轮 Lambert、delta 与 epoch 域，
  不按旧 12 轮假定地址范围，也不声称地址不同就已经统计独立。
- 每一功能增量记录 shade、world / shadow any-hit、delta / guide 的 live / allocated、
  spill、occupancy、跨 TraceRay 状态及同场景 GPU 时间。不能把 SPIR-V 缩小等同于帧数提升。

## 实施顺序与验收

1. **先接配置预算、自发光与首面方块灯。** 保持现有 Lambert 场景，移除固定 12 上限，
   验证最小 / 最大轮数及线性 RR、首面独占 NEE / 深层命灯的归属、STBN 分域、
   远小灯 / 近大灯 / 墙后灯、动画 / tinted emitter，以及夜间洞穴与室内可玩性。
2. **接入前置无 RR megakernel 和直通滤色，暂不打开首反射。** 验证只在落点交接而不逐
   接口调度，再测水、透明玻璃、染色玻璃、玻璃板、相邻不同介质、
   摄像机水下、背后遮挡、多层窗户；主光线、NEE、guide 看到同一边界与段长。
3. **最后补一次首反射和双 guide。** 水中太阳与灯、视野外反射物、透过玻璃看移动实体、
   反射目标被遮挡 / 显露、玻璃后再见水与反射中再见玻璃；Noisy、NRD、DLSS 都验收。

数学 / 行为门禁覆盖：白炉中 R+T 的期望不增能、1/2 选枝补偿、不同三角化下相同段吸收、
等吸收介质分段的一致性、直通反向连接与灯采样的支持域、registered / unregistered emission
归属（特别是首面直达灯不重复、第二次 Lambert 散射后命灯不遗漏）、透明预算与 Lambert
轮数独立、相邻像素暂存边界、未选 guide 的稳定有效性。反弹门禁覆盖 `D=1` 的最后落点、
恰好 D / D+1 个透明事件、`M=B=1`、默认 2 / 16、`B<M`、`B=64`、终点没有额外 NEE、
RR 从正确边界开始且每个后继只做一次；用行为与编译产物验证配置生效和源码依赖，不能用
搜索源码是否包含某个数字代替测试。
重建验收必须包含运动与明暗交界，不用局部公式测试代替先前暴露过问题的完整画面回归。

本轮实现没有新的游戏内性能捕获。下列实现记录不替代上述场景验收；在灯光、透明、重建
均过关前，不扩展法线、金属、高阶镜面、ReSTIR 或材质编码。

## 实现记录

实际调度为 `camera → guide → first → (trace → shade) × (K−1) → trace → terminal → resolve`，
共 `2K+4` 条 RT dispatch：默认 K=16 为 36，上限 64 为 132。camera 内完成选中前置链；
guide 仅为首透明像素补未选分支。每次 trace 内走完自己的直通链，不按透明接口增加 dispatch。
三个队列容量均 N；间接命令为零的队列不启动 raygen，但命令 / barrier 本身仍有成本。

| 常驻传输数据 | 每像素字节 | 生命周期 |
| --- | ---: | --- |
| 单条照明记录 | 144 | camera 至 resolve |
| 首接口 / SH 复用暂存 | 48 | camera 写首接口；guide 完成后 first 改写后 32 B，resolve 读 SH |
| 两个照明队列 + 一个 guide 队列 | 12 | 各阶段发布、消费；无第二条照明路径 |
| 间接命令 | 全帧 48 | 三条 16 B 命令；queue 0 第四字保存 M / D |

总传输缓冲为 `align256(144N) + 60N + 48`，原始每像素成本 204 B；复用已有重建图像。
3840×2160 是 1,692,057,648 B，1920×1027 是 402,255,408 B（约 383.62 MiB）。
相比首版的 136 B/像素增加 68 B，不能把“一条路径”误解为显存没有增加。

路径 `firstDirection.xyz` 在 camera / guide 阶段存首接口 f32 法线；first 的方块灯、太阳
和 guide 方向变换完成后，才改写为首次余弦方向在重建坐标系中的方向。48 B 暂存保存
当前位置与 F、上一帧位置与精确 triangle、上一帧法线与精确 section；guide 后后两行成为
首面直接辐射与去调制亮度方向矩。先读完旧语义，再开始新语义，host 在两个边界显式屏障。
两层吸收系数均 f32，两个 u16 MediumId 原样共用一字；到第三层有效嵌套时终止照明，
不静默覆盖状态。零吞吐本身不打断前置几何 guide；普通 Lambert 延续可据零吞吐停止。

世界 payload 为 96 B，阴影 payload 为 64 B。guide 请求同一最近命中分类与运动信息，
但不求发光；它不携带介质、throughput 或第二条照明状态。共同最近命中入口仍可见窄
发光叶，因此这些大小是下一次寄存器捕获的关注点，不声称 live register 已减少。
阴影不透明 any-hit 只读取精确源身份与目标 emitter 表，不采纹理；遇透明才由 closest-hit
返回吸收参数，raygen 按顺序结算。首面选灯函数在阴影前结束，跨阴影保留 36 B 的窄目标，
不携带通用 LightSample 的 radiance / isDelta 空字段。太阳入口与深层着色不导入灯光树。

主重建 guide 使用直透目标，反射 guide 使用首接口虚拟镜像位置、法线和上一帧目标；
NRD 的反射辐射进入独立 reflection-diffuse 层，DLSS RR 的反射辐射进入 specular 信号并保留
接口至反射目标的命中距离。DLSS 当前后端不提供独立的反射 MV 输入。普通首面太阳走
已有 SIGMA，有透明首接口时太阳计入选中 noisy 分支，避免将反射阴影误用主面 SIGMA。
直透的移动目标传递上一帧位置及带符号的当前距离，显示位置 / FSR 深度仍使用首接口。
透明链逃逸使用 65504 的有限距离作为重建远景锚点；反射远景使用方向重投影。此值仅是
重建约定，不是 transport 的伪造命中点；直透远景尚沿用有限远景锚点，平移稳定性须实测。

GPU 行为门禁包含配置 / RR / emission 归属、最小值优先与 64 轮、首分支白炉期望与单调
Fresnel、嵌套 / 相邻介质及分段 Beer 吸收、精确最大 MediumId、反射 guide 的镜像变换、
64 帧 STBN 地址域和首尾像素的 scratch / command / queue 边界。产物门禁检查 payload、
144 B stride、描述符以及无 OpenPBR / 深层灯光树的源码闭包。这些测试没有替代实际窗口、
水下、移动实体、反射遮挡显露和深层暗光场景的重建回归。
