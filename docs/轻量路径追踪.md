# 轻量路径追踪

`lightweight_path_tracing` 是面向正常游玩的性能优先模式。它使用独立的 Lambert 光传输
模型，共享场景、颜色、精确几何、灯光、大气和重建接口，不声明 OpenPBR 等价。完整实时
与离线的材质数学由各自契约维护。实时设置只提供完整和轻量路径追踪。

## 材质与透明

普通表面使用规范线性 Rec.2020 底色、tint、几何法线和双面 Lambert；金属也按底色处理。
不计算粗糙高光、SSS、法线贴图或完整 PBR。完整模型的 `x^1.04` 底色观感补偿不作用于
Lambert。岩浆是发光 Lambert，不能因为属于流体就归入透明介质。

coverage 与光学透明分开：树叶、粒子和文字先执行 alpha cutout，通过部分仍是 Lambert。
玻璃边框遵守规范材质与“无缝玻璃”设置。只有翻译后确认的透明部分进入 delta 路径。

只有**相机直接命中的首个可见表面**有反射资格。它若为透明接口，目标外观为：

```text
L = F × Lreflection + (1 − F) × Lstraight
F = F0 + (1 − F0) × (1 − abs(dot(n, wi)))^5
F0(water) = 0.02; F0(glass) = 0.04
```

两项非零时以 STBN 各 1/2 选择一条照明路径，throughput 分别乘 `2F` 或 `2(1−F)`；
仅一项有效时确定性选择。反射使用几何法线，直通方向不变。此后所有透明接口只直通和
滤色，不再扣除一份未输出的 Fresnel 反射；首反射资格不会在漫反射或反射后恢复。
不支持 Snell 折射、TIR、镜中镜或焦散。这是明确的外观模型，不保证全局物理互易性。

水和实体染色介质沿真实段长应用 `T=exp(−sigma × distance)`，不能按三角面次数染色。
薄片沿规范参考厚度处理；摄像机水下时第一段已有吸收。最多保存两个非空气介质，身份
精确、两层 RGB 消光为 f32；第三层有效嵌套终止照明，不覆盖旧栈。零 throughput 可以
终止普通照明，但不能阻止仍需完成的几何 guide。

主路径、guide 和阴影都采用有序最近命中穿越。any-hit 只判断精确端点与 coverage，
不能无序累乘候选玻璃颜色，否则最近墙面后方的介质会污染结果。阴影遇不透明面终止，
透明面返回吸收参数后继续同一方向；它始终使用本模式的直通模型。

## 灯光与贡献归属

首主表面是所选照明分支遇到的第一个 Lambert 接收面，包括玻璃后或首面反射后的接收面。
每像素至多查询一次方块灯树，guide 不采灯。

| 接收面 | 太阳 NEE | 方块灯 NEE | 后继 |
| --- | --- | --- | --- |
| 首 Lambert | 一个样本 | 一个样本 | 余弦半球与线性 RR |
| 后续 Lambert | 一个样本 | 无 | 余弦半球与线性 RR |
| 透明接口、guide | 无 | 无 | 直通或 guide 规则 |

首面两族顺序完成，不同时保留两份完整样本。方块灯复用[共享采样](灯光与大气采样.md)的
两级树、纹理面积分布、实际发光和精确目标身份；深层 shade 从源码上不依赖灯光树。

Lambert 之后没有改变方向的透明事件，因此首 Lambert 到注册灯面的直达积分由 NEE 独占。
命灯时按**上一顶点是否拥有该 NEE 技术**判断归属，与本帧是否抽到灯或样本是否被挡无关：

| 路径终点 | 累计规则 |
| --- | --- |
| 相机直视或首反射后、尚未发生 Lambert 的灯与太阳 | 累计，包含中间滤色 |
| 恰好一次 Lambert 散射后命中注册方块灯 | 不重复累计 Le；灯面仍可作为后续接收面 |
| 两次及以上 Lambert 散射后命中注册方块灯 | 累计，前一顶点没有方块灯 NEE |
| Lambert 后命中未注册的可见发光 | 累计，没有竞争 NEE |
| Lambert 后逃逸太阳圆盘 | 不累计，由每层太阳 NEE 负责 |
| 天空和星图 | 按延续方向累计 |

直通不改变归属。省去深层选灯改变方差与成本，不删除深层方块光传输项，也不能保证
减少所有萤火虫。若以后引入 Lambert 后反射或折射，必须重新证明独占 NEE 的支持域。

## 调度与终止

前置透明链使用无 RR 的窄 megakernel；主体为粗粒度 wavefront，没有 tail。

```text
camera → guide → first → (trace → shade) × (K−1) → trace → terminal → resolve
```

camera 推进选中链，guide 仅为首透明像素补未选分支；二者遇 Lambert 就交接，不在
透明循环内计算照明。每个 trace 在本 invocation 内完成直通链，不逐接口增加 dispatch。

| 设置 | 范围 / 默认 | 语义 |
| --- | --- | --- |
| 额外镜面反弹 D | 1–64 / 12 | 限制前置链，以及每条后续直通和 NEE 连接的透明事件数 |
| 最小反弹 M | 1–8 / 2 | Lambert 照明轮数达到 M 前不执行 RR |
| 最大反弹 B | 1–64 / 12 | 实际上限 K=max(M,B) |

透明事件不消耗 Lambert 轮数。D=1 允许首接口事件后的落点查询；只有需要处理第二个
透明事件才超限。coverage 拒绝的候选不计数。主路径、guide 和 NEE 使用相同穿越预算。

第 j 个接收面先结算 emission 与 NEE。仅 `M ≤ j < K` 时在发布后继前执行一次
`p=clamp(maxRGB(beta),0,1)`，存活路径除以 p。完成第 K 次散射后仍查询端点，只结算
环境、允许的 emission 和必要距离，不执行第 K+1 轮 NEE、散射或 RR。

共记录 `2K+4` 条 RT dispatch，默认 28，上限 132。三个队列容量均为 N；空队列不启动
raygen，但 command 与 barrier 仍有成本，不逐轮 CPU 读回。终止规则见
[采样与路径终止](采样与路径终止.md)。

## 路径存储与编译边界

N 是内部渲染像素数。具体字段只以 `shaders/abi.json` 及生成合同为准。

| 数据 | 大小 | 生命周期 |
| --- | ---: | --- |
| 唯一照明记录 | 144 B/像素 | camera 至 resolve |
| 首接口 / SH 暂存 | 48 B/像素 | guide 完成后复用后 32 B 存直接辐射与方向矩 |
| 两条照明队列与一条 guide 队列 | 12 B/像素 | 各阶段发布和消费 |
| 三条间接命令 | 全帧 48 B | 队列 0 第四字保存 M / D |

传输 backing 为 `align256(144N) + 60N + 48`，不包含重建图像、场景或 SDK 内存。
`firstDirection.xyz` 在 camera / guide 阶段保存首接口 f32 法线；first 完成灯光与方向
变换后才改写为首次余弦方向。复用必须先消费旧语义，并由 host 屏障保证阶段顺序。

非 SER 世界追踪使用 96 B payload。SER 变体用 12 B 精确 source 请求遍历，在 HitObject
返回后才初始化 96 B 命中输出；camera / guide 不显式重排，深层 world trace 重排。
阴影 payload 为 64 B，保持普通 TraceRay。

**camera 的 HitObject 后发布必须使用逐 invocation 原子预留。** 在此处使用 subgroup
合并会触发已复现的 device lost；不显式调用 reorder 也不能规避。first / shade 仍使用
原 subgroup 产物。完整规则与验证范围见[路径追踪性能约束](路径追踪性能约束.md)。

## 重建接口与验收

只有一条照明路径，两路 guide 均保持稳定；未选分支照明为零，不能删除其身份或交换
透射/反射通道。guide-only 不计算 emission、NEE、RR 或第二份照明 throughput。

NRD 用直通目标作为主 guide，首反射的镜像目标作为独立反射 guide；镜中 Lambert 照明
归入反射层的 diffuse。DLSS 将反射辐射归入 specular，保留接口至反射目标距离，固定
不提交显式 reflection MV。有效直通主 guide 的 specular albedo 仍来自可见接口。

普通首面太阳使用 SIGMA；透明首接口两路太阳已遮挡、已滤色，进入所选 noisy 分支，
不能再乘主面 SIGMA。FSR 轮廓和大气使用真实可见接口。无样本距离为 0，真正追踪的
miss 使用 65504 重建约定；该值不是 transport 命中点。通道细节见
[透明渲染与实时重建](透明渲染与实时重建.md)。

行为门禁覆盖反弹边界、1/2 选枝期望、emission 归属、介质分段一致性、最大 MediumId、
双 guide、相邻像素存储、STBN 地址域和 HitObject 后唯一发布。编译产物检查 payload、
stride、descriptor 以及无 OpenPBR / 深层灯光树的闭包。运动玻璃、水下、明暗交界和
深层暗光仍需场景回归；数学或 ABI 测试不能替代重建画面验收。
