# 轻量路径追踪首版

2026-09-06：灯光与首透明面反射已接入，当前实现见[灯光与首面反射](轻量渲染器灯光与透明设计.md)。
**以下保留首版基线快照**：128 B、固定 12 次、所有表面 Lambert 和纯 wavefront 均为历史行为，
不能用来描述现在的功能、资源布局或调度。新版本的游戏内画面与性能仍待实测。

首版提供独立的 `lightweight_path_tracing` 实时模式。设置中选择“轻量路径追踪（Lambert）”；
原有实时 PT 和仅主光线模式保留。模式切换、shader reload、分辨率和重建后端变化沿用原有
帧资源所有者与历史失效流程。默认模式不变。

Lambert 是新渲染器的性能与光传输基线，不是目标画质。当前优先恢复所需材质表现并审查共享
热路径。路径阶段复用已分析，当前仍保留 128 B stride，详见[路径记录复用分析](轻量路径记录复用分析.md)。每次增加模型能力时记录寄存器与跨 trace
状态的变化，基线及归因方法见[轻量渲染器寄存器记录](轻量渲染器寄存器记录.md)。
共享大气已切换为太阳、天空、星图保留方向依赖，仅将大气观察位置固定为摄像机；方向透射率
由共享 RGB LUT 提供。候选解析使用窄数据与专用算法，备用材质在选中后读取，普通 UV 不重建
命中几何。这些改动同时用于旧实时和离线 PT，详见寄存器记录中的 L1 实施与复测条目。

## 模型与截断

- 所有命中表面使用双面、几何法线 Lambert，`f = albedo / π`。反照率取现有规范颜色页面和
  tint，在场景线性 Rec.2020 D65 中限制到 `[0, 1]`。保留纹理和 alpha cutout。
- 玻璃、水、金属、薄片和其他材质在此模式中都是上述 Lambert 表面。不使用 authored
  normal、OpenPBR、折射、介质、局部自发光或面光源。这是首版的显式模型范围，不能作为
  OpenPBR 实现或完整资源包材质验收结果。
- 光源是现有天空、星图和有限角半径的太阳。只对太阳做 NEE；天空和星图由散射后的
  逃逸射线积分。相机直接看到太阳圆盘；经过 Lambert 散射后的逃逸射线不再加太阳圆盘。
  两个估计器负责不重叠的光源项，无需 MIS 或 previous-PDF 状态。
- 每个表面独立采样太阳，贡献为 `throughput * albedo * Lsun * cosθ / (π * pSun)`。
  Lambert 方向按余弦半球采样，`p = cosθ / π`，因此延续权重是 `throughput *= albedo`。
- 最多执行 **12 次散射**，从第一次散射开始使用 RR，没有 tail。RR 在当前顶点 NEE 后执行，
  固定线性存活概率 `min(maxRGB(throughput), 1)`，只对存活后继的真实 throughput 除以
  概率补偿，零 throughput 终止。平方根、首反照率去调制的策略和调试开关均已删除。
  第 12 次散射后的射线仍查询一次：逃逸则累加
  环境，命中下一表面则停止，保证太阳和天空都保留至 12 阶反射。截断明确舍弃更高阶能量。

当前仍使用共享大气/显示适配器，包括原有 aerial perspective；首版不声明大气介质的完整
多段路径积分。太阳和天空数值、色域、曝光与 SDR/HDR 输出保持既有接口。

## 调度与寄存器

GPU 顺序为 `camera → (trace → shade) × 13 → resolve`，共 28 次 RT dispatch，位于同一
帧 command buffer 内。最后一对只处理终点，不延长路径。空队列使用零宽间接 dispatch。
这是一版粗粒度纯 wavefront，尚未加入 delta 特化或按材质划分队列。

- camera 为每像素建立一条路径，写队列 0；trace 只做世界求交和首表面 guide；shade 处理
  miss、太阳阴影和下一方向。resolve 只输出重建信号。
- 两个队列交替。每条活跃路径只有一个所有者，每次最多产生一个后继，容量严格不超过
  像素数。shade 的第一个 invocation 清零已消费的源计数；它们读取索引时不再读取计数。
  初始命令为 `(0,1,1,0)`，因此零工作队列也不会遗留旧计数。
- 支持 raygen BASIC + BALLOT subgroup 操作时按组预留后继区间，终止与存活路径统一到达追加点；
  不支持时使用独立标量编译产物。RR 和 subgroup 不增加 dispatch 或缩小固定缓冲分配容量。
- dispatch 间对路径、队列和 indirect command 建立依赖；首表面清理与太阳写入之间、
  最终信号输出之前建立相应图像依赖。帧结束后的 RT→重建同步沿用现有执行器。
- 世界 payload 为 64 B，阴影 payload 为 12 B。前者携带 f32 hit/normal/albedo、精确身份
  和首表面动态 motion，后者只有精确源身份和最近遮挡距离。
- opaque 阴影使用独立的窄 any-hit，只读取精确身份；cutout 路径才引入位置抓取和纹理。
  这一划分复用旧管线已经采用的 geometry class 分组，没有新增队列或 dispatch。
- 阴影遍历前不加载延续路径的 throughput/albedo，也不构造旧 BSDF 或 guide transport
  对象。减少必须跨 TraceRay 存活的数据；实际物理寄存器数仍须新 Nsight 捕获验证。

这里复用经审查的 Vulkan 管线/SBT、不可变图像 binding、采样、纹理/几何叶函数和重建
适配器。新 shader 不导入旧 transport、OpenPBR 或旧路径状态。当前 host 的不可变图像
binding 定义仍位于旧管线类；它只封送共享的 RawWavefrontFrame 接口。

## 路径数据合同

`shaders/abi.json.lambertContract` 生成独立 Slang 常量与 Java 常量。全尺寸缓冲由
`LambertRayTracingPipeline` 在渲染线程上持有，替换后通过现有 GPU retirement 延迟释放。
无新增锁或跨线程可变状态。每帧 camera 完整初始化路径，resolve 是最终读取者，不跨帧积累。

| 记录字段 | semantic / encoding | 最后消费与有效性 |
| --- | --- | --- |
| origin.xyz | BLAS f32 顶点与硬件重心重建的世界命中位置；相机路径为相机位置 | 下一次 trace/shade |
| direction.xyz | f32 单位射线方向 | 下一次 trace；miss 光照 |
| throughput.rgb | f32 线性 Rec.2020 无量纲路径权重 | shade；无非零阈值裁剪 |
| normalDistance | f32 面向入射侧几何单位法线、硬件 RayTCurrent；负距离代表 miss | 紧邻的 shade |
| albedo.rgb | f32 线性 Rec.2020 Lambert 反照率 | 紧邻的 shade |
| identity | u32 section、triangle、已完成散射数、首表面有效标志 | 精确源身份与深度；不压入浮点 |
| radiance | f32 累积 RGB；w 为第一次散射后命中距离，未追踪为 0，实际 miss 为 65504 | resolve；供现有重建接口 |
| firstDirection.xyz | f32 第一次余弦采样方向 | resolve；SH 方向信号 |
| direction.w / throughput.w / firstDirection.w | 首表面 f32 反照率 R/G/B；首次 shade 写入，后续阶段保持 | 后续 shade 的去调制 RR；阴影结束后窄加载 |

每个字段占 16 B，记录 128 B，无有损几何/法线压缩。set 1 的 path/queue binding 沿用
现有编号 36/37，绑定独立缓冲区范围；path 范围末尾按 256 B 对齐。queue 范围包含两个
16 B 的 indirect command，随后是两个 `u32[pixelCount]` 索引数组，无 scratch 或溢出队列。

因此仅传输缓冲约 **136 B/像素 + 32 B**，另有最多 255 B 对齐。3840×2160 为
1,128,038,432 B（约 1.051 GiB），旧实时传输缓冲为 4,346,265,712 B，减少约 **74%**。
这些数值不含场景、纹理、BLAS、重建图像和历史；它们不是总显存或帧率实测。

## STBN

复用已有 `128×128×64×3` RG16UI 表及其帧级共享 GPU buffer，不为新模式另建表。太阳使用
bank 2，Lambert 方向使用此模式未被面光源使用的 bank 0。每个反弹使用不同空间偏移；
64 帧内保留完整时间列，跨周期重新平移。sample epoch、cycle 和反弹一起确定地址。
RR 独立复用旧 hash effect/stream，哈希叶模块不引入 Sobol 表；不消耗或复用上述 STBN 样本。

解码为 `(u16 + 0.5) / 65536`，严格位于 `(0,1)`，避免半球采样端点。相机抖动继续使用
现有与重建匹配的序列。GPU 性质测试读取正式表，覆盖周期边界、末端反弹、u32 回绕，
检查取值域、余弦分布、旋转后的单位方向、常量入射光积分与跨 bank/反弹基本相关性。
这些统计检查不证明所有场景都无结构噪声，也不替代运动场景的降噪效果观察。

## 重建通道

通过相同 RawWavefrontFrame 接入原生含噪、NRD/SH、DLSS RR 与既有 FSR/显示链路。
所有数值先以 f32 传输；仅写入现有重建接口时执行其规定的 FP16 上界和编码。

| 信号 | 首版内容 |
| --- | --- |
| stableRadiance | 相机直接看到的天空、星图和太阳圆盘 |
| noisyDiffuse / hit distance | 经首表面反照率调制的间接光；第一次散射后命中距离 |
| diffuseDirection | 第一次余弦采样方向，供 SH 重建 |
| noisySpecular / specularDirection / specularAlbedo | 零；roughness 为 1 |
| material / normalRoughness / viewZ | 首表面反照率、几何法线、距离、线性 roughness、相机轴向深度 |
| primaryPosition / displayPosition | 按各后端原有合同编码当前或上帧表面位置、camera sample 与对象 motion |
| reconstructionControl | 普通材质类、surface/history/object-motion 有效位；motion-valid 由后续准备 pass 产生 |
| sunLighting / sunPenumbra | 首表面未遮挡太阳贡献、采样可见性、最近遮挡距离对应的 SIGMA penumbra |
| reflectionMaterial / RR reflectionPosition | 无反射分支的无效标记；重建 pass 据此避免读取其他反射通道 |

不无条件清理可选 SH/反射图像：在不使用它们的后端，这些 descriptor 可以 alias 主信号。
transportScratch、重建 motion 及后端历史由其现有后续 pass 写入。

## 验证与后续边界

编译产物门禁验证新 payload 形状、位置、路径/索引 stride、STBN binding 和独立编译闭包。
CPU 合同测试覆盖布局容量、设备限制和两个 SBT queue control；GPU 测试覆盖正式 STBN 表与
Lambert 数学；现有 position-fetch、NRD/颜色/运输数学测试继续承担共享叶函数的回归验证。

2026-09-05 用户确认首版画面正常，并提供首份 Nsight 寄存器捕获；见[性能分析](Lambert首版性能分析.md)。
该捕获缺少受控帧时间和完整运动画质验收。后续增加材质、delta 窄 megakernel、局部自发光或
法线时，应保留基线并逐项记录寄存器增长；新增模型需单独声明近似与采样策略。当前优先核对
大气查询和 any-hit 的实际工作及生命周期，不以新增队列或降低记录精度作为默认解决办法。
