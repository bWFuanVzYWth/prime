# 场景资源生命周期

本文件约束上传、AS 构建、发布和退休的成本与所有权。几何翻译、着色记录和纹理身份分别见
[区块簇场景翻译架构](区块簇场景翻译架构.md)、[地形几何显存压缩设计](地形几何显存压缩设计.md)
和[纹理翻译架构](纹理翻译架构.md)。

## BLAS 生命周期与压缩

`PreparedBlas` 是构建输入的统一边界，位置用途决定生命周期：

| 位置用途 | BLAS 策略 | 输入位置退休 |
| --- | --- | --- |
| `BUILD_ONLY` 静态几何 | 允许 compaction | 最后一次 GPU 构建读取完成后 |
| `MOTION` 动态几何 | 不申请 compaction | 当前/上一帧运动重建不再使用后 |

动态拥有的体素 mesh 也必须遵守 `MOTION` 分类，不能因生成方式类似静态地形而进入
compacted-size 查询。相机朝向改变 billboard 顶点与动态原型键时，需要真实构建；不能
按材质或拓扑相同复用顶点不同的 BLAS。

录制顺序为独立 BLAS 构建、既有 AS write→read barrier、静态 compacted-size 查询、
TLAS 构建或更新。同一共享 prototype 每次构建只查询一次，不按实例重复查询。
压缩目标分配、复制、地址替换和旧地址退休由场景所有者统一管理；复制及引用旧地址的
GPU 工作完成后才能回收 backing。

当前每帧静态上传最多 8 MiB、4 个 cluster；compaction 复制最多 8 MiB、16 项，压缩目标
分配的 in-flight 上限为 64 MiB。不可拆分的超大项可在无其他占用时单独推进，避免永久
饥饿。压缩保持 FIFO。预算限制工作量，不丢弃合法几何。

目标分配预算不能限制错误分类造成的查询工作量，因此静态/动态边界必须在创建
`PreparedBlas` 时确定。TLAS 保持完整 resident scene；反射、阴影与间接光仍可能访问
屏幕外实例，不能以相机视锥裁剪代替预算。

## 上传与发布

帧和场景更新使用 prepare/accept：候选数据先准备完整，`encoder.execute()` 正常返回后
才推进 resident 映射、上传游标和历史。未被提交接受的更新执行 abandon；已接受提交
随后失败时退休 renderer。旧 GPU 资源按完成时间线回收，正常热路径不等待设备空闲。

- staging 接受 position 到 limit 的范围；`memAddress(ByteBuffer)` 已包含 position，
  不能再次加 position。slice、非零 position 和只读源保持相同范围语义。
- `MaterialId` 追加只上传新增区间，游标在提交接受后推进。
- `SurfaceRecords` 槽位和引用由 render thread 拥有，GPU 完成回调只投递退休通知。
  活记录不可重编号；空槽必须等旧 GPU 引用退休后才可复用。
- 脏槽逐项从集合移除，避免 `HashSet.removeAll(List)` 在特定尺寸关系下退化为平方
  复杂度；合并脏区间不能修改旧帧仍在使用的表实例。
- 建网探针和 `FaceGrid` 暂存限定在一次调用内；可变探针不得插入长期 map 后继续修改。

## 捕获边界与资源完整性

粒子来源按当前捕获会话中已知的 AtlasManager GPU 纹理身份识别。usage 的
render-attachment 位不能证明纹理不是已知 sRGB atlas；未知纹理不能当作 atlas 0。
来源信息随会话捕获，不跨 reload 复用旧对象身份。未知来源明确报告兼容性限制；允许的
粒子常量颜色降级保留几何，不借用其他图集 UV。

发行检查验证星图清单、尺寸、压缩与解压数据的 SHA-256 以及 gzip 完整性。运行时解压
或长度检查失败必须明确指出损坏资源，不能继续上传失败字节；临时文件、机器路径和一次性损坏偏移不属于资源契约。

## 定位突发帧时间

Vulkan 调试标签区分静态/动态 BLAS、输入生命周期、三角形数、OMM 查询和 TLAS
BUILD/UPDATE。先确认耗时位于构建、等待查询、压缩复制还是 TLAS，不能只凭“AS”事件名
推断原因。

`-Dprime.profileSubmissions=true` 启用 `prime.Submission` JFR 事件，记录 CPU 录制和提交。
`previousGpuNanos` 来自已完成 GPU TimerQuery 的滑动统计，不阻塞读取，也不保证与当前
CPU 事件一一对应；缺失 GPU 结果不能为诊断插入等待。抓帧比较需要固定场景、设置和
分辨率，并结合频率与后台负载解释。未确认根因的原生崩溃单列在 [FIXME](FIXME.md)。
