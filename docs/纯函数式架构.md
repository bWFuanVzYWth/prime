# 架构与数据流

Prime 采用函数式核心、命令式外壳。Minecraft、Vulkan、原生库、配置和文件 I/O 位于边界；
场景语义、帧计划、历史判定、codec 和数学计算使用显式输入。架构边界不得以额外 GPU pass、
同步点或高频完整复制为代价。

## 六层依赖

| 层 | 包与职责 | 可依赖 |
| --- | --- | --- |
| `client` | 组合根、Mixin、配置、UI | 全部层 |
| `runtime` | 会话、渲染模式、异步调度 | `runtime`、`adapter`、`vulkan`、`core`、`support` |
| `adapter` | `scene.vanilla` 与只读 Mixin accessor；捕获 Minecraft 状态 | `adapter`、`core`、`support` |
| `vulkan` | GPU/native 执行与资源生命周期 | `vulkan`、`core`、`support` |
| `core` | 不可变值、场景语义、计划和纯算法 | `core`、`support` |
| `support` | 跨层共享且不反向依赖 Prime 业务层的日志、清理等基础设施 | `support` |

`adapter` 不依赖 LWJGL，`core` 不依赖 Minecraft client、Blaze3D、LWJGL、Mixin 或 Fabric。
Minecraft 捕获先转换成 core 快照，Vulkan 只消费快照；两侧不得互相观察实现对象。
`verifyArchitecture` 对编译 class 运行 `jdeps`，检查完整允许矩阵、平台依赖和跨层强连通分量，
并由 `check` 强制执行。门禁不设置单类例外。

[渲染核心数据 IR](渲染核心数据IR.md)定义跨这些层流动的数据语义。`core` 拥有不含 GPU/native
句柄的 semantic 描述、稳定 ID、单位、不可变值和纯转换计划；`vulkan` 拥有物理 encoding、
binding、alias、barrier 和资源 lifetime。schema 可同时生成两侧 API，但不得让 core 依赖 Vulkan
格式/descriptor，也不得让 Vulkan 重新解释 Minecraft/source 语义。

## 所有权与数据流

```text
Minecraft / 配置 / 输入
        ↓ 边界捕获与校验
不可变 core 快照或计划
        ↓
runtime 调度
        ↓
Vulkan / native 执行
        ↓ host 接受或 abandon
已提交历史与资源状态
```

客户端线程单一拥有 runtime 控制器。GPU 句柄只属于 Vulkan 边界；core 只观察稳定 ID、revision
和描述值。跨线程任务传递不可变快照或所有权已转移的数据，不传递可变 Minecraft/GPU 对象。
每项颜色、坐标、材质、重建和 interop 转换只有一个 owner；其他层只能调用该纯转换或消费其
结果，不能复制符号、矩阵转置、色域或 packing 公式。语义相同的数据允许通过所有权转移和
alias 零拷贝，格式相同但语义不同的数据不得因方便而接错。
场景资源用单调 revision；资源重载由 `ResourceEpochCoordinator` 在捕获和 worker 期间提供短
lease，retire 后拒绝新读取，最后一个 reader 退出时完成 reload。

资源更新采用 prepare/publish：事务对象独占尚未发布的 GPU 资源和 staging batch；提交前失败
立即销毁，提交后失败延迟销毁，成功 publish 后才转移所有权。每类 frame index、相机历史、
图像初始化和一次性上传状态只有一个生命周期所有者，不以 GPU wait 代替所有权证明。

帧状态采用 prepare/accept：执行器从已提交状态和当前快照生成候选状态；只有 host 接受提交后
才能推进历史。接受前失败执行 abandon；接受后宿主失败则 runtime 进入 `FAILED` 并退休
renderer，不复用已经推进的历史。

稳定的具体边界如下：

- `PrimeConfigFile` 只做原子文件 I/O，`PrimeConfigCodec` 独占当前 properties schema，
  `PrimeConfig` 只拥有客户端线程状态与 renderer revision；未知字段按当前 schema 规范重写；
- `VanillaClusterCompiler` 隐藏 Minecraft cluster capture/Section 编译，`TerrainStreamer` 只拥有
  调度和回压；`TerrainUpdateTransaction` 独占尚未发布的 staging、cluster、TLAS 和 light buffer；
- `NrdFrameBindingPool` 按 queue completion 回收每帧 descriptor/constant allocation，
  `NrdDenoiser` 只编排 native dispatch、pipeline 和图像语义。

## 确定性边界

- 每帧只使用 `beginFrame` 捕获的一份 `RendererSettings`；
- 随机样本由稳定的像素、样本、路径槽、bounce、分支和 seed 寻址；
- 排序、哈希和序列化不得包含对象身份、GPU 地址、padding 或未初始化数据；
- 数组可以通过所有权转移零拷贝发布，发布后构建者不得再修改；
- 完全重合 primitive 的 traversal 顺序不是契约，需保留的叠层在场景构建阶段消歧；
- NRD、DLSS、FSR、Vulkan traversal 和动态 mod 回调是外部边界，不伪装成可重放状态。

## 变更门禁

新增模块或状态时必须确认依赖方向、唯一所有者、提交失败路径、跨线程不可变性与热路径成本，
并用行为测试、真实 Shader 测试、ABI 检查或架构门禁覆盖实际风险。引入新的共享可变子系统、
锁域或锁顺序前必须单独批准。生产 Shader 另以源码可见性为性能边界，遵守
[生产 Shader 编译边界契约](生产Shader编译边界契约.md)。
